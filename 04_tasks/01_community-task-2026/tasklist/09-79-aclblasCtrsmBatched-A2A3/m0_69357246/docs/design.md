# aclblasCtrsmBatched：批量三角求解设计（A2/A3）

# 需求背景（required）

## 需求来源

本设计对应9月社区任务“aclblasCtrsmBatched算子开发（A2/A3）”。实现采用 Ascend C kernel 直调，接入 ops-blas 的句柄、stream、状态码和工作空间管理。目标平台为 Atlas A2/A3，工具链以 CANN 9.1.0 为基准。

## 问题分析

三角求解的依赖沿矩阵阶数展开。同一系统中的后一行依赖已经求得的行，不同 batch 和不同右端项可以并行。小矩阵需要减少下发、索引和标量开销；大矩阵需要将非对角更新转为矩阵乘，复用片上数据。

设计采用几何条件驱动的多路径执行。外部保持列主序复数布局，内部按路径选择交错或实虚分离布局。计算与搬运粒度随阶数、右端项数、batch 数和平台资源变化。

# 需求分析（required）

## 功能与接口

对每个批次 b 独立计算，解矩阵 X 原地覆盖 B：

    LEFT : op(A[b]) X[b] = alpha B[b]
    RIGHT: X[b] op(A[b]) = alpha B[b]

N 表示不转置，T 表示转置，C 表示共轭转置。A、B 都是 Device 指针数组；各矩阵不要求相邻分配。批次共用维度、前导维和枚举参数。

    aclblasStatus_t aclblasCtrsmBatched(
        aclblasHandle_t handle, aclblasSideMode_t side,
        aclblasFillMode_t uplo, aclblasOperation_t trans,
        aclblasDiagType_t diag, int m, int n,
        const aclblasComplex* alpha,
        const aclblasComplex* const A[], int lda,
        aclblasComplex* const B[], int ldb, int batchCount);

| 项目 | 约定 |
| --- | --- |
| 数据类型 | COMPLEX64，实部和虚部均为 FP32 |
| 存储 | 列主序；A 只使用指定三角；B 有效区域原地更新 |
| 求解阶数 k | LEFT 为 m，RIGHT 为 n |
| 右端项数 r | LEFT 为 n，RIGHT 为 m |
| 前导维 | lda ≥ max(1,k)，ldb ≥ max(1,m) |
| 批次数 | batchCount ≥ 1；各 B 有效区域互不重叠 |
| 对角 | UNIT 隐式取 1，不读取实际对角；NON_UNIT 使用非零对角 |
| 标量 | 任务接口要求 Host 标量；Device 标量扩展先读取真实值再选择路径 |
| 执行流 | 使用 handle 绑定的 stream；调用方读回结果前同步 |

## 边界与错误行为

Host 首先检查 handle、枚举、维度和前导维。空 handle 返回 HANDLE_IS_NULLPTR；其余非法参数返回 INVALID_VALUE。资源和执行错误向调用方返回对应状态码，并记录算子名与关键参数。

- m=0 或 n=0：返回成功，不启动 kernel。
- alpha=0：仅清零 B 的有效元素，不读取 A 或 B 的旧值。
- UNIT：对角按 1 参与运算，对角存储的 NaN 不进入结果。
- leading dimension 的 padding：保持原值，不作为有效输出写回。
- 非法枚举、负维度、batchCount≤0、必需空指针和非法 leading dimension：在计算前处理。

# 详细设计（required）

## 总体数据流

    参数检查 → 标量读取 → 几何与资源评估 → 工作空间准备
                                         ↓
                 批量向量 / 小阶求逆应用 / 大阶分块求解
                                         ↓
                            按原布局写回有效 B 元素

Host 只选择通用几何路径。kernel 从指针数组读取真实矩阵地址。不依赖测试编号或环境变量选择产品路径。

## 路径选择与任务映射

| 几何特征 | 路径 | 并行与复用 |
| --- | --- | --- |
| 小阶、较多 batch | 批量 Vector 直接求解 | 将多个系统或右端项放入同一向量，减少标量循环与零散搬运 |
| 中小阶、足够右端项 | 三角逆预处理 + Cube 应用 | 每批复用逆矩阵；右端项分块分核 |
| 大阶或宽矩阵 | 对角块预处理 + 分块更新 | 沿依赖顺序推进对角块，并行处理右端 tile |
| padding、尾块或窄矩阵 | 连续片段搬运与向量求解 | 按有效长度计算，减少填充和无效 Cube 工作 |
| 对累计顺序敏感的系统 | 保序 Vector 求解 | 保持替代法依赖顺序，复用向量与中间结果 |

任务索引由 batch、右端 tile 和三角块坐标组成。Host 与 kernel 使用一致的 tile 参数和任务映射。右端项少时合并批次以提高核占用；右端项多时复用三角数据，扩大连续搬运。

## 三角方向与分块算法

先确定逻辑三角方向，再映射原矩阵坐标。转置交换坐标，共轭转置同时取反虚部。RIGHT 可以转写为等价左侧系统，也可以保留右乘并采用专用布局；路径需明确 alpha 缩放位置和恢复布局的步骤。

以下为下三角分块计算，p 表示当前对角块，q 表示尚未求解的块：

    X[p] = inverse(A[p,p]) · B[p]
    B[q] = B[q] - A[q,p] · X[p]

上三角反向推进。逆矩阵只用于块内求解或可复用的小阶系统，不构造大阶稠密全逆。RIGHT 与转置路径沿等价依赖方向更新。

## 复数算术与数值控制

复数矩阵乘按实部和虚部分解：

    Cr = Ar Br - Ai Bi
    Ci = Ar Bi + Ai Br

输入和输出使用 FP32 分量。常规 Vector 路径采用 FP32 运算；Cube 路径采用 FP32 累加，明确控制中间数据类型。小阶混合路径可使用 FP16 非对角输入和受控的中间反馈；对角处理与最终输出保留 FP32。每条路径独立满足同一精度门槛。

复数除法需避免平方和的无谓溢出与下溢。普通值使用向量化计算，特殊值按 IEEE 分类处理。保序路径可采用乘积误差与求和误差补偿，减少替代法与 Netlib 累计顺序的差异。数值保护只影响必要计算，不放宽比对阈值。

## 片上存储与同步

GM 保存原始矩阵和工作空间。UB 保存交错数据、实虚分量、索引与临时向量。Cube 路径在 L1/L0 使用分块矩阵布局。根据平台容量计算同时驻留的 tile 数。

- 对齐后的物理长度与逻辑有效长度分别记录。
- 按实际维度核对 ND2NZ 自动填充能力；K 方向对齐尾部在消费前显式置零。
- 写回仅覆盖有效行列，padding 保持原值。
- L1 复用前等待消费结束；MTE2、Vector、MTE3、Cube 之间用对应事件建立依赖。
- 正常出口和提前返回出口恢复调用约定要求的 mask、控制状态和同步状态。
- 工作空间按 handle 生命周期管理；检查大小计算、乘法与对齐溢出。

## 性能设计

先判断瓶颈属于路径选择、并行度、数据搬运还是依赖链。小阶优先合并 batch、批量生成索引、在 UB 中复用矩阵。大阶优先扩大连续 tile，将非对角计算交给 Cube，减少重复格式转换。

性能按一次调用全部 kernel 耗时之和统计。预热与有效采样分开，采用任务书的平均单次耗时口径。准备、格式转换、求解、恢复布局都计入多 kernel 路径。性能采集与插桩检查串行执行。

# 特性交叉分析

| 交叉项 | 风险 | 设计措施 |
| --- | --- | --- |
| RIGHT × T/C | 坐标及三角方向同时变化 | 统一逻辑坐标，单独验证布局恢复 |
| UNIT × 特殊值 | 误读实际对角 | 在读取或计算入口屏蔽对角存储 |
| 小阶 × 大 batch | 核占用不足、标量开销偏高 | 合并系统、向量化替代与连续传输 |
| 非对齐阶数 × Cube | 未初始化尾部或越界 | 区分有效长度与物理长度，显式填充 |
| padding × 原地输出 | 覆盖保护区 | 有效行列写回，逐批检查 padding |
| Device 标量 × 路径选择 | 使用旧值或假值 | 在同一 stream 中读取真实值并处理错误 |
| A2 × A3 | 资源与编译差异 | 平台查询控制 tile，同源编译与分别验证 |

# 可维护与测试设计

## 工程组织

公共声明放在 include/cann_ops_blas.h 的 C 接口区域。算子实现放在 blas/trsmbatched/arch22/，按 Host、数据转换、求解与更新阶段划分。正式测试放在 test/trsmbatched/ctrsmbatched/arch22/，复用 GTest 与 CSV 驱动框架。

三角坐标、任务索引和工作空间规则集中实现。注释解释布局、同步和数值约束。实验脚本、设备日志、性能采样与构建产物保存在独立验证目录，不进入产品提交。

## 精度与契约测试

Golden 使用 Netlib BLAS 的 cblas_ctrsm，逐 batch、列主序比较有效输出。实部与虚部分开判定：atol=rtol=2^-13，匹配比例不低于 0.99；有限值最大误差遵守 1e-2 或 32 ULP 的任务口径。Inf、NaN 按分类与符号规则比较。禁止用历史 CSV 的附加倍率扩大门槛。

覆盖 LEFT/RIGHT × UPPER/LOWER × N/T/C × UNIT/NON_UNIT 全组合。尺寸包含零维、1、小质数、2的幂及相邻尺寸、非方阵、padding 和不同 batch。alpha 覆盖零、单位、负值和复数。另验证参数错误、独立矩阵地址、保护区、工作空间和 stream 行为。

小阶 RIGHT 覆盖 K 对齐边界两侧，以独立进程冷启动检查未初始化数据依赖。新增优化先验证少量代表用例，最终以同一版本集中回归。

## 性能与内存测试

性能与精度分开执行，以官方基线逐条比较。NPU 平均单次 kernel 总耗时应不高于 gpu_ms / 0.8，换算为微秒即 gpu_ms × 1250。按规定预热后对有效样本取平均，不将不同版本或不同轮次的最好结果拼接为通过数。

独立插桩构建使用 mssanitizer。核对退出码、实际执行的 kernel、error、warning 和输出结果。分别检查尾部、L1 复用、跨核通信与寄存器退出状态。A2/A3 使用同源代码，各自保存设备、CANN、编译参数与验证证据。
