# 需求背景

为 Atlas A2/A3 实现 `aclblasSgemv`，沿用 `ops-blas` 仓已有的 950PR 接口。A2/A3 内核放在 `blas/gemv/arch22/`，按同目录的 `Cgemv` 组织文件。

[任务说明](https://www.hiascend.com/activities/task-center/details/a8c0b7d0985349c59503ec0c34ca7344)

# 需求分析

对列主序 FP32 矩阵和向量计算 `y ← α·op(A)·x + β·y`。矩阵操作支持 N、T 和 C。实数下 C 与 T 共用实现。矩阵元素 `A[i,j]` 的物理偏移为 `i + j * lda`，向量步长允许为正或负。

```cpp
aclblasStatus_t aclblasSgemv(
    aclblasHandle_t handle, aclblasOperation_t trans, int m, int n,
    const float* alpha, const float* A, int lda, const float* x, int incx,
    const float* beta, float* y, int incy);
```

# 详细设计

## 接口与参数

| 参数 | 含义 |
| --- | --- |
| `handle`、`trans` | 使用句柄绑定的 stream 下发。N 的输出长度为 `m`，归约长度为 `n`。T/C 的输出长度为 `n`，归约长度为 `m`。 |
| `m`、`n`、`lda` | `m, n ≥ 0`，`lda ≥ max(1, m)`。矩阵物理布局为 `lda × n`，只访问有效的 `m × n` 区域。 |
| `alpha`、`beta` | Host 上的 FP32 标量指针。 |
| `A`、`x`、`y` | Device 上的 FP32 数组。`A` 和 `x` 只读，`y` 原地更新。 |
| `incx`、`incy` | 允许正负步长。逻辑长度为 `L > 0` 时，向量占用跨度为 `1 + (L - 1) * abs(inc)`。负步长从这段存储的末端开始。 |

## Host 侧

1. 空句柄返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`。其余非法参数返回 `ACLBLAS_STATUS_INVALID_VALUE`。校验转置枚举、维度、`lda`、标量指针和步长。步长为零、为 `INT32_MIN` 或跨度乘积超过 int32 范围均报错，乘积用 64 位计算。仅当 `m,n` 均非零时要求 `A` 非空，`x/y` 在各自逻辑长度非零时要求非空。
2. 校验通过后，`m=0` 或 `n=0` 直接返回成功。其余输入根据转置方向和步长选择搬运方式。Tiling 下发维度、步长、标量、输出和归约块长，以及各核负责的区间。矩阵偏移和内存字节数用 64 位计算。
3. 按设备可用向量核数分配输出块。向量步长绝对值为 1 时按物理连续区间搬运。其他步长按公式取数，只写 `y` 的逻辑元素。各核独占输出区间，分块写回不得覆盖相邻块或步长间隙。

## Kernel 侧

- **N 路径**。每核处理一段输出行，按列块搬入对应的连续行片段，在 UB 中累加 `A[:,j] * x[j]`。累加块保留在 UB，归约结束后一次写回。以 4096 方阵验证多列搬运的带宽，以极瘦矩阵验证按行分核。
- **T/C 路径**。每核负责一组输出列。沿列内连续地址分块读取 `A`，与 `x` 相乘后做 FP32 归约。分块时优先让同一核复用已搬入的 `x`。
- **长归约**。先测试按输出分核。输出太少时，可把归约轴切成连续区间，各核写独立的 FP32 部分和，再在同一 stream 上求和并写 `y`。工作区用完后按 stream 顺序回收。根据输出长度、归约长度和可用核数选择路径，切换阈值由实测确定。

单核 UB 同时容纳矩阵 tile、`x` tile、累加块及搬运缓冲。块长按设备可用 UB 和实际缓冲数量计算。搬运覆盖有效地址，未对齐首尾块按实际元素数处理。大步长超出批量搬运能力时，回退到逐段或逐元素访问。

写回时统一计算 `alpha * sum + beta * y`。`beta=0` 时跳过读取旧 `y`，`alpha=0` 仍走归约计算。部分和方案仅在最后一次归约应用标量，确保 `beta` 项只计算一次。

## 支持硬件与约束

- Atlas A2/A3（`arch22`），Ascend C kernel 直调，按任务书使用 CANN 9.1.0。自测覆盖 910B3。
- 支持按运行时维度分块，无广播。调用按句柄的 stream 异步执行，读回结果前由调用方同步。FP32 的归约顺序随分块而变。
- 任务书 §3.1 和 §3.3 对性能机分别写了 Atlas 800I A2 和 Atlas 800T A2。自测按 §3.3 准备 800T A2，报告记录实际机型。

# 可维可测分析

- 在 `test/gemv/sgemv/arch22/` 注册 GTest，用官方 CSV 跑完 1,000 条精度和 200 条性能用例。覆盖转置、矩形、非紧凑 `lda`、正负步长、空维度、参数错误、`β=0` 与非有限值。负向用例直接走接口校验，测试封装先识别 `INT32_MIN`，避免在分配前对它取绝对值。
- 精度按任务书 §3.2 与 CPU 参考结果比对。FP32 使用 `rtol=atol=2^-13`、匹配率至少 99%，最大绝对误差和 Inf/NaN 按任务书规定判定。
- 性能逐例对照随包 A100 CSV，平均耗时上限为对应基线的 1.25 倍。首轮测 `4096×4096` 的 N/T/C 和 `1048576×4`。按 §3.3 用 `msprof op` 预热后采集至少 10 次有效样本，另保留随包脚本使用的 `aclrtEvent` 结果，待确认验收口径。
- 共用原有公开接口和头文件，A2/A3 实现独立于 950PR 路径。编译和实机验证待完成。
