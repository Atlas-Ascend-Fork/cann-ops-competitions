> **Rosetta Flex ddG 端到端加速｜工程与验收设计**
>
> 设计范围为运行环境、Host 运行管理、工程接口、计时与验收规则。

# 需求背景（required）

## 需求来源

依据社区任务书第 2 章确定工程模式和交付接口，第 3 章确定环境、精度与计时口径，第 4 章确定验收材料。章节顺序沿用 CANN 社区设计模板。 [官方设计模板](https://gitcode.com/cann/cann-ops-competitions/blob/master/04_tasks/01_community-task-2026/resources/design_template.md)

## 背景介绍

### 整模块验收背景

任务考核由统一命令启动的完整异构流程。验收范围覆盖整批任务的输出完整性、统计精度和端到端墙钟时间。CANN 提供目标设备的软件栈。

### 性能对照口径

以任务书规定的 48 核 CPU 墙钟基准为性能对照。目标环境为绑定 24 核 CPU 和单卡 Ascend 950PR，采用任务书统一的端到端计时口径。 见任务书第 3 章。

### 工程功能边界

工程接口覆盖环境准备、执行与产物校验。输出文件和运行摘要应对应同一次执行。

# 需求分析（required）

## 需求描述

围绕任务书的统一命令行交付要求定义环境检查、运行记录和验收产物。工程应能说明运行使用了哪一版代码、哪套软硬件和什么命令，并给出用于复核的计时和检查结果。平台初始化、文件写入或校验失败时，错误记录应能定位到具体阶段。

## 需求拆解

| 需求 | 设计约定 |
| --- | --- |
| 环境可复核 | 记录 CPU 型号、亲和性掩码、设备型号、卡号、CANN、驱动和固件版本 |
| 运行可复现 | 记录代码提交、完整命令、运行标识和任务书要求的种子字段 |
| 输出可核验 | 按任务书的接口定义生成结果文件和运行摘要 |
| 性能口径统一 | 用单调时钟度量从入口读取输入到结果落盘的墙钟时间 |

# 详细设计（required）

## 算子分析

### 数学公式

端到端墙钟时间 `wall_time_s = t_end − t_start`，其中 `t_start` 为入口开始读取输入的时间，`t_end` 为最终结果文件落盘完成的时间，二者取同一单调时钟。参考加速比 `speedup = T_ref / wall_time_s`，两项耗时均以秒计且大于零。`T_ref` 取任务书规定的 CPU 墙钟基准。

### 支持数据类型

工程接口使用 UTF-8 的 JSON、CSV 和文本日志。摘要按任务书记录 `wall_time_s`、`mutations_completed`、`cpu_cores_limit`、`npu_device`、`cann_version`、`seed`、`git_commit` 和 `command`。时间为有限数值，计数和种子为整数，版本、命令和提交号为字符串。摘要使用任务书规定的字段名和单位。

### 支持形状

一次执行对应一个运行摘要 JSON 对象和一套结果文件。文件检查覆盖表头、列数、记录数和数据类型，以任务书规定的文件格式为准。 见任务书第 2.4 节。

## 算子实现

### 实现方案

运行管理依次完成环境检查、执行记录、结果落盘和产物核验。开始时记录版本及执行标识。写入产物后才记录成功并归档摘要。失败时保留诊断日志并返回非零状态，避免把部分产物当作完整结果交付。运行管理接口和日志结构与设备计算实现分开验证。

#### 3.2.1 host侧设计：

Host 运行管理负责检查依赖和设备可访问性、确认 CPU 亲和性、记录计时、写入摘要和报告错误。按环境检查、计算执行、结果写入、校验、摘要写入五个阶段标记错误。运行摘要与结果使用同一运行标识，复核时先验证运行标识与产物的一致性。

##### 1. 分核策略：

验收由操作系统 CPU 亲和性或容器 cpuset 约束主机进程及其工作线程。预检读取可用 CPU 集合，确认验收运行绑定 24 核，并将读取的掩码与请求值同时记录。

##### 2. 数据分块和内存优化策略：

资源管理应向 Host 报告初始化和分配异常。内存使用属于工程检查项，任务书未设独立的内存验收阈值。

##### 3. tilingkey规划策略：

Host 与设备模块以匹配的构建版本交付。构建标识应能区分设备接口版本，以便定位版本不匹配问题。

#### 3.2.2 kernel侧设计：

设备模块通过运行时接口向 Host 报告执行状态。设备调用异常应进入统一错误处理流程，按调用阶段返回诊断信息。

## 支持硬件

| 要素 | 任务书目标环境 | 环境配置项 |
| --- | --- | --- |
| CPU | 绑定 24 核 | 型号、亲和性掩码和进程约束方式 |
| NPU | 单卡 Ascend 950PR | 具体型号和逻辑卡号 |
| CANN | 9.0.0 及以上 | 完整版本号与配套驱动、固件版本 |

## 算子约束限制

正式验收限于任务书指定的单机、单卡和 24 核环境。输出和验收报告必须对应同一次执行。一次性软件安装和源码编译从性能计时排除，入口运行中的加载、准备与结果落盘纳入计时。任务书规定的协议约束、输入输出和验收条件继续适用。 见任务书第 3 章和第 7 章。

# 可维可测分析

## 精度标准/性能标准

| 验收项目 | 判据 |
| --- | --- |
| 结果完整性 | 结果文件必填字段、记录数及有限值要求符合任务书 |
| 统计精度 | 按任务书第 3.2 节的分层判据执行官方自验 |
| 端到端性能 | `wall_time_s ≤ 5565.3 s`，相对 48 核参考基线至少 `10.0×` |
| 可追溯性 | 命令、环境、代码版本和输出可追溯到同一次运行 |

工程负向验证覆盖缺少依赖、绑核条件不符、设备不可用、输出路径不可写及摘要字段缺失。各用例按预期错误阶段和退出状态核对。 见任务书第 3—4 章。

## 兼容性分析

任务书规定的命令行接口和结果字段是交付契约。更新工程内部实现时，验证结果和摘要仍可由官方检查工具读取。变更 CANN、驱动或固件时，复核环境预检、构建与目标设备执行的兼容性。
