# 需求背景（required）

## 需求来源

本设计对应“10月社区任务-ops-nn算子onnx适配”，目标仓库为 [cann/ops-nn](https://gitcode.com/cann/ops-nn)，迁移接口参考 [Issue #5115](https://gitcode.com/cann/ops-nn/issues/5115)。改造范围以任务书第1节列出的 **75个算子条目、74个插件文件**为准。

## 背景介绍

### 现有实现及问题

现有插件通过 `ParseParamsFn` 接收 `google::protobuf::Message`，转为 ONNX 节点后读取属性、名称和输入输出信息。解析实现直接依赖 protobuf 生成类型，单测也需要构造 protobuf 对象。

迁移后使用 `ge::Operator` 接收框架信息，通过 `attribute` JSON 读取属性，注册为 `ParseParamsByOperatorFn`。改造目标是解除解析层的 protobuf 依赖，同时保持已有模型转换行为。

### 改造范围

范围包含激活、卷积、归一化、池化、索引、量化及RNN等插件。`NPUDynamicQuant` 与 `NPUDynamicQuantV2` 共用一个插件文件，两条注册均保留；Softmax的V11/V13路径、ScatterElements的历史Scatter注册也分别覆盖。

工程修改由74个插件、74份对应framework UT、UT构建接入和一个公共头组成。公共头使用仓前缀命名为 `common/inc/framework/nn_onnx_plugin_util.h`，复用仓内JSON库。

# 需求分析（required）

## 需求描述

完成任务范围内全部参数解析入口的等价迁移，使相同模型在迁移前后得到相同的目标属性、注册映射及推理行为。原有数据类型、形状、格式、默认值和可选输入输出约束继续生效。

## 需求拆解

1. 替换回调签名和注册接口，移除解析代码对protobuf生成头文件、类型和运行库的直接依赖。
2. 保留属性缺省、类型判断、重复属性顺序、校验分支、名称及动态输入输出行为。
3. 为各插件接入framework UT，并通过迁移前后OM转换、推理验证等价性。
4. 保持GraphFn、kernel、tiling和算子原型不变；已有计算逻辑问题另行记录。

# 详细设计（required）

## 算子分析

### 数学公式

本任务修改参数解析入口，原计算公式和计算图保持。解析过程为：

```text
源 ge::Operator
  ├─ 节点名称、输入输出信息 ─────────────┐
  └─ attribute JSON → 按原顺序逐属性解析 ├→ 目标 ge::Operator → 原计算图
                                      ┘
```

### 支持数据类型

沿用各算子原有dtype约束。解析层保持整数、浮点、字符串、列表和Tensor属性的类型；不新增或扩大设备计算dtype支持。

### 支持形状

沿用原插件的rank、形状、广播、动态输入输出及可选槽位约束。形状相关属性按原分支写入，由原推导和计算实现继续处理。

## 算子实现

### 实现方案

#### 3.2.1 host侧设计：

**接口和注册。** 回调改为以下签名，原函数名及其注册关联保持：

```cpp
domi::Status ParseParamsXxx(const ge::Operator& op_src, ge::Operator& op_dest);
```

注册使用 `.ParseParamsByOperatorFn(ParseParamsXxx)`，原 `OriginOpType`、opset范围、`ImplyType`及动态IO注册保持。

**公共工具与插件分工。** 公共头负责取得名称、输入输出槽位、JSON属性数组及基础字段读取；各插件继续保留自己的属性名、默认值、校验和写入顺序。名称获取改用 `GetOpName(op_src)`，保留原 `name`、`original_type` 写入行为。

属性数组按原遍历顺序处理，不预先合并成“同名属性只留一个”的字典。原实现取首个、后者覆盖或列表累加的路径分别保持；原来不检查属性type的分支，也不额外增加type过滤。

| 关键语义 | 实现方式及检查点 |
| --- | --- |
| 整个属性缺失 | 使用原默认值或保持原未写出行为；原必需属性缺失时仍失败。 |
| 属性存在，标量字段省略 | 按proto零值处理。FLOAT属性缺 `f` 取0.0，不能退回算子默认值；INT属性缺 `i` 取0。 |
| FLOAT载体 | 按任务约定读取字符串型 `f`，再用仓内浮点转换工具处理；非法值按解析契约返回失败。 |
| 字符串及Tensor | 保留完整字节、dtype和shape；转换后的Tensor持有有效数据，避免局部缓冲区失效。 |
| 可选输入输出 | 按源槽位信息保留空槽、输入数及原写入时序，不能把空槽直接删除。 |
| JSON异常 | 读取JSON的路径捕获解析异常并返回FAILED；原来不读取JSON的路径保持原固定属性和SUCCESS行为。 |

两个具体检查例：Gemm的 `transA`、`transB` 独立处理，缺一侧不改变另一侧默认值；Conv的四项pads由 `[h_begin,w_begin,h_end,w_end]` 重排为原内部顺序，奇数长度仍失败。这样可以在属性断言和OM输出上直接发现迁移错误。

**Int8ConvRelu内部属性契约。** 原Host生产者将 `ascend_quant_offset` 写为FLOAT，原GraphFn以int读取，读取失败后仍使用未初始化的int。本次仅将生产者写入类型改为INT，保留原 `zero_point=3`，不修改getter、GraphFn、kernel或tiling。原10项UT保留，其中3项成功用例的类型断言同步为INT；新增3项直接调用int getter的契约测试，共13项。对标双方都使用该修复：`B*`=原实现＋共同补丁，`C*`=迁移实现＋同一补丁。该共同修复及`B*`/`C*`对标基线随代码一并提交正常评审，原未修复库的真实失配证据保留。

##### 1. 分核策略：

不涉及。本次为Host解析代码，设备分核沿用原tiling和kernel。

##### 2. 数据分块和内存优化策略：

不涉及设备分块或UB优化。Host侧检查JSON、字符串和Tensor载荷的数据生命周期。

##### 3. tilingkey规划策略：

不新增或修改tilingkey，原设备执行分支保持。

#### 3.2.2 kernel侧设计：

本次无kernel改动。带 `ParseOpToGraphFn` 的插件仅迁移参数解析入口，原拆图函数和动态输入逻辑保持。

## 支持硬件

任务书允许在Atlas A2或Ascend 950任一平台验证，CANN版本要求大于9.0.0。每组迁移前后比较使用同一硬件和环境。本次实际验证使用Ascend950PR、CANN9.1.0，当前结果不混入旧A2记录；各算子能否转换、执行仍受原SDK及设备实现约束。

## 算子约束限制

- 原注册范围、属性和设备实现约束保持，不通过修改GraphFn、kernel或tiling扩大支持域。
- Int8ConvRelu原未修复完整库的950数值失配保留。采用上述共同INT修复后，原模型、meta及全部3个输入不变，完整INT8输出8,454,272字节一致；该结果与未修复对照分开记录，共同补丁及基线待正常评审。
- Gemm缺省C补例保留原GraphFn忽略alpha的行为，只验证迁移等价性，不宣称修复ONNX计算语义。
- 官方用例或UT与精确基线源码不一致时，按任务书修订许可单独说明并提供修改代码，不改变生产语义迁就错误断言。

**执行方法。** 构建插件并开启 `OP_HOST_UT`，运行 `Onnx*PluginTest.*`；experimental用例使用对应构建配置。OM验证归档本轮插件实际加载路径及内置同名注册被跳过的日志，防止误用内置插件。对动态输出按官方工具声明分配容量并预先置零，保存完整设备输出；容量校验与设备返回的动态shape分别说明。

两轮输出不同须先按原规则排查；只有实测不可复现并说明原因的用例才可申报对应档位，不能为消除差异直接放宽判据。

**补充覆盖。** 在原全部模型及其变体之外，补充未覆盖的dtype、属性取值和可选IO场景，包括Conv无bias、Gemm无C。每次配对复用同一份模型和输入；生成器、UT、工具或meta的修订均保留原因和代码。

## 兼容性分析

以迁移前仓代码为基线，逐插件保持注册、属性、名称和IO语义。旧接口在特定SDK所需的兼容层只部署于迁移前插件；迁移后插件独立验证protobuf依赖已解除。公共工具使用仓前缀及仓内JSON版本，避免与其他算子仓重名或引入新依赖。
