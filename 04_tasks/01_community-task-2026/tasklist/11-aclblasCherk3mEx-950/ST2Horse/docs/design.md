# 需求背景

## 需求来源

2026 年 11 月 CANN 社区任务「aclblasCherk3mEx 算子开发（950）」。本设计面向 `cann/ops-blas` 的 Ascend 950PR（arch35），依据任务书 §2–§4 及随附用例编写。

## 背景介绍

Hermitian 秩-k 更新只需要计算结果的一半。已有 `aclblasCherk` 提供句柄、列主序和三角更新的参考实现，其 arch35 通用路径分别启动四次实数矩阵乘。本接口增加交错复数 INT8 输入，并要求在一次计算 kernel 启动中完成三个实数乘积。可复用仓内实数矩阵分块与流水实现；共轭、三角归属和标量处理由本接口负责。

# 需求分析

## 需求描述

```cpp
aclblasStatus_t aclblasCherk3mEx(
    aclblasHandle_t handle, aclblasFillMode_t uplo, aclblasOperation_t trans,
    int n, int k, const float* alpha, const void* A, aclDataType Atype, int lda,
    const float* beta, aclblasComplex* C, aclDataType Ctype, int ldc);
```

结果为 `C ← αXXᴴ + βC`。α、β 为实数 FP32，支持 Host 和 Device 标量。A、C 为列主序，调用方保证 A 的可读区域与 C 的可写区域不重叠。公共声明位于 `include/cann_ops_blas.h`，实现位于 `blas/herk/arch35/`，测试位于 `test/herk/cherk3m_ex/arch35/`。算子说明增补到 `blas/herk/README.md`。

## 需求拆解

| 参数或状态 | 预期行为 |
| --- | --- |
| N、C | N 时 X=A，A 为 n×k；C 时 X=Aᴴ，A 为 k×n。OP_T 和其他非法枚举返回 INVALID_ENUM |
| UPPER、LOWER | 仅访问指定三角，结果原地写回；参与更新的对角虚部写正零。未选三角和列尾逐字节保留 |
| 类型与步幅 | A 为 ACL_COMPLEX64 或 ACL_INT8，C 为 ACL_COMPLEX64；其他组合返回 NOT_SUPPORTED。lda 至少为 max(1,N 模式的 n 或 C 模式的 k)，ldc 至少为 max(1,n) |
| 空指针与尺寸 | 空句柄返回 HANDLE_IS_NULLPTR；非法尺寸、前导维度、空标量返回 INVALID_VALUE。n>0 时 C 必须非空，秩-k 项实际参与时 A 必须非空 |
| 退化计算 | n=0 无设备启动；k=0 或 α=0 时允许空 A，β=1 保持 C 全部位，其他 β 仅缩放指定三角；β=0 时不读旧 C，对角虚部也无需读取 |

# 详细设计

## 算子分析

令 X=R+iI。N 路径的逻辑元素 (i,t) 来自 A[i+t·lda]；C 路径来自 A[t+i·lda] 并对虚部取反。INT8 实、虚字节分别提升至 FP32 后再共轭或求和，因而 −128 取负不会回绕。P=RRᵀ，Q=IIᵀ，W=(R+I)(R−I)ᵀ。结果实部为 P+Q，虚部为 W−P+Q。对角线只需实部，并显式清零虚部。

例如 N 模式、n=2、k=1，A 的两行分别为 1+2i 与 3+4i，α=1、β=0。UPPER 应写 C₀₀=5、C₀₁=11+2i、C₁₁=25；LOWER 应写 C₁₀=11−2i。这个例子可以区分共轭方向和列主序下的转写方向。

## 算子实现

### Host、分核与存储

1. 按句柄、uplo/trans、n/k/lda/ldc、标量与类型和矩阵指针的顺序检查。标量指针和类型须在 n=0 时也合规。CPU 标量取值后按值下发；Device 标量遵循 handle 绑定的 stream 顺序。若需要根据 Device α 判定空 A 合法性，读取标量后按仓内约定同步并检查错误；正常张量计算异步下发。禁止 CPU 直接解引用 Device 地址。
2. Host 根据形状、输入类型、转置和片上容量选择缩放、小规模或 Cube 路径。小规模由同一计算 kernel 为每个三角元素累计三个实数乘积；缩放只处理有效三角。大规模初始方案采用 64×64 输出块，K 按硬件矩阵乘粒度分片。只分派指定半面的块，对角块内再屏蔽另一半。核数由平台查询并受有效块数限制。
3. 一次输出仅由一个逻辑块完成最终写入。K 分段时，分段乘积写到各自独占的中间区域，统一按段序合并；不以多个核对同一个 C 元素作无序覆盖。最后一块的填充只发生在私有面板，读写用户 A/C 时使用真实 n、k、lda、ldc。地址、三角块数、工作区乘法及对齐用宽整数并检查溢出。
4. 以面板高 Np、面板深 Kp 估算，大路径四份 FP32 输入面板占 16·Np·Kp 字节。设输出块边长 B、选中块数 T、同时保留 S 个 K 分段，三份部分积占 12·T·B²·S 字节。默认从单段开始；如需要多段，优先滚动复用或分批调度。L1/L0 的矩阵片沿用 Cube 内核布局；向量侧按实际 UB 容量为输入片、转换/输出片和对齐留足空间，启用双缓冲前复核两组缓冲的总占用。工作区按句柄约定申请、在同一流上按序复用，覆盖用户指定工作区不足、重复调用和流切换。

### Kernel 与数值处理

打包阶段从交错输入提取 R、I、R+I、R−I。Cube 计算阶段在**同一 kernel 的每个工作块内**顺次计算 P、Q、W，三次计算共用分块参数；使用矩阵引擎的输出布局时核对 W 两侧操作数与目标 C(i,j) 的方向。写回阶段处理 α、β、三角边界与对角虚部。三个阶段在同一条流排队，无跨核自旋。极小问题可在一次设备启动中直接完成 3M 和写回，减少额外启动及面板搬运。

浮点输入优先使用 FP32 路径，重点覆盖 3M 虚部相消、对角平方和、极端缩放及非有限值传播。对能用数据本身判断的特殊值或舍入敏感分量，可在融合 kernel 中单独修正并验证；输入类型提升和实虚符号保持一致。以正式用例验证累加精度与 K 分段选择，记录偏差最大的元素，不因输入编号或种子改变算法。

## 支持硬件与约束

目标为 Ascend 950PR、CANN 9.1.0 及以上。运行时接受合法 n、k 与带填充的前导维度。输入无广播，C 原地更新；精度验证包含非方输入、非对齐尾块及非零对角虚部。实现独立于同期的 `aclblasCherkEx`。
