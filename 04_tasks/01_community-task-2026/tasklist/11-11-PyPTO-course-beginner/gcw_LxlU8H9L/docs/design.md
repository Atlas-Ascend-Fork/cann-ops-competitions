# 面向零基础人群的 PyPTO 算子开发课程设计文档（算子工坊方案）

## 需求背景（required）

### 需求来源

11 月社区任务：开发一套面向 0 基础人群的 PyPTO 算子开发课程。本设计提出**算子工坊**方案：课程以"PyPTO 算子"为主线组织——学员每学会一个数学/网络概念，就同步把它实现为一个可运行、可验证的 PyPTO 算子，课程结束时学员亲手写完约 30 个算子，覆盖任务书要求的全部知识点。

- 任务书：任务页附件《开发一套面向0基础人群的PyPTO算子开发课程.md》（知识点范围、验收标准以任务书为唯一真值源）
- 课程提交目标：`cann-learning-hub` 仓 `contrib/tutorials/pypto_op_workshop/`（任务书 §5 指定 `contrib/tutorials/`）
- 上库标准：`docs/course_submission_criteria.md`（三级目录、命名规范、三道验收关）；目录组织判例参照仓内已合入课程 `contrib/tutorials/computer_composition_and_architecture/`
- 设计文档提交：`cann-competitions` 仓 `04_tasks/01_community-task-2026/tasklist/11-11-PyPTO-course-beginner/gcw_LxlU8H9L/docs/design.md`，以 PR 形式提交
- PyPTO 权威来源：pypto.gitcode.com 官方文档（Tensor 编程 + `pypto.frontend.jit`），CANN 9.1.0 起随包集成；课程 API 口径以 CANNLab 实测为准
- 截止与奖金：2026-12-21，¥39,730.50；讨论帖 atomgit.com/cann/cann-learning-hub/discussions/71

### 课程定位与差异化

面向**零 AI 基础但有基础 Python 能力**的学习者（学生、软件/测试工程师、其他行业从业者）。与按学科分章的传统 AI 课程不同，本课程按**算子类型**分章（逐元素→归约与索引→矩阵乘与线性层→卷积→循环门控→注意力），每个概念即一个算子工坊：先在白板上讲清数学直觉，再进 Notebook 把它写成 PyPTO 算子，跑通、验证、然后做一道**错误猎手**练习（见需求分析）——学习路径与昇腾算子开发者的真实工作方式同构。

## 需求分析（required）

### 教学策略：一概念一算子一验证

| 教学环节 | 形式 | 对应任务书要求 |
| --- | --- | --- |
| 数学直觉 | 手算小例子（≤4 个元素）+ 结构图，不堆公式 | §3.3-2 不堆复杂数学公式 |
| PyPTO 实现 | 完整可运行 code cell（声明→编译→执行→同步→读回） | §3.4-1 全流程不切目录 |
| 参考对照 | NumPy 独立实现 + 误差断言（atol/rtol 逐算子配置） | §3.4-3 代码正确 |
| 边界测试 | 空输入/极端值/Inf/NaN 的行为观察 cell | §3.5 特殊值覆盖 |
| **错误猎手** | 给一段带 bug 的实现（shape 错配/掩码反/忘记同步/类型错），学员定位并修复 | §4-3 练习题精确有效 |

**错误猎手体系**是本方案的练习特色：每章至少 2 道注入真实 bug 的调试题（bug 类型取自算子开发的真实错误模式），比常规"从零编写"更高效地训练排错能力，且天然可自动判定（修复后断言通过即得分）。纯概念小节配选择/填空题。所有练习附完整答案（`answer/` 独立 notebook，与正文零共享状态）。

### PyPTO 计算与工程设计

**编程模型**（pypto.gitcode.com 官方口径）：主机侧准备输入/输出张量（torch_npu 承载），`pypto.frontend.jit` 类型注解描述设备计算，执行后同步读回。铁律：**模型张量运算一律 PyPTO 实现**；NumPy 只承担参考实现与数据生成，每个算子配"PyPTO 结果 vs 参考结果"对照断言——不把 torch/NumPy 调用包装成 PyPTO 实现。开发期先在 CANNLab（A2/A3，CANN 9.1.0，Python 3.11）跑通五级样例（env_check → add → matmul → conv → attention）校准 API，再批量生产章节内容；课程代码只承诺实测版本可用，版本号随环境表公布。

**工程结构**（按课程标准三级目录）：

```text
contrib/tutorials/pypto_op_workshop/
├── README.md                 # 主 README：简介/人群/硬件表/环境表/目录
├── coverage.md               # 任务书知识点 → 算子/练习/验证映射矩阵
├── common/                   # env_check.py 环境自检 + ref_impl.py 参考实现与对照工具
├── tools/                    # check_structure.py 结构检查 + run_all.py 逐本执行
└── ch1_getting_started/      # 各章同构：README + 0n.0m_*.ipynb + answer/ + images/ + src/
```

- 每本开头固定三 cell：环境自检 → 课程根定位（向上查找标记文件）→ 本节导入；逐本新内核可独立执行，无跨本状态；
- 结构图为原创 SVG/PNG（广播轴对齐、卷积窗口滑动、RNN 状态流转、注意力数据流、Transformer 架构），存各章 `images/` 相对引用；
- 错误猎手题：`%%writefile` 释放带 bug 骨架到本节工作目录 → 学员定位修复 → 运行自测断言判定；答案本含完整修复版与"bug 讲解"（该错误在真实算子开发中的原型）。

## 可维可测分析（required）

### 验证方案（对齐课程标准三道关）

1. **AI 低错检查**：文本/链接/拼写检查，课程内相对链接随结构脚本校验；
2. **Checklist 自检**：课程标准清单逐项打勾（三级目录、命名、README 五要素、练习答案齐备、图片相对引用、无过时 API），自检表附 PR 描述；
3. **运行验证**：`tools/run_all.py` 逐本新内核全量执行（正文+答案），记录耗时/失败 cell/traceback，禁止 allow-errors；验收证据 = 执行日志 + 环境自检输出。

### 数值口径

- 每算子对照：`|actual − ref| ≤ atol + rtol·|ref|`（FP32 默认 atol=1e-5 / rtol=1e-4，逐算子可在配置覆盖）；注意力掩码行、softmax 大值、梯度饱和区单设判据；
- 训练类实验验证：损失有限且呈预期趋势、参数更新有效、因果性断言（改未来 token 前缀不变）；
- 错误猎手判定：修复后目标断言通过（自动判定，无主观分）。

### 兼容性与交付节奏（截止 2026-12-21）

- 纯新增目录，不动 cann-learning-hub 既有文件；依赖固化（CANN 9.1.0 配套 PyPTO / Python 3.11），数据全部代码生成（固定种子），无外部下载依赖；
- 小形状约束（向量 ≤4096、矩阵 ≤128²、序列 ≤32、batch ≤8），单本端到端 ≤5 分钟，全课程 ≤1 小时跑完；
- 6 周节奏：W1 CANNLab 环境实测 + 五级样例 + 第 1 章样章（全部范式定版）；W2–W3 第 2–4 章（张量/微分/MLP）；W4 第 5–6 章（卷积循环/注意力）；W5 全量 run_all 终验 + coverage.md 终版 + PR 与评审闭环；W6 缓冲与验收材料打包。
