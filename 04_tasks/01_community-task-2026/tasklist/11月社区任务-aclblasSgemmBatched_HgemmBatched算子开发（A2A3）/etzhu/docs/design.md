# aclblasSgemmBatched / aclblasHgemmBatched 算子设计文档


## 1 需求背景

### 1.1 需求来源

本设计在 Atlas A2/A3 的 arch22 平台上实现单精度和半精度的指针数组批量矩阵乘，接口语义分别对标 cuBLAS 的 `cublasSgemmBatched` 与 `cublasHgemmBatched`。两个接口均在 ops-blas 的 `include/cann_ops_blas.h` 中声明，通过 BLAS handle 绑定的 stream 下发计算。

### 1.2 背景介绍

同一批内的矩阵共享尺寸、转置方式和标量，而各矩阵的 Device 起始地址由表项分别给出。对于大矩阵，关键是让 Cube 持续处理输出块；对于数千个小矩阵，逐矩阵读取指针、搬运和写回可能比乘加耗时更多。带填充的前导维和非单位标量又限制了直接写回 C 的条件。因此，分发既考虑矩阵尺寸，也考虑实际前导维、标量和可用工作区。

## 2 需求分析

### 2.1 算子接口与约束

S 的矩阵和标量均为 FP32，H 的矩阵和标量均为 FP16。每个批次索引 `b ∈ [0, batchCount)` 独立计算 `C[b] ← α × op(A[b]) × op(B[b]) + β × C[b]`。其中 `op(A)` 为 `m×k`，`op(B)` 为 `k×n`，逻辑输出为 `m×n`。`ACLBLAS_OP_N` 保持原矩阵，`ACLBLAS_OP_T` 和 `ACLBLAS_OP_C` 对实数均表示转置。

| 参数 | 类型和位置 | 形状与约束 |
| --- | --- | --- |
| `handle`，`transa`，`transb` | Host 句柄和枚举 | handle 有效；两个转置标志各自取 N、T 或 C。 |
| `m, n, k, batchCount` | Host `int` | 均非负。尺寸和批量在调用时传入。 |
| `alpha, beta` | Host 标量指针 | S 使用 `float`，H 使用 `aclblasHalf` 的 IEEE binary16 位表示，两指针均须有效。 |
| `Aarray` | Device 只读指针表，表项指向只读 A 矩阵 | N 时物理存储为 `lda×k` 且 `lda≥max(1,m)`；T/C 时为 `lda×m` 且 `lda≥max(1,k)`。 |
| `Barray` | Device 只读指针表，表项指向只读 B 矩阵 | N 时为 `ldb×n` 且 `ldb≥max(1,k)`；T/C 时为 `ldb×k` 且 `ldb≥max(1,n)`。 |
| `Carray` | Device 只读指针表，表项指向可写 C 矩阵 | 每个矩阵占 `ldc×n` 个元素，`ldc≥max(1,m)`。原地写回各列的前 `m` 个元素，保留列尾填充。 |

`lda, ldb, ldc` 为 Host 按值传入的 `int` 型前导维，按元素计，其下界见上表。三个指针表的长度均为 `batchCount`，表本体和所指矩阵均在 Device 上。调用方保证各有效表项指向足够长的内存，各 `C[b]` 的写入区互不重叠，且与任何批次的 A、B 输入区互不重叠。只读输入地址可以重复。接口不对形状做广播，也不要求相邻批次等距。

### 2.2 需求拆解

| 要解决的问题 | 设计决定 | 核验方式 |
| --- | --- | --- |
| 空矩阵、零标量或非法参数 | Host 按依赖关系校验，区分立即返回、仅缩放 C 和执行乘法 | 检查状态码、空指针、NaN 旧值及未写区域 |
| 列主序、转置、非紧凑矩阵 | 以真实指针和前导维建立视图，尾块按有效行列数搬运 | 覆盖九种转置组合、偏移地址和各列填充哨兵 |
| 大矩阵吞吐与小矩阵调度开销 | Cube 分块、AIC/AIV 协同，以及小矩阵按批打包 | 逐例与任务包中同参数的 A100 kernel 基线比较 |
| S/H 精度及极值处理 | FP32 累加，H 在输出处收窄；对有溢出风险的小 FP32 面板保留复算路径 | 使用独立 CPU golden，同时检查混合容差与逐元素误差上限 |

## 3 详细设计

### 3.1 算子分析

取第 `b` 个批次，输出 `C(i,j)` 的列主序偏移为 `i + j×ldc`。第 `l` 个内积项的偏移如下，均以元素计。每个矩阵的起始地址分别取自 `Aarray[b]`、`Barray[b]`、`Carray[b]`。

| 取数 | N | T 或 C |
| --- | --- | --- |
| `op(A)[i,l]` | `i + l×lda` | `l + i×lda` |
| `op(B)[l,j]` | `l + j×ldb` | `j + l×ldb` |

Cube 将同一段列主序内存看作行主序的转置视图，以 B 为左操作数、A 为右操作数，形成乘积 `(op(A) × op(B))ᵀ`。`SetOrgShape` 描述含前导维的物理布局，`SetSingleShape` 描述当前有效块。这一映射省去了对整矩阵的显式转置，也使输出能直接按调用方的 `ldc` 定位。

### 3.2 Host 侧设计

1. 空句柄返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`。转置枚举越界返回 `ACLBLAS_STATUS_INVALID_ENUM`。维度、批量、前导维或标量指针非法返回 `ACLBLAS_STATUS_INVALID_VALUE`。
2. 上述校验成功后，若 `m=0`、`n=0` 或 `batchCount=0`，直接返回 `ACLBLAS_STATUS_SUCCESS`，无需访问矩阵地址表或启动 kernel。
3. 输出非空时先要求 C 地址表有效。仅当 `k>0` 且 `α≠0` 时才要求 A、B 地址表有效。无乘积且 `β=1` 时直接成功返回；其余无乘积场景只做 `C ← βC`。`β=0` 时所有路径均可在旧 C 未初始化的情况下写出结果。
4. H 的 Host 标量按 binary16 位模式解码为 FP32。`RunTiles` 按精度、转置、形状、前导维、标量、核数及工作区选择路径。`RealGemmBatchedParams` 为 64 字节，按值携带维度、标量、模式和 64 位窗口位置。需要的核数为零时返回 `ACLBLAS_STATUS_INTERNAL_ERROR`，kernel 下发失败返回 `ACLBLAS_STATUS_EXECUTION_FAILED`。
5. Host 在 `handle->stream` 上按顺序下发各阶段。API 成功返回表示本次下发成功；调用方在读取结果或释放 Device 表、矩阵和工作区之前，等待该 stream 的工作完成。

### 3.3 分核、分块与工作区

通用路径以 `128×128` 输出块为单位。令 `R=ceil(m/128)`、`Q=ceil(n/128)`，第 `b` 个矩阵的第 `q` 个列块、第 `r` 个行块对应线性编号 `(b×Q+q)×R+r`。Host 检查总块数是否能用 64 位表示。核从自身编号开始，以实际启动核数为步长领块；边界块取剩余行列数。专用路径按其访存特点重分块，例如将一个 `256×128` 乘积块分给两个 AIV 子核写回。

通用 Cube 的基本 K 块为 FP32 的 64 或 FP16 的 128。单段 K 最多 4096，超长 K 分段将结果累加到 FP32 临时块。默认标量 `α=1, β=0` 且满足 K 范围、输出前导维和相应布局条件时，可直接写 C。需要临时乘积时复用 handle 的工作区，其默认容量为 32 MiB，调用者也可配置。通用槽大小为 `128×128×sizeof(float) = 64 KiB`。

### 3.4 Kernel 侧设计

| 场景 | 数据流与选择理由 |
| --- | --- |
| 常规矩阵、长 K | Cube 通过 Matmul 计算分块乘积，禁用 HF32。需要缩放或旧 C 时保留 FP32 乘积，由 AIV 完成 `αP+βC`。仅 `β≠0` 时读取 C。通用向量路径按 K 面板搬运，处理 Cube 描述符范围外的尺寸或步幅。 |
| 短 K、大输出，含非对齐前导维 | 条件满足时 AIV 把输入整理到对齐的临时面板，K 向上补至 16 的倍数并补零。Cube 在本核的两个工作区槽之间交替写入结果，两个 AIV 子核按列分工，用原 `ldc` 和实际有效长度写回 C。 |
| 小输出、长 K | FP16 单批次计算中，当 α≠0、`16≤m,n≤64`、`512≤k≤4096`、`lda≤65535`、`ldb≤65535`，且工作区足以存放各段 FP32 部分积时，沿 K 维切分。`k≤2048` 时每段最多 256 项，`k>2048` 时每段最多 512 项。AIC 并行计算部分积，AIV 归并后完成标量更新并写回 C。 |
| 小矩阵、大 batch | 将多个独立矩阵放入同一组向量指令；FP32 的 `1×1×1` 路径每包最多 512 个批次。在 Device 核对一组指针的实际步长，满足条件才合并 DMA，其余情况按表项搬运。 |
| FP16 紧凑 NN，`512³`，batch=2，`α=−1, β=1` | 完整窗口且至少可用 16 个 AIC 时，16 个 Cube 任务各算一个 `256×128` 乘积块并写入私有 FP32 槽。每个 AIC 发布结果就绪信号，两路 AIV 各消费半块，在 FP32 执行 `C−AB`，最后转 FP16 写回。 |
| FP16 紧凑 NN，`17×33×15`，batch≥32 | 纯 AIV 路径每组最多处理 4 个矩阵，在 UB 将数据转为 FP32，并按行、列收集操作数。15 个 K 项按每组 5 项执行外积与累加，接着在 FP32 执行标量更新，转回 FP16 后，每个矩阵仅写回 561 个有效元素。省去向 GM 写临时乘积和跨核等待。 |

## 4 可维可测分析

### 4.1 精度标准

S 的 CPU 基准为 Netlib BLAS 3.10.0 的 `cblas_sgemm`。H 将 FP16 输入、标量及所需的旧 C 展开为 FP64，调用 OpenBLAS 0.3.29 的 `cblas_dgemm`，结果依次转换为 FP32、FP16，得到 golden。Device 计算精度见第 3.4 节。

有限元素以 `abs(actual−golden) ≤ atol + rtol×abs(golden)` 判定是否匹配；每例要求匹配率至少 99%，且每个元素的绝对误差均不超过 `max(固定上限, 32×ULP(golden))`。S 的 `atol=rtol=2⁻¹³`、固定上限为 0.01；H 的 `atol=rtol=2⁻¹⁰`、固定上限为 0.1。NaN 检查对应位置，无穷值检查符号。输出的前部保护区、各列填充和尾部保护区另作字节比较。

### 4.2 性能标准

正式 kernel 计时与辅助 ACL event 计时的判据依据任务书 §3.3, 正式判据为单次调用全部 kernel 的设备耗时。每例预热 5 次，取随后连续 10 次成功调用，先合计一次调用内全部阶段和工作区窗口的 `Task Duration`，再取算术平均，达标条件为 `mean_kernel_us ≤ 1.25 × gpu_ms × 1000`。
