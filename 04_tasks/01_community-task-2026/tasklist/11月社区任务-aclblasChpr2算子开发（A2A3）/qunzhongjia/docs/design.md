# aclblasChpr2 设计文档

## 需求背景

复数压缩 Hermitian 秩二更新。写入 AP 的每项增量为 alpha*x[i]*conj(y[j]) + conj(alpha)*y[i]*conj(x[j])。

目标平台为 Atlas A2/A3（arch22），性能验收使用 Atlas 800T A2（910B3）。本方案采用按压缩列长度分核。[官方任务及附件](https://www.hiascend.com/activities/task-center/details/7a1275ee6b654459957fc27c8dde32b0)

## 需求分析

沿用 ops-blas 公共头文件的入口、枚举和状态码。Host 按任务书 §2.4–2.5 校验结构参数，区分空规模、标量短路和实际读写张量的情形。设备侧从 handle 绑定的 stream 执行，所有地址计算使用能容纳物理跨度的整数。

设置非实 alpha 且 x 与 y 不平行，区分两个共轭方向。上、下压缩分别与参考比较；检查长度一、零步长错误和 alpha 为零时 AP 保持原样。

## 详细设计

### 按压缩列长度分核

用压缩前缀元素数平衡各核所有的列。每次将一段 x、y 搬入本地，缓存列首标量，沿 i 连续处理 AP。对角单独取实数输出，其他位置按复数更新。

写回采用单列内有界尾块。alpha 为零时在指针校验后返回，保持原 AP 字节。

实现落在 `blas/spr2/arch22/`，GTest 接入 `test/spr2/chpr2/arch22/`。同一 API 在不同 tiling 下采用相同的参数校验与数据类型约定。对齐搬运的最后一段以逻辑末元素为界，必要时用带掩码的存取处理尾部。

## 可维可测分析

在设备侧通过公共 API 发起计算，用 Netlib CHPR2 生成独立参考值。每个用例保留随机种子、输入类型、期望状态与实际状态；正常输出按用例的 `mere_threshold` 和 `mare_multiplier` 核对，复数输出分别统计实部和虚部。计数由本期随包 CSV 得出。

| 官方用例表 | 精度及契约用例 | 性能用例 |
| --- | ---: | ---: |
| `chpr2_test.csv` | 1000 | 200 |

正式性能采集先预热 5 次，后取 10 次有效调用。用 msprof op 读取 Task Duration，每次先合计该调用的计算内核再求均值，换算为 ms 后与对应变体的 gpu_baseline.csv 对齐。每项 NPU 平均内核时间 ≤ 对应 GPU 基线的 1.25 倍。记录实际加载的库、设备和原始计时。任务书 §3.4 将内存专项列为不涉及。
