## 背景介绍

Flex ddG 通过骨架采样、侧链重打包及约束最小化，计算突变对蛋白结合自由能的影响。直接运行时，评分和导数计算与 CPU 协议控制交错，涉及大量细粒度计算、几何采集和主机设备同步。本任务保留原始算法与力场，将可批量计算的成对相互作用与导数归约交由 Ascend C 实现，并在 24 核 CPU 与一张 950PR 上协同执行独立轨迹。

### 标杆实现与现状分析

标杆为 Rosetta 2026.29，固定提交 80a0635615099e1b918474a63acba7b1de6fd107。保留任务包 ddG-backrub.xml、talaris2014、原始 backrub、repack、mutate 和最小化协议。本任务属于分子模拟应用加速，无对应 TBE 算子，不以 TBE 或 ACLNN 接口为标杆。

当前候选采用原生 Rosetta EnergyMethod 与 MinimizationGraph 回调，已完成 Etable、Coulomb 几何和 resident 原子导数等组件验证。原始预算单轨迹完成诊断为 431.621 s；四条独立原预算轨迹并发完成为 449.428 s，4/4 返回成功，合计观测 RSS 峰值约 5.01 GiB。上述为开发诊断，不代表 50×35 正式性能或精度通过，亦不作为线性外推的验收证据。

### 功能分析

输入为 BD-623 结构、50 个突变配置、原始 XML、力场参数与统一主种子；输出为逐轨迹能量、逐突变 ddG 均值与标准差、官方 checker 所需结果及端到端运行摘要。所有突变与轨迹从主种子确定性派生独立 RNG 状态，不筛选离群轨迹，不换种重采。

# 详细设计（required）

## 算子分析

### 数学公式

对每条轨迹 t，结合能定义为 G_bind(X,t)=E_complex(X,t)-E_separated(X,t)，其中 X 为 WT 或 MUT。突变效应为 ddG(t)=G_bind(MUT,t)-G_bind(WT,t)，逐突变汇总 35 条轨迹的均值与样本标准差。实际四态提取、能量单位与任务规定转换沿用官方后处理，不用近似评分替代最终能量。

原生评分 E=sum_k w_k E_k。对需要求导的成对径向项，主机保持原始分支语义，设备计算径向导数，再按原始边归属和 CSR incident 顺序聚合至各原子；坐标导数通过原生接口交回 Rosetta。LJ、LK 及静电的截断、近距多项式、count-pair 和特殊类型处理与固定源码对齐。

### 支持数据类型

| 数据 | 表示与处理 |
|---|---|
| 原生坐标、标杆能量、分支判断 | 保留原生 double 语义与边界判断 |
| 设备向量计算 | 现有混合精度路径，以 CPU double 参考检查误差 |
| 未加权导数缓存与归约 | 保留现有精度补偿表示与 DD 聚合约束 |
| 行号、CSR、偏移 | 校验范围，地址与长度运算防溢出 |
| 最终输出 | 均值、标准差、能量与时间为有限值；失败显式报告 |

### 支持形状

面向任务包 50 突变及其全部独立轨迹；当前结构 420 残基、6315 原子。pair 数与 CSR 长度随构象、cutoff 和邻接图动态变化。最终评分 6 Å、最小化 9 Å 两类 cutoff 均需覆盖；8 Å 为任务协议的可移动壳层，不与评分 cutoff 混用。不涉及张量广播。

## 算子实现

### 实现方案

CPU 继续维护完整 pose、采样与 MC 接受概率、repack、最小化控制以及最终后处理。NPU 加速原生回调暴露的几何、成对评分和导数归约。先保留直接调用路径，再以含 IPC 的真实吞吐实验决定是否启用跨轨迹批处理服务，不能用设备局部加速比代替整体验收。

### host 侧设计

1. 输入校验：固定 Rosetta、XML、数据哈希及设备型号；校验突变链、位点、氨基酸、原子数量与邻接偏移。以统一 --seed 派生突变和轨迹种子，禁止针对位点硬编码挑选种子。
2. 调度：有限个工作进程执行完整独立轨迹，所有进程共同绑定 CPU 0..23。诊断先测 8/12 路，再以相同任务集合比较并发度、吞吐、尾延迟和实际内存。
3. 几何采集：复用原生邻接图、冻结的 Coulomb 列表和稳定 pair slot，保留 per-edge 能量方法 ownership；不裁剪协议要求的完整评分上下文。
4. 按需导数：score-only 请求只更新能量并清除受影响 pair 的 force-valid；真实导数请求补齐相同坐标/参数代次的导数。未完成的 force 缓存不能读取。
5. 内存：使用三角 pair 索引替代方阵元数据，按有效行分块搬运；容量复用，但拓扑、参数、类型或 mode 变化必须显式重建。空包与短包清除旧 slot 尾部。
6. 输出：保存逐任务身份、种子、返回码、版本与完整结果；后处理严格使用全部有效独立样本。未完成任务不得计入 nstruct_done，不以零值或旧结果填补。

#### 分核策略

CPU 工作与服务端调度共享 24 核总预算，不额外占用核数。设备按有效 pair 行或 CSR 原子范围划分连续区间，处理不均匀尾块；核数与 tile 参数结合实际平台能力和输入规模选择，避免小请求满核造成开销。

#### 数据分块和内存优化策略

固定类型系数与稳定描述符驻留设备，构象变化时上传坐标和 dirty ranges。按照 UB 容量、临时数组及 buffer 数量决定 tile 大小，尾块单独屏蔽越界。禁止跨轨迹共享可变坐标、已加权梯度与最终输出。设备内存、主机私有内存与 cgroup 总内存分别记录，RSS 合计仅作辅助指标。

#### tilingkey 规划策略

按 energy-only、force 与 resident aggregation 模式分派；cutoff、参数与布局版本参与兼容性校验，不把不同模式的未完成缓存互用。当前实现为应用内 C ABI/ACL 直调，不虚构 ACLNN 注册接口；若集成仓后续要求标准 tiling 注册，则按仓接口规范映射相同模式。

### kernel 侧设计

执行 Init、CopyIn、Compute、CopyOut 流程。几何阶段根据主机原生分支标识及坐标产生距离相关输入；评分阶段执行 LJ 吸引/排斥、LK 溶剂化及现有静电实现；导数阶段输出未加权导数，并保留原方法的边归属。resident 聚合按当前 score weights 计算各原子贡献并输出原生需要的导数表示。

保持 6 Å 和 9 Å 的原始分支、cutoff、氢类型及 count-pair 规则，非激活分支不得传播无效参数的 NaN。changed pair 的 energy/force 有独立有效位，防止 score-only 调用留下过期梯度。精度补偿与 CSR 顺序不得为了性能直接删除。

### 跨轨迹批处理候选设计

现有布局组件已检查冷拼包、坐标刷新与 resident dirty 更新；原生多进程服务尚待实现。服务只合并兼容计算请求，不合并轨迹状态。

拟采用 client_id、client_generation、request_id、topology_epoch、parameter_epoch、coordinate_epoch、weight_epoch 标识请求，校验 counts、offsets、payload_bytes 和 ownership_masks。每客户端初期只允许一个在途同步请求，服务不等待同一客户端的多个依赖请求来凑批。队列设置字节数和请求数上限，按批量规模或等待期限提交。

每客户端持有独立 pair/CSR/权重缓存，重连后更换 generation 并重建，旧响应丢弃。后端 distinct type columns 上限 640，超限拆批或显式失败。先用复制型 IPC 测净收益，再决定共享内存；单 stream 起步，完整调用吞吐优于直接路径才扩大并发。

### 数据检测和异常处理

无效范围、参数变化、部分更新失败使缓存计划失效，重建后再提交。进程退出、OOM、设备错误、超时或非有限结果使本次 attempt 失败，保存输入身份与日志；不透明重放成功结果，不筛选离群值或换种重采。缺乏可靠原生 checkpoint 时，从该轨迹起点恢复，并保证重试不重复计入统计。

## 性能优化验证顺序

先测并发容量和 CPU 阶段 profile，分离 backrub、scoring、packing、minimization、几何采集、设备提交与等待。仅优化实测热点；IPC 原型在含复制、排队和归约的实际吞吐有净收益后接入原生协议。最后冻结实现执行完整验收，避免组件微基准收益掩盖剩余 CPU 工作。
