### 问题分析

三个公开 BLAS 接口仅更新 `uplo` 指定三角，另一三角及 leading-dimension padding 必须零写。仅比较浮点数相等不足以证明未修改：对旧值加零或整块读改写可能改变负零、subnormal 或 NaN payload。开发复现中，Csyr2 LOWER 的原子加零前缀触及非操作区，Cherk 部分整块输出路径同样违反写回范围。

原仓部分测试还存在容差私自放宽、参考累积精度与极值行为问题；应保留原始结果，建立可追溯的严格验证链，而不能通过放宽阈值消除失败。

## 详细设计（required）

### 算子数学与接口

沿用 `include/cann_ops_blas.h` 的 `aclblasCsyr2`、`aclblasCher2k`、`aclblasCherk` 签名及枚举值。

- Csyr2：`A += alpha*x*y^T + alpha*y*x^T`，不做共轭。
- Cher2k：N模式 `C = alpha*A*B^H + conj(alpha)*B*A^H + beta*C`；C模式相应为 `A^H*B` 与 `B^H*A`。
- Cherk：N模式 `C = alpha*A*A^H + beta*C`，C模式 `C = alpha*A^H*A + beta*C`；alpha/beta为实标量。
- Hermitian 运算只发布所选三角，并强制有效计算路径的对角虚部为零；合法 quick return 保持原始全缓冲字节。

### Host 侧

保留参数检查顺序与动态核数策略。对已存在的微小矩阵专用向量路径，仅在满足原本形状、布局和语义条件时启用；长K和一般分块路径不通过扩大标量回退范围来绕过规范。标量位于Device时延续既有解析逻辑，不在Host读取矩阵后计算输出。

R36 按评审意见撤回 Cherk 不可达的 tiny 路径启用配置：n≤256、k>0 已由既有 precision 路径处理，不保留误导性的重复选择分支。有效计算路径与公开接口保持一致。

### Kernel 写回边界

1. 将每列写回区间与所选三角求交，非操作区间不发出store。
2. UB→GM DMA源要求对齐。LOWER首个非对齐操作片段通过向量Gather移入对齐UB暂存，然后仅写该片段；之后发布对齐后缀。
3. Csyr2使用独立64B UB TBuf，来自已有padding预留，避免与跨列仍存活的X/Y暂存别名。原先共享暂存方案在开发诊断中产生回归，已被独立暂存替代并保留失败日志。
4. Cherk/Cher2k复用该次输出后不再使用的旧C UB区作首片段暂存，不通过整块恢复另一三角来声称零写。
5. 每次复用暂存前显式保证MTE3已完成；性能优化必须保留这一依赖，不能删除必要屏障冒险通过基准。
6. 继续审计所有 direct/tile/partial/planar、小矩阵及quick-return分支，逐条确认GM写回范围。无新增Device全矩阵保护备份或持久缓存。
7. R32 的 LOWER 批处理直接传入已知列与行差，避免逐列 64 位除法/取模；每列边界仍独立裁剪。
8. 在 mask 容量与前缀范围满足条件时，复用已有 256B mask，对互不重叠的 UB 列依次 GatherMask compaction。mask 复用间保留向量屏障，全部 compaction 完成后共用一次 V→MTE3 屏障，再逐列只写所选三角。容量不满足时继续走原安全路径，不按性能 case 名分支。
9. 所有 TPipe 均为 kernel 入口局部对象，通过指针传给辅助类，不作为对象成员；核数来自实际设备能力。

### 数值修复

- 小 N 向量路径（n≤256）使用二进制范围缩放、乘积残差与补偿加和；较大矩阵继续使用原 Cube 路径，不扩大标量矩阵计算回退。
- 每次调用仅在既有 workspace 存放 `64*min(n,AIV核数)` 字节范围归约元数据；不备份完整 C、不跨调用缓存结果、不在 CPU 计算输出。
- Cherk 非有限路径遵循冻结Netlib的运算次序：N模式逐K项缩放相应复分量，包含零交叉项；C模式保留规约后的缩放和非对角零交叉项。避免规约结束才粗粒度传播NaN而污染同一行的其他有限元素；对角虚部和原始NaN/Inf分类严格检查。有限补偿和较大矩阵Cube路径不因此扩大回退范围。
- R26 定位并修复 dav-c220 的按位 And 计数问题：改用 uint16 视图与双倍元素计数，显式向量屏障保证全部浮点位段处理完毕，保留修复前失败日志。
- 统一主参考采用冻结Netlib BLAS3.10 complex128 cblas_zher2k/zherk，再转回complex64；适用于全部Cher2k/Cherk数值用例，保持原FLOAT32容差、99%匹配率和动态32ULP硬上限。该解释依据任务书引用的高精度参考要求，但参考精度关系尚未获发布方确认，作为公开假设披露，不按case择优。原FP32失败对照保留为历史，未改标通过。

## 可维可测分析

### 两层验证

调用前真实D2H快照确认Device输入与Host原始字节一致。调用后：

1. 使用原始位模式保护非操作区、padding和quick-return，注入±0、不同NaN payload、subnormal、Inf和有限伪随机值；额外验证器反例防止零测试/恒通过。
2. 所选三角按实/虚分别执行混合容差；最大绝对误差点决定ULP锚点，保留NaN/Inf类别检查与真实匹配率。

参考链明确区分：默认全部Cher2k/Cherk使用统一complex128主参考，原FLOAT32判定参数不变；可选 `TRIANGULAR_GOLDEN_PRECISION=fp32_crosscheck` 仅用于交叉对照。Csyr2沿用其参考。R36双硬件和R38 A3完整原FP32结果保留；R40未重跑全量可选FP32，不能将历史或未运行项目写为本HEAD通过。

新增非CSV方法 FrozenNetlibNonfiniteClassification，在每代实际执行180组：n=2/3/32，U/L、N/C，Inf/0、0/Inf、Inf/Inf、NaN/0及有限模式，分别置于全部元素、首元素和次元素。每组都有实/虚混合容差与独立bit保护记录，包含同一行混合有限/Inf的回归，防止仅均匀Inf输入通过而遗漏跨K污染。

执行前显式设置 `LD_LIBRARY_PATH="$NETLIB_ROOT/lib:$BUILD_DIR:$LD_LIBRARY_PATH"`，并逐个程序验证 `libcblas.so.3` 与间接依赖 `libblas.so.3` 均指向冻结的 Netlib 3.10.0 目录。只固定 CBLAS 链接路径不足以证明其间接 BLAS 来源。11月1日发现历史 Cher2k 间接加载系统 BLAS 后，旧数据与身份已完整隔离归档，撤销其冻结参考身份结论；R36已重跑受影响Cher2k；R40两代再从最终HEAD独立构建、重新执行全部必需阶段，不复用旧HEAD成功缓存。

R36 新增默认 CSV 清单门禁：非空、唯一非空 ID，以及按实际默认文件逐前缀核对准确条数；三套 smoke/full 共六项检查均实际执行。Csyr2 默认文件采用已保存 diff 的官方修正版，共1222条；Cher2k/Cherk 默认 smoke 各50条数据，full 分别1214/1200条，均与外部完整官方1224条集合分别验证，不把表头计作数据、不以默认小集合代替官方全量。
