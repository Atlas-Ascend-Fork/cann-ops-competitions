# 需求背景（required）

## 需求来源

依据原始《行列双向INT8量化算子任务书》的功能、ACLNN 工程化、精度、性能、内存及工程测试要求实现。原始公开任务包包含 27 个精度输入，其中 5 个兼用于性能和内存验证；另规定 12 个额外种子/存储偏移输入和 13 个非法输入/属性场景。

代码仅在一个功能分支集中交付。主仓调用接口为工程目录同级的 `row_col_int8_quant.cpp`；公共声明位于 `xllm_ops_api.h`，由同级 CMake 源文件列表纳入编译。完整独立算子工程包含内核、Host 注册/推导/tiling、构建安装、两阶段 ACLNN、独立 C++ 样例、PyTorch NPU 封装和 Kernel 直调。

## 背景介绍

通用 FP32 Abs/ReduceMax/Round/Cast 组合需要多个框架算子及完整 FP32 中间张量。两次 DynamicQuant 的方案还需要转置与独立 absmax 计算。本文针对稠密有限 FP16 输入，以局部统计工作区和分块重复读取输入，避免完整 FP32 矩阵及全矩阵转置工作区，并减少正式 ACLNN 入口的设备提交次数。

不包含 threshold、COO 异常值输出、稀疏路径、反向、NaN/Inf 处理或其他 dtype 扩展，不为未要求的硬件代际声明支持。

# 需求分析（required）

## 输入输出与约束

| 名称 | 形状 | dtype | 约束 |
|---|---|---|---|
| `x` | `[M,N]` | FP16 | 选定 NPU 上物理 ND、逻辑连续、有限值；`1 <= M <= 4096`，偶数 `2 <= N <= 4096` |
| `qRow` | `[M,N]` | INT8 | 按整行 absmax 量化，范围 `[-127,127]` |
| `qCol` | `[M,N]` | INT8 | 按整列 absmax 量化；仍为 `[M,N]` 行主序，不返回转置视图 |
| `rowAbsmax` | `[M]` | FP32 | 行绝对最大值，不是反量化 scale |
| `colAbsmax` | `[N]` | FP32 | 列绝对最大值，不是反量化 scale |

属性为空字典。拒绝未知属性、非法属性容器、输入个数错误、CPU/BF16/FP32 输入、错误维数、非连续、尺寸越界和奇数 N。物理非 ND 张量也不得仅凭逻辑连续性误传为 ND。

四个输出位于同一 NPU，均连续，底层存储相互独立且不与输入共享。输入位模式不变。计算和数据搬运均在 NPU，Host 只读取元数据，不进行 CPU 代算。

## 需求拆解

1. 生成逐位正确的行列 absmax，并实现指定的 FP32 因子、FP32 乘积、最近偶数舍入和裁剪。
2. 以完整 ACLNN 工程提供注册、推导、tiling、用户目录安装包和两阶段 API。
3. 提供 `run`、`prepare` 和 `run_direct`，保持当前设备/stream 语义、存储独立性及异步生命周期安全。
4. 限制 workspace 与活跃分配峰值，不建立完整 FP32 矩阵或全矩阵转置中间结果。
5. 执行全部公开与扩展输入、非法场景、双流、压力、重复调用、性能和内存检查，保存逐项真实记录。

# 详细设计（required）

## 数学定义与数值处理

```text
r[i] = max_j(abs(x[i,j]))
c[j] = max_i(abs(x[i,j]))
qRow[i,j] = clip(rint(fp32(x[i,j]) * fp32(127 / r[i])), -127, 127)
qCol[i,j] = clip(rint(fp32(x[i,j]) * fp32(127 / c[j])), -127, 127)
```

统计量为零时，对应轴的量化结果必须为零。`rint` 采用最近偶数舍入。

有限 FP16 转 FP32 无精度损失，绝对值和最大值统计精确；UB 的正零补齐使正负零输入的 absmax 统一为正零。将零分母替换成 FP16 最小正数，仅用于避免除零；该轴输入全部为零，因此量化乘积和输出仍为零，不改变非零统计量。

量化使用 FP32 因子与乘积，裁剪后通过 FP32 到 INT32 的 `CAST_RINT` 实现最近偶数舍入，再经 FP16 转 INT8；范围内整数的中间转换精确。显式设置 `DEQSCALE` 为 FP16 的 1，避免 FP16 到 INT8 指令消费遗留缩放寄存器状态。

向量除法与 CPU 除法可能在舍入边界附近不同，因此严格使用任务验证器规则：absmax 逐位一致，常规 INT8 逐元素一致，仅在 CPU FP32 量化前值距半整数不超过 `2e-5` 时允许相差 1，并记录元素数；全零和精确中点用例完全一致。不得全局使用 ±1 容差。

## Host 与 tiling 设计

固定 tile 为 64 行、256 列：

```text
rowTiles = ceil(M / 64)
colTiles = ceil(N / 256)
tileCount = rowTiles * colTiles
```

最多使用目标设备的 48 个 AIV 核，tile 按核编号循环分配。Host 传递 M、N、行列 tile 数和 block 数，不扫描输入值。稠密 FP16 ND 路径不按 dtype 或广播引入额外 tiling 分支。

尾块以有效行列范围控制输入和输出搬运，统计时对无效区域补零。即使 M 为 1、N 为 2 或维度恰跨 tile 边界，也使用相同地址推导。

## Kernel 三阶段设计

1. **局部统计**：每个 tile 搬入有效 FP16 子矩阵，正零填充 UB，转 FP32 后取绝对值。块内和 repeat 归约得到 64 个局部行最大值，行方向树形归约得到 256 个局部列最大值。
2. **全轴统计**：跨列 tile 合并行统计，跨行 tile 合并列统计。使用带 stride 的 DMA 聚集局部结果，再在补零到 2 的幂的 UB 数组上归约，写出最终 FP32 absmax。
3. **量化输出**：再次读取原 FP16 tile，分别广播行因子与列因子，计算、舍入、裁剪并批量写出两个 INT8 矩阵。

ACLNN 内核将三阶段放在一次设备 launch 中，以两次硬件 `SyncAll` 保证阶段之间的跨核可见性。Kernel 直调复用三个阶段主体，在当前 stream 顺序提交三次 launch，不依赖 ACLNN 的跨核启动元数据。

核内用显式流水事件约束 vector 清零、DMA 输入、vector 读取和输出 DMA；缓冲仅在前一消费者完成后复用。除两次跨核同步外，不以 Host 同步实现算法阶段依赖。

## 地址推导与工作区

对于 tile `(tr,tc)` 中的有效坐标 `(i,j)`：

```text
matrixOffset = (tr * 64 + i) * N + tc * 256 + j
tileIndex = tr * colTiles + tc
partialBase = tileIndex * 320
columnPartialOffset = partialBase + j
rowPartialOffset = partialBase + 256 + i
```

统计工作区为 FP32，单 tile 保存 256 列和 64 行共 320 个值。地址计算与搬运边界保证尾块不访问有效存储范围之外的数据。

```text
userWorkspaceBytes = 4 * ceil(M/64) * ceil(N/256) * (64+256)
workspaceBoundBytes = 16 MiB + userWorkspaceBytes
outputBytes = 2*M*N + 4*M + 4*N
activePeakDeltaBound = outputBytes + workspaceBoundBytes + 16 KiB
```

16 MiB 是 CANN 同步系统工作区，也计入验收上限。直调采用相同工作区布局与统计区偏移。最大形状的 tile 数为 1024，用户统计区为 1,310,720 字节，总工作区上限为 18,087,936 字节。没有 atomics、完整 FP32 输入副本或全矩阵转置工作区。

## 片上缓冲预算

| 缓冲用途 | 容量 |
|---|---:|
| FP16 输入/转换暂存 | 32 KiB |
| FP32 数值 | 64 KiB |
| FP32 归约/计算 scratch | 64 KiB |
| 因子/广播 scratch | 8 KiB |
| INT8 输出 | 16 KiB |
| 合计 | 184 KiB |

目标 UB 为 192 KiB。FP16 转换暂存仅在数值转入独立 FP32 缓冲后复用，输出缓冲复用前等待 DMA 消费完成，不把不同阶段的存活区域错误重叠。

## 接口、分配与生命周期

注册 `RowColInt8Quant`，提供两阶段 `aclnnRowColInt8QuantGetWorkspaceSize` / `aclnnRowColInt8Quant`。私有 `.run` 安装包默认位于用户安装前缀，不覆盖系统 CANN；安装后的生成头文件和独立 C++ 样例给出完整 API 调用方法。

安装脚本读取构建目录 `CPackConfig.cmake` 的实际包名，再安装到用户前缀，不写死 Ubuntu 包名，也不从多个旧 `.run` 中猜测选择。缺失配置、缺失指定产物或安装失败均返回错误。CPU 回归覆盖 Ubuntu、openEuler 和自定义包名、路径含空格、旧 Ubuntu 包残留和安装器失败；这些是包名选择回归，不替代指定 openEuler 镜像的真实构建验证。

```python
outputs = solution.run([x], {})
call = solution.prepare([x], {})
outputs = call()
outputs = solution.run_direct([x], {})
```

框架边界检查元数据，使用恢复式设备 guard 和当前 PyTorch NPU stream。每次调用分配新的四个输出和临时工作区，prepared 调用也不复用输出。prepared 对象持有输入引用；普通异步调用额外向消费 stream 记录输入存储，防止输入由其他 stream 分配并提前释放时被过早回收。

绑定通过已注册的 NPU storage factory 和缓存分配器创建 ND 张量，保持活跃分配统计与 stream 关联，避免额外的空张量算子调度。最多缓存 64 个线程局部 ACLNN 执行计划，key 包含 shape、逻辑设备和 stream；每次重绑输入输出地址，不缓存输出或 workspace，描述符不拥有张量存储。

内存复现条件包含 `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`。默认缓存分配器曾复用过大的空闲块，导致同样请求下活跃分配峰值超限；本配置由项目环境脚本设置，不修改其他任务的全局环境。
