# 需求背景（required）

## 需求来源

CANN 社区任务 2026 · `9月社区任务-单精度实数Cholesky分解、求解和批量接口(950)`（任务书位于 `04_tasks/01_community-task-2026/tasklist/` 下同名目录）。

## 背景介绍

### 算子实现

本任务在 **Ascend 950PR（dav-3510）** 上以 **Ascend C / catlass** 从零实现实数单精度 Cholesky 的分解/求解/求逆及批量接口，共 5 个接口**一并交付、不允许拆分验收**，对标 cuSOLVER `potrf/potrs/potri` 参考耗时（任务书 §3.3 门禁 P-01~P-12）：

| 接口 | 功能 |
|---|---|
| `aclsolverSpotrf` | 分解 A = L·Lᵀ（或 A = Uᵀ·U） |
| `aclsolverSpotrs` | 三角求解 A·X = B |
| `aclsolverSpotri` | 求逆 A⁻¹ |
| `aclsolverSpotrfBatched` | 批量分解（A 为设备端指针数组） |
| `aclsolverSpotrsBatched` | 批量求解 |

### 关键约束（决定架构选型）

| 参数 | 含义 | 约束 |
|---|---|---|
| `uplo` | LOWER / UPPER | 只读一侧，互为空 |
| `n` | 矩阵阶 | 分解原地覆盖输入缓冲 |
| `A(array)` | 批量时为**设备端指针数组** | `lda ≥ n` |
| `info` | 第 k 阶顺序主子式非正定指示 | 逐矩阵独立，不中断其它矩阵 |
| `batchSize` | 矩阵个数 | P-10 达 46256 |

1. 调用方缓冲为**列主序**（`lda` 由调用方给定），且批量时矩阵地址由设备端指针数组给出——"矩阵在设备上不保证规整排布"，依赖"基址 + 固定步长"的批量核必须先用一次 D2H 拷贝校验规整性，不规整则回落逐矩阵路径；
2. catlass 批量核（`BatchedMatmulTla`）把每矩阵步长写死为 `strideA=m·k / strideB=k·n / strideC=m·n`，而本任务需要 C 直接落在调用方列主序缓冲（步长 `n·lda`）⇒ 用**只覆盖 `ToUnderlyingArguments` 的内核包装**提供运行期覆盖（不改公共仓；曾误判"fixpipe 不能写带行距 C"，真因即此处）；
3. 分解逐列串行（主元依赖上一列的更新），AIV 侧只能做"列式向量更新"，尾随的大块更新交给 Cube。

# 需求分析（required）

## 需求描述

以 Ascend C 实现上述 5 个接口：`float32`、LOWER/UPPER、`lda ≥ n`、任意 batch；精度满足任务书判据（逐元素 `rtol=atol=2^-13` + DPOT01 残差兜底）；性能满足 P-01~P-12 门禁 `T_NPU ≤ T_GPU/0.35`。

## 需求拆解

1. 单矩阵分解：向量核（AIV only）+ 分块面板核（AIV）+ Cube 尾随更新；
2. 求解/求逆：以分解因子为输入的三角求解与求逆，复用分解产物；
3. 批量分解：面板 → Cube 尾随更新 → A22 更新三段流水，按 batch 切块在独立 stream 上流水；
4. 精度：任务包 `verify_accuracy.py` 全量判定通过（含批量 A0 抽样与 info 契约）；
5. 性能：12 项门禁全部达标（P-10 为重点）。

# 详细设计（required）

## 算子分析

### 数学公式

- 分解：`A = L·Lᵀ`（LOWER）或 `A = Uᵀ·U`（UPPER）；Schur 补 `A22 ← A22 − L21·L21ᵀ`
- 求解：`L·Y = B` 前代，`Lᵀ·X = Y` 回代
- 求逆：`A⁻¹ = L⁻ᵀ·L⁻¹`

### 支持数据类型 / 支持形状

`float32`；LOWER/UPPER；`n × n`，批量 `batchSize` 个（n=16…4096，门禁覆盖 32/128/1024/2048/4096）。

## 算子实现

### 实现方案

#### 3.2.1 host 侧设计

1. **分核**：优先满核——批量按 `min(AIV 核数, batchSize)` 投放 block，核内 grid-stride 领矩阵；`n==32` 的 SIMT 形态按 `ceil(batch/512)×2` 过度投放（实测更优）。
2. **路径门控**：分块（面板+Cube）路径**只在 `n==128 && uplo==LOWER && lda==n` 启用**（即 P-10 形状），其余形状走向量核/逐矩阵路径——面板核以"列级向量 op + 列级 V→S 同步"为代价，只在 batch 极大、单矩阵工作量可被 Cube 摊掉时划算；该门控同时保证 P-01~P-09/P-11/P-12 的代码路径完全不受影响。
3. **跨矩阵块流水（默认 `CHUNKS=4`）**：batch 均分 N 块、各块在独立 stream 跑完整三段，wall 由"两段之和"变为"两段之 max"；数值与单流逐位一致（同矩阵内运算与顺序不变）。
4. **tiling 关键参数**：面板宽 `kn`（默认 8）、内层块宽 `blk`（默认 0=逐列）、L21 单条 2D DataCopy 打包、组内元数据批量搬入；均可由环境变量覆盖以便现场调优。
5. **缓冲布局**：每矩阵一段（段长取该面板最大者）；左看为**紧凑 scratch（`kn × m_max`，比右看 `l21Pack` 小 5×）**；规整性由一次 D2H 拷贝判定，不规整回落旧路径。

#### 3.2.2 kernel 侧设计

1. **三段流水**（同 stream 顺序发射，天然成栅栏，无需 MIX/跨核旗语）：
   ① 面板核（AIV）：列循环 `j∈[0,kn)`：主元 → 整列缩放 → 预热 → 列内 rank-1 更新；同时写回 L11/L21 并打包/写 scratch 供 Cube；
   ② Cube 批量 GEMM：右看 `S = L21·L21ᵀ` 直写并原子累加进调用方 A22；左看 `S = Σ_{t<kk} L[·][t]·L[·][t]ᵀ`（只更新"块列"，K=kk）；
   ③ A22 更新：右看由 fixpipe 的 `SetAtomicAdd` 在 TileCopy 层完成；左看由面板核在 CopyIn 后一条连续 `Sub` 完成（作用区恰为面板要读的 m×kn）。
2. **Cube 出核布局（关键设计）**：新增只覆盖 `ToUnderlyingArguments` 的内核包装，把三个每矩阵步长改为运行期可传——C 走"列主序 `MakeStride(lda, Int<1>)`"（调用方 A22 的真实布局），由 fixpipe 以 `SetAtomicAdd<float>()`（原子层取 TileCopy，`BatchedMatmulTla` 不调用 epilogue）直接累加。探针实测：该写法在 `M=8/ldc=64`（历史判死配置）与 `M=112/ldc=128`（生产真实形状）上**逐元素正确**；此前"地址步进缺陷"结论是批量核 `strideC` 写死所致，非写通路问题。
3. **左看表述（默认）**：每面板只更新"块列"（m×kn），历史贡献用一次 `K=kk` 的 GEMM 求和，尾随流量由 `Σm²` 降至 `≈n²/2`（kn=16 时 3.9×）；操作数直读调用方 A（免打包缓冲），C 落紧凑 scratch（行主序 ld=m，fixpipe 最廉路径），无需原子/取负。
4. **同步与写回纪律**（实测教训固化进代码注释）：
   - 同一 UB 缓冲的跨流水共享必须双向栅栏：`SyncVtoMte3()` 须放在向量写**之后**，否则打包/搬出读到旧值；
   - **"值等价"≠"可去栅栏"**：曾删掉一条服务于"值冗余 SetValue"的 V→S 栅栏，小 batch 全过但 P-10 形状用例 4/5 抽样矩阵数值 FAIL（该栅栏真正保护的是「预热缓冲 colj(V 写) → 系数标量读(S 读)」）⇒ 已回退；
   - 可省的是**值冗余且代价昂贵**的标量操作：删每 (列×矩阵) 一次的 `SetValue`（栅栏保留）+ 预热拷贝从 `m−a8` 收到 `kn−a8`，合计 ~4 ms，是最后跨过 P-10 门禁的一步。

### 支持硬件

| 支持的芯片版本 | 涉及勾选 |
| --- | --- |
| Ascend 950PR（Atlas 950，dav-3510） | √ |

> MIX 形态（`KERNEL_TASK_TYPE_MIX_AIC_1_2`）在融合实验中被实测否决（175 ms vs 交付 28.7 ms），未进默认路径。

### 算子约束限制

1. 输入须对称正定；非正定时该矩阵 `info` 置首个非正定阶数并停止该矩阵（不中断其它矩阵）；
2. `lda ≥ max(1,n)`；批量接口 `A` 为设备端指针数组；
3. 批量分块（面板+Cube）路径仅对 `n==128 && LOWER && lda==n` 启用，其余形状走向量/逐矩阵路径；
4. 就地覆盖：分解结果写回输入缓冲。
