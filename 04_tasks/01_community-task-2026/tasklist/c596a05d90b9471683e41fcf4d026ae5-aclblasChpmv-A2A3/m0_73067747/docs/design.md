# aclblasChpmv（Atlas A2/A3）算子设计

## 需求背景

本题为 2026 年 11 月昇腾社区任务。在 ops-blas 的 arch22 产品线上提供 cuBLAS Chpmv 对应的句柄式 BLAS 接口。开发基线为 ops-blas/master 的 55ef791b77f3677b45da3468b0a8b17941424f84。该版本已包含 11 月 23 日进入仓库的两阶段内核。本设计复用已有工程和向量内核，并针对本批次的接口契约、用例及性能门槛开发和验证改动。性能优化的选用依据为逐例真机记录。

## 需求分析

函数原型沿用 include/cann_ops_blas.h。输入为 handle、uplo、n、alpha、AP、x、incx、beta、y、incy，输出写回 y 的原有存储。所有复数均为相邻的两个 float32，标量地址可以分别位于 Host 或 Device。矩阵按列压缩存储，共 n(n+1)/2 个复数。调用方保证输出与 AP、x 的可访问区域互不重叠。仅对逻辑步长位置写回，保留 y 中的间隙。

目标设备为 Atlas A2/A3；选用 910B3 自验。运行时接受 n≥0，两条步长均可为任意非零 int。不要求广播和视图输出。

## 详细设计

### 算子分析

对行 i 求 s(i) = Σ A(i,j)x(j)，再写入 y(i) = alpha·s(i) + beta·y(i)。上三角存储部分的偏移为 i+j(j+1)/2，下三角存储部分为 i+j(2n-j-1)/2。对未存储的元素，交换 i、j 并取共轭。主对角只用实部。负步长时，第 k 个逻辑元素位于 (n−1−k)·abs(inc)；先扩展至 64 位再求绝对值及乘积。

### Host 与 Tiling

校验顺序依次为 handle、负 n、uplo、步长、两个标量指针。随后 n=0 直接成功；n>0 时继续校验 AP/x/y，再判断标量值。非法枚举返回 INVALID_ENUM，空句柄返回 HANDLE_IS_NULLPTR，其余参数错误返回 INVALID_VALUE。读取 Device 标量时，当前候选使用仓内 ReadScalarFromHostOrDevice，经 handle 的 stream 获取数据；该读取包含同步，后续计算在同一 stream 上异步下发。

alpha=0 且 beta=1 时直接返回。alpha=0 的其他情况只启动缩放内核。一般路径依据 n、AIV 核数和有效 workspace 选择累加核数。每核保留两个长度为向上对齐至 8 的 n 的 float32 部分和数组。workspace 的单核占用为 8×align_up(n,8) 字节。输出归约核数受设备核数及输出分块数限制。Host 检查空间并传递启动错误。

### Kernel 与数据搬运

上游向量路径按压缩矩阵的列和输出行块组织计算。复用同一存储元素计算三角内及镜像位置的贡献。每个累加核写入独立工作区，在同一 stream 上启动第二个内核，按输出行归约各核结果、应用 alpha 和 beta 并写回。行块最多 1024 个复数；最后一块使用实际剩余长度。搬入 UB 后分离实虚数据，单位步长走连续搬运，非单位步长依据窗口大小采用跨步采样。beta=0 分支须直接覆盖逻辑输出，避免旧值中的 NaN 污染结果。

提交 c2c3049a 按矩阵阶数、向量核数及步长选择下列实现。表中核数均指 AIV。

| 阶数 | 每核工作与存储 | 边界与精度处理 |
|---|---|---|
| 1–16 | 每核计算独立输出行，按有效字节数写回一个复数。 | 读取已存储的三角和共轭镜像，忽略对角虚部。 |
| 17–128 | 在 UB 缓存整个压缩矩阵和输入向量，按行 Gather 实部与虚部，再作乘法和归约。 | beta 为零时跳过读取 y。计算出现非有限结果时按 Netlib 运算顺序重算该行。 |
| 129–256 且至少有 32 个核 | 一次 kernel 启动。分两次搬入压缩矩阵，同一核负责的各行先缓存第一段命中的元素，再与第二段数据合并。 | 两段各设零填充区域以处理跨段索引。符号修正、对角线处理和回写沿用按行计算逻辑。其余核数采用下一行的两阶段路径。 |
| 至多 4095 阶且未命中前述路径 | 第一阶段按列计算每核部分和。单位步长、至多 640 阶且至少 32 核时，先将本核负责的压缩列搬入 UB，再从同一缓冲读取对角元素和非对角向量。多行块单位步长路径将 x 缓存在 UB，跳过与行块无交集的列。第二阶段以一次跨步 DMA 取回各核对应的实、虚平面，在 UB 中按原核顺序归约。跨步输入的物理跨度能装入 8192 个复数的窗口时连续搬入，再抽取逻辑元素。更长跨度按步长搬运。 | 输出连续时以每 64 行估算归约核数，跨步时以每 24 行估算，上限为设备核数。性能计时包含累加和归约两个 kernel。 |
| 4096 及以上 | 以 16 行为分配单位，在各核间均分输出行，每核按至多 256 行分块。直接区和镜像区分开搬运，在 UB 中分别保留直接和、镜像和。按至多 64 行划分对角子块。对角子块按列预存基址；直接三角区域以向量加法加上当前行偏移，共轭区域用掩码覆盖索引并设置虚部符号。每行沿用原有浮点乘加与归约顺序。 | 逻辑贡献按分段顺序累加，控制长行的 FP32 舍入误差。跨步 x 在可用工作区足够时先打包为连续向量，性能计时同时包含打包和计算。工作区不足时由行内核直接读取跨步输入。 |

每个尾块都依据实际剩余行列数限制访问。910B3 上已将实现结果与固定输入的 Netlib golden 比对，1000 个官方精度用例全部通过，另 200 个性能形状的实部、虚部各自通过。性能结论以固定提交的逐点 msprof 记录和独立复测为准。

## 可维可测分析

复用 ops-blas 的 GTest 框架加载原始 1200 条 CSV。精度的 1000 条用例在相同输入上调用 Netlib 3.10.0 cblas_chpmv，按实部和虚部分别输出逐例结果。校验 NaN、Inf、主对角虚部、负步长、用户输出间隙、零阶叠加非法结构参数，以及 Host/Device 标量混合位置。比较器要求非有限值逐元素同类，两个无穷大还须同号。负对照覆盖实测结果扰动、NaN 替换无穷、无穷符号相反及有限值替换无穷。

性能的 200 个用例已按 n、uplo、incx、incy 与 gpu_baseline.csv 顺序逐条核对。每例在预置缓冲上预热 5 次，接着记录连续 10 次有效调用。正式结果按 msprof 的 Task Duration 对单次 BLAS 调用内的所有 kernel 求和，再对 10 次取算术平均。每例独立比较 1250×gpu_ms（µs）；事件耗时只用于交叉验证。零样本或缺少阶段时，该点为未验证。最终报告关联固定 commit、原始采样、用例数及逐例门槛。
