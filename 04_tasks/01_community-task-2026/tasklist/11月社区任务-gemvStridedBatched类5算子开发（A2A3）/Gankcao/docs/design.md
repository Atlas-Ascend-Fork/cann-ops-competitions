# 需求背景

本设计对应 2026 年 11 月 gemvStridedBatched 类五算子社区任务（Atlas A2/A3），采用 11 月 24 日修订的列主序约定。上游 ops-blas 提交 `6df9aa04a1d37288966e1b97a20ae8033ca2ce3c` 已有 arch22 五个入口、共享向量核和测试工程。本次在该实现上对齐修订后的参数校验、步长、混合精度与批处理性能，公共 API 沿用 `include/cann_ops_blas.h`。

# 需求分析

对每一批 b 计算 `y_b ← α op(A_b) x_b + β y_b`。矩阵按列主序占用 lda×n 个元素，N/T/C 都要求 lda≥max(1,m)。N 时 x/y 长度分别为 n/m，T 和 C 时为 m/n。批间偏移以各自数据类型的元素为单位。

| 接口前缀 | A、x | y | 运算和 α、β |
| --- | --- | --- | --- |
| S | FP32 | FP32 | FP32 |
| HSH | FP16 | FP16 | FP32 |
| HSS | FP16 | FP32 | FP32 |
| TST | BF16 | BF16 | FP32 |
| TSS | BF16 | FP32 | FP32 |

# 详细设计

Host 依次校验 handle、trans、尺寸、lda、inc、stride、批数、标量及数据指针。非法枚举返回 INVALID_ENUM，非法维度、步长和重叠批区间返回 INVALID_VALUE，空 handle 返回 HANDLE_IS_NULLPTR。合法的空输出或零批数在检查后直接返回。检查矩阵跨度 lda×n，以及向量跨度 1+(len−1)×abs(inc)，以 64 位中间值避免乘法和负步长取绝对值溢出。

内核复用 arch22 的变体分派。批首地址使用各自的 stride，负 inc 从逻辑向量尾端起步。N 路径沿行块输出以复用 x，T/C 路径沿列分配点积；按输出长度与 batchCount 检查核间利用率，小批量大矩阵优先在批内划分独立输出。每个 y 元素只由一个核写回。混合精度输入先扩为 FP32，再乘加、缩放并按目标类型舍入。α=0 走纯缩放，β=0 避开旧 y 的读取。优化分派依据尺寸、转置和步长。

# 可维可测分析

在 CANN 9.1.0、910B3 上用 GTest 加载附件五组 CSV，每组 1000 条精度与边界、200 条性能。逐批以 Netlib BLAS 3.10.0 的 cblas_sgemv 计算 golden，输入按变体量化，输出按 y 类型舍入。逐例报告混合容差匹配率（至少 99%）及最大绝对误差，同时检查返回码、零标量及 NaN/Inf 分支。

性能先预热 5 次，再取 10 次完整调用的算术平均。正式数据来自 msprof op 的 kernel replay，另记 ACL event 耗时。按完整 BLAS 参数与各变体 A100 基线配对，逐例核对 GPU/NPU≥0.8。对于修订记录注明待复测而表内已有数值的条目，报告保留来源及可验证范围。交付冻结输入和 golden、逐例结果、环境版本、复现命令及真实终端截图。
