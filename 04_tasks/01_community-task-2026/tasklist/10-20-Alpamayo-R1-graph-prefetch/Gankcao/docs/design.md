# Alpamayo-R1 图模式与预取优化开发任务书（设计计划）

提交人：Gankcao。任务：10月社区任务—Alpamayo-R1 图模式与预取优化。

本文为实施前计划，不包含已完成声明或实测成绩。实施顺序为 A2 + CANN 9.1 基线复现、优化和验证，再迁移到 A3 完成独立基线与验证；A2 阶段结果不替代 A3 验收。

# 需求背景（required）

## 1.1 需求来源

依据下发《Alpamayo-R1 图模式与预取优化(A2, A3)》和 `test_cases/README.md`。目标代码仓为 [cann/cann-recipes-embodied-ai](https://gitcode.com/cann/cann-recipes-embodied-ai)，样例目录为 `navigation/alpamayo-r1/`，技术文档为 `docs/navigation/alpamayo-r1/README.md`。开发前通过目标仓 RFC/Issue 讨论并冻结硬件、依赖、输入、评测协议及图边界；代码 PR 关联该 RFC/Issue。

## 1.2 背景及目标

现有样例在固定上游提交上应用昇腾适配 patch，已经包含融合 Attention、RMSNorm、addcmul、索引及内存分配优化。拟在该既有昇腾 eager 实现上接入稳定子图的 capture/replay，并针对 profiling 证实为 memory-bound 且存在安全依赖窗口的 MatMul 类权重热点接入预取。

目标是在不改变模型语义、权重、精度类型、输入、扩散步数、轨迹数量及 CoC 采样参数的前提下，保持输出一致，降低稳态端到端耗时。文档记录的 7.32 s 仅为历史参考；性能比较使用同一平台、同一软件版本与完整配置下重新实测的 eager 基线。

## 2.2 功能与范围

提供独立 `enable_graph`、`enable_prefetch` 开关，默认均为 false。必须覆盖 eager、graph-only、prefetch-only、graph+prefetch 四档。保留 1/3/5/10 轨迹入口及原有输出格式。不新增量化、模型并行或自定义算子。

模型私有改动拟采用 monkey patch，封装在样例 patch 中；优先限制于该样例。若确需修改公共 `module/` 或框架，列出全部直接调用样例，并对至少一个既有样例完成同平台功能、精度与代表性性能回归。

# 详细设计（required）

## 3.1 基线与热点分析

使用既有适配后的 `src/alpamayo_r1/test_inference.py` 入口复现单样本推理，单独建立固定 100 clips 的评测入口。首先记录模块级耗时、kernel 时间线、Host 提交间隙、同步、内存峰值及采样过程。数据下载、权重加载与首次编译单列，不混入稳态推理。

拟优先调查扩散/动作预测中重复执行、shape 稳定的子图；VLM 动态生成、CPU 控制流、`.item()` 和变长输入先作为图边界风险分析。候选仅为预研方向，最终捕获子图及边界以 profiling 和 RFC 共识为准，不预先宣称某个 MatMul 为 memory-bound。

## 3.2 图模式生命周期

1. 图外完成模型初始化、静态输入/输出 buffer、随机状态及可复用 workspace 准备，记录张量 shape、dtype、device、layout 与地址约束。
2. 区分 warmup、compile/capture、replay，分别记录次数、耗时和失败原因；只在冻结支持的输入签名上复用图。
3. 每个请求将新数据写入稳定地址的 buffer；replay 完成后，在 buffer 下一次复用前保存或消费输出，避免比较到已被覆盖的数据。
4. 固定随机种子与随机状态语义，检查 warmup/capture 是否消耗随机序列。需要时将随机输入在图外按原调用顺序生成；不得缓存结果、固定复用噪声或改变采样算法来取得一致性。
5. 输入签名不受支持、捕获失败或运行条件不满足时，提供可观测的 eager 回退；正式图模式成绩必须有真实 replay 证据，不能将静默回退计为图优化成功。
6. 核对各档模式原始输出、图次数与缓存命中，排除持续 graph break、逐次重编译及错误图复用。

## 3.3 预取设计

在实际软件栈支持的官方预取接口中选择实现，开发前核实 A2/A3 与 capture/replay 的支持边界，不预先绑定未经核实的 API。通过访存、计算与时间线证据识别目标权重热点，说明权重来源、大小、最后写入与首次消费之间的依赖关系。

预取位置须位于权重就绪之后、计算消费之前，存在可重叠计算窗口；不添加破坏收益的隐藏 Host/Device 同步。按模块、权重规模、合法依赖及平台能力选择策略，不按验收 clip 或输入内容特判。确认真实预取事件与调用位置、频次，并比较单独预取及组合模式的 kernel 变化与显存。

## 3.4 配置与回退

四档模式共享权重、数据、数学路径及采样配置。图缓存按支持的输入签名管理并限制生命周期，关闭开关后解除对应包装，恢复原调用路径。验证连续不同请求、轨迹数切换、关闭后重开、异常捕获及不支持输入回退，防止旧输入/旧输出残留或内存持续增长。

# 测试与验收设计（required）

## 4.1 测试矩阵

每个平台独立执行以下矩阵，不跨硬件或 CANN 版本计算优化收益：

| 类别 | 覆盖与判据 |
| --- | --- |
| 开关 | 四档组合、默认关闭、单独关闭及回退，结果符合配置 |
| 固定输入 | 固定权重、输入与 seed；三档优化的原始轨迹（位置与旋转等实际返回 Tensor）与 eager 的 shape、dtype、逐元素值一致；序列化轨迹及 CoC 文本一致 |
| 数据集 | 固定 100 clips，四档均覆盖 1/3/5/10 轨迹，保存逐 clip 原始预测和指标；不替换或筛除失败 clip |
| 精度门槛 | 10 轨迹 minADE ≤ 0.5676，且各优化档不得劣于同平台 eager；1/3/5 轨迹保留并做相对基线回归，绝对门槛适用范围在 RFC 中确认 |
| 性能 | 每档至少预热 1 次、正式运行至少 3 次；计划扩大至至少 10 次，若波动无法区分收益则继续重复；组合模式稳态端到端耗时低于 eager 且收益超过基线波动 |
| 稳定性 | 每档至少连续 20 次，无失败、内存持续增长或输出漂移；固定 seed 对照与连续请求状态测试分别记录 |
| 存储 | 开启 profile_memory 的独立 profiling 运行，记录峰值、稳态占用及连续请求趋势；报告图缓存和 workspace 额外开销 |
| 错误返回 | 精度、配置、运行或比较失败必须返回非零状态，不吞掉异常、不将无法比较记为通过 |

逐元素一致不以近似容差代替；如 eager 自身不稳定或现有算子影响复现，先隔离定位并向维护者确认，不自行豁免。

## 4.2 minADE 协议

沿用样例数据坐标、预测时域、采样时间点和轨迹匹配定义。单 clip 指标以各预测轨迹相对真实轨迹的平均位移误差最小值为基础；100 clips 的聚合、轨迹组维度、时间窗和每 clip seed 规则须对照现有评测并在 RFC 中固定，不能仅凭单 clip 脚本自行推断完整数据集协议。

自验附件对 1/3/5/10 与绝对阈值的表述需确认。本计划以主任务书明确的 10 轨迹阈值为依据，并对全部轨迹数量提供可追溯数据，不宣称其他轨迹数量已获阈值豁免。

## 4.3 测时及波动

拟采用同设备独占、相同同步边界的稳态墙钟端到端计时。建议覆盖请求数据进入推理路径后的必要拷贝、模型调用及 CoC 解码；不含一次性下载、模型加载和首次捕获。具体起止位置及序列化是否包含在内，在 RFC 固定后四档保持一致。

性能运行与带 profiler 的诊断运行分离，交错测量 eager 与优化模式，避免启动顺序、温度或其他作业影响结论。保存每次耗时及均值、中位数、分位数和离散程度；同时报告目标模块、kernel 变化和内存峰值。建议采用配对重复和收益置信区间，并对照 eager 重复组间波动确认提升；最终判定方法在 RFC 中约定，不将某个自定百分比冒充官方门槛。

# 实施安排与交付（required）

1. **方案阶段**：提交设计文档；目标仓 RFC/Issue 固定评测协议、平台版本和候选方案，完成 CLA、贡献规范及数据/权重访问准备。
2. **A2 基线阶段**：A2 + CANN 9.1 配套环境核对；完成原始适配 eager 推理、重复性、100 clips 与 profiling，保存不可覆盖的基线证据。
3. **A2 优化阶段**：先实现最小稳定子图，再依据 profiling 接入预取；完成四档功能、精度、性能、内存和稳定性验证，不同时改变多项配置掩盖归因。
4. **A3 复验阶段**：记录 A3 配置并独立复现 eager；复用同一实现验证完整矩阵，必要平台分支以能力检查实现。A3 成绩单独报告，不套用 A2 耗时或结论。
5. **交付阶段**：一个代码 PR 仅包含 Alpamayo 样例，关联 RFC/Issue；通过 `pre-commit run --all-files`、仓库 CI 及两平台实机验证后申请验收。

拟交付：图 wrapper、静态 buffer、预取与回退逻辑；环境锁定及四档配置；测试和复现入口；更新 `navigation/alpamayo-r1/README.md` 与 `docs/navigation/alpamayo-r1/README.md`；逐项自验报告及真实终端/profiler 截图。

报告记录源码提交、环境与硬件、权重/数据/输入哈希、完整命令、首次编译和逐次稳态耗时、轨迹/CoC 比较、100 clips minADE、显存及异常。大型 profiling 与日志提供可追溯制品链接；权重、数据集、凭据、真实访问地址及二进制资产不入代码仓。截图来自实际运行，不替代原始数值与日志。

# 风险与待确认事项

- RFC 确认：CANN 9.1 与框架/驱动配套、A3 型号；固定 100 clips 和评测聚合；1/3/5 轨迹阈值解释；计时边界和波动判据；具体捕获与预取接口。
- 64 GB 为设备总容量，10B 权重之外仍有 KV cache、激活和图 workspace，须实测容量，不能据此保证十轨迹配置必然可运行。
- 若没有可证明安全且有效的预取目标，或 A3 未取得端到端收益，则该项仍未完成，不以单 kernel 理论收益或 A2 结果替代。
- 不修改精度、数据、seed 或采样规模规避失败；不将基线异常或框架限制记为验收通过。
