# 面向 AI 零基础学习者的 PyPTO 算子开发课程设计

## 1. 需求背景与依据

本课程对应 [11 月社区任务：开发一套面向 0 基础人群的 PyPTO 算子开发课程](https://www.hiascend.com/activities/task-center/details/1073bd69ad9f48f7848f2d940a5b2918?menu=guide)。学习者具有基础 Python 能力，但不需要预先学习线性代数、微积分和深度学习。课程帮助学习者理解神经网络的计算过程，并能用 PyPTO 编写、运行和验证其中的算子。

需求依据为任务页面提供的[任务书原始附件](https://www.hiascend.com/p/resource/202611/0ea229424699443abbe1f3f4b3720d1a.zip)、[课程上库验收标准](https://gitcode.com/cann/cann-learning-hub/blob/6c9f50caee8ddf846d6fb4053195d31ac89fd87d/docs/course_submission_criteria.md)、[贡献指南](https://gitcode.com/cann/cann-learning-hub/blob/6c9f50caee8ddf846d6fb4053195d31ac89fd87d/CONTRIBUTING.md)及 [CANNLab 课程开发指南](https://gitcode.com/cann/cann-learning-hub/blob/6c9f50caee8ddf846d6fb4053195d31ac89fd87d/docs/CANNLab_course_development_guide.md)。任务讨论入口为[课程仓讨论帖 #71](https://atomgit.com/cann/cann-learning-hub/discussions/71)。附件未公开可核实的 Git commit，不能用课程仓规范的 commit 代替任务书 commit。

课程开发位置规划为 `contrib/tutorials/pypto_ai_foundations/`。本设计描述教学组织、计算方案及验证计划，运行结果与环境实况另行记录。最终实现可以调整章节划分、文件名称及技术细节，交付时以知识点、实践和验证证据的完整对应关系说明调整；任务书规定的内容与验收条件不能因调整而减少。

## 5. PyPTO 计算设计

### 5.1 编程与环境边界

采用 PyPTO Tensor 编程。依据[官方快速入门](https://pypto.gitcode.com/guide/quick_start/tensor/quick_start.html)和 [JIT 接口说明](https://pypto.gitcode.com/api/tensor_api/config/pypto-frontend-jit.html)，主机准备输入和输出张量，带类型注解的 `pypto.frontend.jit` 入口描述设备计算，并将结果写入输出张量；同步完成后读取输出。不能把 Python 函数重新绑定局部变量当作设备输出写回。

PyTorch/NumPy 用于生成数据、承载主机/设备张量及独立参考验证。正文所教的运算及模型组合使用 PyPTO 执行，明确标识参考计算；不能把 PyTorch 的卷积、RNN 或注意力调用包装成 PyPTO 实现。Python 可组织小规模时间步和训练迭代，模型的张量运算在 PyPTO 中完成。

CANN 推荐版本为任务书指定的 9.1.0。依[官方安装说明](https://pypto.gitcode.com/install/build_and_install.html)，9.1.0 及之后的 CANN 包集成 PyPTO。课程优先使用配套安装，运行前输出实际包版本并核验所用 API；当前在线文档可能包含更新版本能力，不将其直接等同于已安装版本。Notebook 不自动升级 CANN、驱动或已有框架以绕过配套问题。

### 5.2 算子与组合模块

| 模块 | 设备计算与实现方案 | 独立验证重点 |
| --- | --- | --- |
| 基础运算 | 加减乘除、广播、归约、转置、变形、点积和矩阵乘法 | 形状推导、广播轴、归约维度与尾块 |
| 激活和损失 | ReLU/Sigmoid/Tanh；MSE；稳定 Softmax 与交叉熵 | 大正/负值、饱和、概率和、损失分母 |
| 训练 | 显式链式求导、梯度归约、SGD、权重衰减、外部传入 Dropout 掩码 | 梯度形状、更新方向、训练/推理语义 |
| 卷积和池化 | 小尺寸窗口切片与乘加；必要时展开为矩阵乘法；窗口最大/均值归约 | 通道次序、padding、stride、有效元素数 |
| 现代 CNN 模块 | 卷积/激活堆叠，残差相加、密集特征拼接 | 残差维度投影、拼接轴、特征数增长 |
| RNN/GRU/LSTM | 线性变换、激活与门控状态更新；显式状态传递 | 时间顺序、门排列、GRU 重置约定、LSTM 双状态 |
| 注意力 | QK 转置乘积、缩放、掩码、稳定 Softmax、与 V 相乘 | 被遮蔽位置权重、有效长度、缩放分母与因果性 |
| Transformer | 嵌入查表、位置编码、多头重排、残差、LayerNorm、FFN、交叉注意力及输出层 | 头维度、归一化轴、交叉注意力来源、标签移位 |

选用固定小形状降低编译和理解成本，每例声明 shape、dtype、布局、参数及合法范围。非法维度、空归约、零除数和不匹配的头数等在主机侧检查。分块示例显式处理尾块有效区域，按实际芯片和 API 对齐约束配置向量/矩阵分块，不把教学分块常量宣称为所有硬件的最佳值。

### 5.3 数值与模型语义

基础例子优先 FP32。若矩阵运算使用 FP16 输入、FP32 累加或显式类型转换，必须解释发生位置和误差来源，参考计算以同一量化后输入为基准，并额外说明相对未量化数据的差异。容差随 dtype、运算长度和数据范围写入用例配置，避免整门课程用一个宽松阈值掩盖问题。

Softmax 先减最大值再取指数；交叉熵采用稳定的对数归一化表达式。注意力有效行必须有至少一个可见位置，课程基础接口拒绝全遮蔽有效行；padding 查询位置的输出按明确掩码置零。LayerNorm 说明归一化轴、方差定义和 epsilon；Dropout 使用固定种子生成掩码，训练阶段采用保留概率的倒数缩放，推理阶段直通。

微积分练习先以高精度参考验证解析公式，再核验 PyPTO 梯度。差分使用中心差分并说明步长，避免在 ReLU 零点等不可导位置作相等判定。GRU 必须注明 reset-before 或 reset-after 约定，参考实现与之相同；LSTM 明确各门和记忆状态。训练数据划分先于标准化拟合，验证/测试数据不参与统计量学习。

## 6. 环境与数据计划

正式验证至少使用一个外部开发者可创建的 A2/A3 CANNLab 环境，并核对 cann-learning-hub 在线 Notebook 的直接运行要求。若只验证一种硬件，README 只列该型号为已验证，不推导另一平台已通过。

环境记录至少包含：镜像模板名称、镜像版本、Python 内核名称及完整版本、系统与 CPU 架构、NPU 型号、驱动/固件、CANN、PyPTO、torch、torch_npu、Notebook 执行工具版本和运行模式。检查设备可用性和 NPU 执行模式，缺少设备或配套依赖须明确失败，不静默退回 CPU 并标记课程通过。

每本 Notebook 给出安装及运行所需命令，环境脚本的作用域要准确：在子 shell 中执行 `source` 不会修改当前 Python 内核环境，课程应使用已配套内核，或在说明的独立子进程中完成环境加载和脚本执行。Python 依赖在验证后固定版本；最终复现不依赖变化中的默认分支或未提交文件。

数据以小规模合成数值、简单几何图案和原创短文本为主。数据生成器、种子、shape、参数、词表和划分规则均随代码提供；下载数据若确有必要，注明公开来源、固定版本、许可、校验及失败处理。训练和生成案例的目的为解释机制，不以小数据结果证明真实语言能力。

## 7. 验证方案与验收判定

### 7.1 内容与结构检查

建立 `coverage.json`，逐项映射任务书条款到讲解 Notebook、代码单元、练习答案和验证用例。核对所有指定知识点有解释和例子；“出现关键词”不等同于内容覆盖。人工检查文字、图意、前置知识顺序和练习难度，自动检查 Notebook 格式、英文命名、首末小节、每章目录、答案及图片相对链接。

自动核对每章末尾客观题和三个难度的编程题，确认实操小节具有独立编程练习及可执行答案。检查正文没有未解释的核心 API、设备参数或 shell 命令，也没有只有封装调用而无法看到关键实现的教学断层。

### 7.2 数值与行为检查

每个教学算子使用独立参考结果，记录输入规格、随机种子、最大绝对误差、相对误差及判定阈值。计算 `abs(actual - reference) <= atol + rtol * abs(reference)` 的逐元素条件，另行检查 shape、dtype 和有限值；特殊 NaN/Inf 行为如被教学使用，单独定义判据。

除了正常随机输入，还验证零值、负值、重复值、非整块形状、有效广播及边界窗口。重点覆盖：矩阵维度匹配，padding/stride 输出尺寸，池化边界，稳定 Softmax，Dropout 训练/推理差异，GRU/LSTM 状态，注意力掩码和 Transformer 形状流。数值梯度和独立自动微分可用于核对参考梯度，但不替代设备梯度实现。

小模型训练记录完整损失序列、参数配置与随机种子。检查有限梯度、有效参数更新和预先定义的学习目标，不要求每一次随机小批量更新都降低损失。因果性用修改未来 token 后前缀输出不变来验证；序列生成同时核对结束符和最大长度约束。

### 7.3 全课程运行

使用 Notebook 执行工具按课程清单逐本启动新内核、顺序执行全部代码单元，正文和参考答案都在覆盖范围。每本记录启动时间、耗时、执行单元数、退出状态、失败单元及 traceback。超时和缺少环境记为失败/未测，不允许 `allow_errors` 将异常变成通过。

清空输出的源码 Notebook 与执行副本分别存放。执行副本、逐本日志、配置、环境记录和原始输出共同支持验证结论；最后一次成功结果不能覆盖和掩盖当前 commit 的失败。

任务没有规定固定性能倍率或模型精度榜单门槛。若教学展示性能比较，单独报告首次编译，稳态计时预热 5 次、重复 20 次，计时边界前后同步，记录设备负载、中位数及样本；如实际环境需要其他口径，明确配置并保留原始样本。无实测数据时不宣称优化收益。

### 7.4 从完整 commit 复现与材料生成

最终提供《自验证步骤说明》和《复现附件说明》。前者从完整 commit 获取代码开始，给出环境部署、数据准备、全量执行、输出解析和材料生成的顺序命令；后者关联输入、参数、配置、实际输出和日志，写清包内相对路径与解压位置。

所有运行、验证、解析和报告生成脚本位于指定 commit 中或随包提供。汇总报告从本次机器输出生成，不复制模板示例或手填测量值。原始输入/输出按任务要求保存；执行 Notebook 保留实际输出但不随源码提交。必要附件按清晰用途组织，最终 ZIP 使用 STORE/DEFLATE，主包不超过 100,000,000 字节。

交付前重新下载原任务网页及附件并处理差异。从验收 commit 独立检出，按照实际交付步骤检查部署、数据、Notebook 执行和材料生成，记录该次检验范围；已有有效结果是否复用以版本、输入、环境和要求是否变化为依据。最终核对 ZIP 算法、大小、CRC、完整解压内容和路径，Windows 未实测时不声称 Windows 实测通过。

## 8. 风险与实施顺序

| 风险 | 预防与处理 |
| --- | --- |
| 文档与安装 API 版本不一致 | 先验证配套环境和最小样例，固定实际版本；不把在线最新版能力默认为旧版本能力 |
| 课程只讲模型名称而缺少原理 | 用知识点映射、结构图、可解释小例子和练习检查教学深度 |
| 封装掩盖框架或状态依赖 | 检查 PyPTO 调用路径；逐本新内核执行，正文与答案使用独立输入 |
| 运行时间或数据体积过大 | 小张量、小模型、可生成数据；限制编译并行度和执行超时 |
| 浮点误差、梯度错误与参考语义不一致 | 同输入独立参考，明确类型、轴、门控和掩码约定，保留误差和失败用例 |
| 在线环境尚未验证 | 保留未测状态；实际镜像和内核确认后逐本验证，不用本机检查替代 |

实施按“环境与样章—数学基础—神经网络模块—综合课程—完整验证和材料”推进。各阶段先保证教学概念和最小可运行实例，再扩展练习和边界。设计评审、CI 检查、课程运行验证、人工验收与正式合入是不同环节，应分别记录其状态。正式交付以任务书要求和真实证据为准。
