# aclblasCrot 算子设计文档

# 需求背景（required）

## 需求来源

本需求来自 11 月社区任务“aclblasCrot 算子开发（A2/A3）”。使用 Ascend C 实现单精度复数向量 Givens 旋转，完成 Atlas A2/A3 平台适配及配套自验证。

## 背景介绍

### aclblasCrot 算子开发

复数向量旋转用于线性代数计算。本算子使用实数标量 c 和复数标量 s，对两个复数向量逐元素执行旋转，并将结果分别写回原向量。

### 现有方案分析

ops-blas 已有同族旋转算子及其他架构上的相关实现，可参考其接口组织、参数处理和工程接入方式。本任务补齐 A2/A3 上的 Crot 能力，结合平台特点设计计算与数据搬运流程。

### 算子功能分析

| 参数 | 含义 | 数据类型 | 形状及约束 |
| --- | --- | --- | --- |
| handle | 携带执行 stream 的库句柄 | aclblasHandle_t | 有效非空句柄 |
| n | 参与旋转的复数元素数量 | int | n≥0，n=0 快速返回 |
| x、y | 输入及原地输出向量 | COMPLEX64 | Device 内存，逻辑长度均为 n |
| incx、incy | 向量元素访问步长 | int | 支持正负步长，跨度满足接口要求 |
| c | 实数旋转标量 | FLOAT32 | Host 或 Device 内存中的单值 |
| s | 复数旋转标量 | COMPLEX64 | Host 或 Device 内存中的单值 |

复数由两个 FLOAT32 分量组成。x、y 分别按各自步长访问，两个输出均由同一对原始输入计算。

# 需求分析（required）

## 需求描述

基于 ops-blas 工程，以句柄式 BLAS 接口直调 Ascend C Kernel，实现 A2/A3 平台的 aclblasCrot。接口、旋转公式、正负步长、快速返回和异常行为遵循任务书约定。

## 需求拆解

1. 实现复数旋转及共轭计算，保证 x、y 原地更新的正确性。
2. 支持连续和跨步访问，以及 c、s 的 Host、Device 和混合存储位置。
3. 完成句柄、维度、指针和跨度校验，按约定处理快速返回及错误码。
4. 根据向量规模组织并行计算与数据搬运，达到任务书的性能目标。
5. 完成接口接入、构建和测试注册，提供精度、性能及边界用例的自验证材料。

# 详细设计（required）

## 算子分析

### 数学公式

对逻辑位置 i 的一对输入元素，旋转公式为：

```text
x_new[i] = c × x_old[i] + s × y_old[i]
y_new[i] = c × y_old[i] − conj(s) × x_old[i]
```

其中 `conj(s)` 表示 s 的复共轭，i 的范围为 `0≤i<n`。逻辑位置通过 incx、incy 映射到实际存储位置，负步长从对应向量物理跨度的尾端起算。

### 支持数据类型

x、y、s 使用单精度复数，实部与虚部均为 FLOAT32。c 使用 FLOAT32。输出类型与输入向量一致，实部、虚部按照任务书规定的精度标准分别验证。

### 支持形状

x、y 的逻辑形状均为 `[n]`。n>0 时，各向量的物理存储至少覆盖 `1+(n−1)×abs(inc)` 个复数元素。支持小规模、大规模和非对齐长度，以及正负非零步长。

## 算子实现

### 实现方案

整体采用 Host 参数处理与设备侧分块计算相结合的方式。按向量长度和访问步长选择适合的执行路径，逐对读取原始数据、完成复数旋转，再写回对应位置。

#### 3.2.1 host 侧设计

Host 侧按照任务书规定的顺序检查句柄、n、步长和指针。n=0 时完成规定检查后返回成功，n<0 及非法步长、跨度溢出等情况返回对应错误码。

根据指针属性识别 c、s 的存储位置，支持 Host、Device 及混合模式，并保证标量读取与绑定 stream 的执行顺序一致。

结合平台资源、向量规模和连续性生成 tiling 信息，合理划分各核的工作范围及单次处理规模。计算任务通过 handle 绑定的 stream 下发。

#### 3.2.2 kernel 侧设计

Kernel 侧完成输入搬入、复数旋转和结果写回。计算时保留当前元素对的原始值，确保两个输出使用同一组输入，并正确处理 s 的共轭。

连续访问路径重点提高数据搬运和向量计算效率，跨步路径按照逻辑元素位置访问。尾部处理限定在有效元素范围内，写回时保留步长间隙中的原有数据。

#### 3.2.3 接口与工程接入

对外提供以下接口，沿用 ops-blas 的句柄、复数类型和状态码约定：

```cpp
aclblasStatus_t aclblasCrot(
    aclblasHandle_t handle,
    int n,
    aclblasComplex* x,
    int incx,
    aclblasComplex* y,
    int incy,
    const float* c,
    const aclblasComplex* s);
```

实现接入 arch22 构建分支，并补齐对应 GTest 注册。接口声明、产品支持说明和测试调用保持一致。

## 算子约束限制

- handle 为空时返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`。
- handle 检查通过后，n<0 返回 `ACLBLAS_STATUS_INVALID_VALUE`，n=0 返回成功并保留 x、y 原值。
- 正常计算路径要求 x、y、c、s 非空，步长非零且不为 INT32_MIN，地址跨度符合任务书的 int32 范围约束。
- 访问范围由 n、incx 和 incy 决定，输出写回对应向量的有效位置。
- 执行通过绑定 stream 下发，调用方在读取结果前同步，并保证相关存储在任务完成前有效。
- Inf/NaN 输入及输出按任务书的特殊值规则验证。

# 可维可测分析

## 精度标准/性能标准

| 验收项目 | 标准 | 标准来源 |
| --- | --- | --- |
| 参考结果 | 按 Netlib/LAPACK Crot 语义生成，包含复数 s 的共轭处理 | 任务书功能及精度要求 |
| 有限值精度 | 实部、虚部分别按 FLOAT32 混合容差验证，rtol、atol 均为 2⁻¹³，匹配比例至少 0.99，最大绝对误差同时满足规定限值 | 任务书精度要求 |
| 特殊值 | Inf/NaN 单独统计并按任务书规则判定 | 任务书精度要求 |
| 性能 | 每个性能用例的平均耗时不高于对应 GPU 标杆的 1.25 倍 | 任务书性能要求 |
| 内存与访问 | 检查有效范围、尾部及步长间隙的访问和写回情况 | 任务书功能与自验要求 |

精度验证覆盖 x、y 两路完整输出。测试包含连续及正负步长、共轭运算、不同标量存储位置、非对齐长度、零维、非法参数和特殊值，并按任务书补齐输入分布及缺失场景。

性能测试覆盖配套的全部性能用例，按任务书要求使用 msprof op 采集单算子 task duration。预热 5 次后，连续执行至少 10 次有效采样，取算术平均作为单次耗时，逐项记录 GPU 标杆耗时、NPU 实测耗时和判定结果。

自验证材料包含环境、执行步骤、用例结果和原始日志。内存部分按交付模板说明实际验证内容，任务书未单独设定峰值内存指标。

## 兼容性分析

接口采用 ops-blas 统一类型及状态码，参数顺序与任务书定义一致。A2/A3 的校验顺序和边界语义遵循任务书约定，通过 arch22 分支接入现有工程，并对同族接口执行必要的构建及回归验证。
