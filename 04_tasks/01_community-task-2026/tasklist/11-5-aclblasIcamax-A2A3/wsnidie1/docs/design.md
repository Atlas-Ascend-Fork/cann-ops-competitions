## 背景介绍

### Icamax 算子能力补齐

Icamax 用于复数向量的主元定位及数值计算中的极值选择。输入为实部、虚部交错存储的 `complex64` 向量，输出为符合 BLAS 约定的 1-based 整数索引。

本任务复用现有 `aclblasIcamax` 公共接口，为 Atlas A2/A3 增加 Ascend C kernel 直调实现。实现放在 `blas/iamax/arch22/`，不引入与现有接口平行的私有入口。测试放在 `test/iamax/icamax/arch22/`，通过仓库统一 GTest 框架注册。

### Icamax 现状分析

目标仓库已提供公共 API 声明、`aclblasComplex` 类型、句柄与工作区机制，以及 arch35 的复数 Icamax 和 arch22 的实数 Isamax 参考实现。arch35 使用的专用能力不能直接视为 arch22 可用能力；本方案采用 arch22 支持的批量 DMA、向量计算及归约接口。

| 项目 | 已有基础 | 本任务改动 |
| --- | --- | --- |
| 公共接口 | `include/cann_ops_blas.h` 中已有声明 | 沿用原签名 |
| 类型与句柄 | `aclblasComplex`、绑定 stream、有效工作区 | 沿用原机制 |
| arch22 归约族 | 实数 Isamax | 增加复数 L1 模及确定性索引选择 |
| arch35 Icamax | 已有另一架构实现 | 保持其源码及原有测试行为 |
| Icamax GTest 注册 | 上游只为 arch35 注册 | 补齐 arch22 注册 |
| 产品文档 | Icamax 产品支持表未覆盖 A2/A3 | 补充 A2/A3 实现及使用说明 |

### Icamax 功能分析

对逻辑元素 `i=0..n-1`，取物理元素 `x[i*incx]`，计算 `abs(Re)+abs(Im)`，输出严格比较语义下首次取得最大值的逻辑索引加一。

| 参数 | 含义 | 数据类型/位置 | 约束 |
| --- | --- | --- | --- |
| handle | 库句柄，携带执行流与工作区 | Host 句柄 | 必须有效 |
| n | 逻辑复数元素数 | Host `int` | `n>=0`；负值为非法参数 |
| x | 输入向量 | Device `const aclblasComplex*` | 正常计算路径不得为空；输入只读 |
| incx | 物理复数元素步长 | Host `int` | 正值正常计算；非正值 quick return |
| result | 1-based 结果 | Device `int*` | 任意路径均不得为空 |

沿用接口原型：

```cpp
aclblasStatus_t aclblasIcamax(
    aclblasHandle_t handle, int n, const aclblasComplex* x, int incx, int* result);
```

# 需求分析（required）

## 需求描述

在 Atlas A2/A3 上实现复数 Icamax，保持句柄式 BLAS 接口、Device 标量输出、绑定 stream 上的异步执行，以及与指定 Netlib `cblas_icamax` 参考一致的精确整数结果。

计算量使用复数的 L1 模 `|Re|+|Im|`。本任务不使用欧氏模，不支持负步长反向遍历。NaN、Inf、正负零、同模并列和跨度溢出按任务书明确约定处理。

## 需求拆解

1. 完成参数检查、quick return 和 64 位跨度计算，非法参数在读取输入或启动归约前返回。
2. 完成连续及正步长输入的批量搬运和向量 L1 模计算。
3. 对每个 tile 显式选择最小并列索引，对跨 tile、跨核结果保持相同规则。
4. 小输入单核，大输入分核并使用第二级归约；避免跨核自旋和 Host 同步。
5. 保持首项 NaN 停留索引 1、后续 NaN 不胜出、首个 Inf 胜出的 Netlib 语义。
6. 保留官方 1,000 条精度和 200 条性能用例，另外补充正态分布、特殊值、地址偏移与边界测试。
7. 达到每个正式性能 case 的 `GPU耗时/NPU耗时>=0.8`，并保留完整原始计时数据。
8. 提供产品与测试 README、设计文档、规定格式报告、日志、截图及可访问的验收代码身份。

# 详细设计（required）

## 算子分析

### 数学公式

令 `a_i=FP32(abs(Re(x[i*incx]))+abs(Im(x[i*incx])))`。

对不存在 NaN 的输入：

```text
result = 1 + min { i | a_i = max_j(a_j) }, i,j ∈ [0,n)
```

对特殊输入使用 Netlib 的有序更新语义：以第一个元素初始化比较值，只有后续值严格大于当前值才更新结果。因此：

- 首元素的比较值为 NaN，返回 1；后续 NaN 不参与胜出。
- 首个 Inf 胜出，后面的 Inf 不覆盖它。
- 所有零、同模常量或其他相等最大值，返回最小逻辑索引。
- 有限 FP32 分量相加溢出为 Inf 时，该结果按 Inf 参与同样的比较。
- `n=0` 或 `incx<=0` 时结果为 0，不读取 `x`。

### 支持数据类型

| 对象 | 类型 | 说明 |
| --- | --- | --- |
| 输入 x | COMPLEX64 | 每元素两个交错 FLOAT32 分量 |
| L1 模与向量归约值 | FLOAT32 | 保留任务规定的 FP32 加法和比较语义 |
| Host 跨度乘法 | INT64 | 避免 `int` 域乘法溢出 |
| 全局逻辑索引 | UINT32 | 归约内部使用；合法结果转换为 INT32 |
| tile 内候选索引 | FLOAT32 | 连续路径最大为 7679，非连续路径最大为 1023，均可精确表示 |
| 输出 result | INT32 | Device 单值，1-based；quick return 为 0 |

### 支持形状

逻辑形状为 `[n]`。正步长正常计算时物理复数元素跨度为 `1+(n-1)*incx`。

- `n`、`incx` 沿用 API 的 `int` 参数，不另设与正式 CSV 尺寸绑定的接口上限。
- Host 使用 INT64 检查 `(n-1)*incx`，超过 `INT32_MAX` 返回 `ACLBLAS_STATUS_INVALID_VALUE`。
- 大跨度合法输入仍要求调用方提供真实可访问的物理分配；不因形式合法而假定任意地址可访问。
- 支持运行时 `n` 和正 `incx`；不涉及 Tensor 广播或框架图模式的 dynamic shape。
- 正式性能用例均为 `incx=1`，最大 `n=4,194,304`；正步长非连续输入另由功能测试覆盖。

## 算子实现

### 实现方案

采用“Host 校验与分核、核内分块向量归约、必要时第二级合并”的结构。

| 文件 | 职责 |
| --- | --- |
| `blas/iamax/arch22/icamax_host.cpp` | 参数校验、quick return、动态核数、工作区检查及异步启动 |
| `blas/iamax/arch22/icamax_kernel.h` | Host/kernel 共用启动函数声明 |
| `blas/iamax/arch22/icamax_kernel.cpp` | partial/finalize 入口与同一 stream 的启动顺序 |
| `blas/iamax/arch22/icamax_kernel_impl.h` | 批量搬运、L1 模、显式 tie 选择、核间结果合并 |
| `test/iamax/icamax/arch22/` | 官方 CSV、独立补充 CSV、生成器及 GTest |

调用顺序为：参数检查 → quick return 或选择核数 → 检查有效工作区 → 启动 partial → 多核时启动 finalize → 调用方同步后读取 Device 结果。

#### 3.2.1 host侧设计：

参数检查按以下顺序执行：

| 顺序 | 条件 | 行为 |
| --- | --- | --- |
| 1 | `handle==nullptr` | 返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR` |
| 2 | `n<0` 或 `result==nullptr` | 返回 `ACLBLAS_STATUS_INVALID_VALUE` |
| 3 | `n==0` 或 `incx<=0` | 允许 `x` 为空；在绑定 stream 上异步写 result=0 |
| 4 | 正常路径 `x==nullptr` | 返回 `ACLBLAS_STATUS_INVALID_VALUE` |
| 5 | INT64 跨度超过 INT32_MAX | 返回 `ACLBLAS_STATUS_INVALID_VALUE` |

quick return 使用 `aclrtMemsetAsync` 写四字节输出，ACL 下发失败映射为 `ACLBLAS_STATUS_EXECUTION_FAILED`。正常路径不逐次分配工作区，不把输入或 tiling 从 Host 拷入，不执行 Host 同步。

##### 1. 分核策略：

V8 每核目标处理 16,384 个逻辑复数元素。

```text
n <= 16384: B = 1
n > 16384:  B = min(ceil(n/16384), 当前设备AIV核数)
```

多核路径从仓库平台接口动态获取 AIV 核数；查询失败返回内部错误。该阈值是性能调优起点，不是随测试 case 编号特化的逻辑。真机性能检查后如修改阈值，须重新绑定源码和结果。

kernel 通过 `q=n/B`、`r=n%B` 计算分区：第 `b` 核从 `b*q+min(b,r)` 开始，处理 `q+(b<r)` 个元素。前 `r` 核各多一个元素，所有合法元素恰好覆盖一次。

##### 2. 数据分块和内存优化策略：

V8 的连续路径每 tile 7,680 个复数；正步长非连续路径每 tile 最多 1,024 个复数。工作区来自 handle 当前有效缓冲区，每核独占 32 字节，存储部分最大值、逻辑索引及填充，避免相邻核写入共享一个 32 字节事务。

- 单核路径直接写结果，不要求额外工作区。
- 多核要求至少 `B*32` 字节；空工作区或容量不足返回执行失败，不进行隐式申请或同步。
- finalize 一次批量读入所有 partial，再按最大值与最小索引规则合并。

V8 partial 的显式 UB 分配如下。这是源码中的缓冲区容量，不等同于进程 HBM 峰值测量：

| 缓冲 | 连续路径字节数 | 非连续路径字节数 | 用途 |
| --- | ---: | ---: | --- |
| packed | 61,440 | 32,768 | 连续交错块，或非连续输入 32 字节行 |
| real、imag | 61,440 | 32,768 | 模值、分量与候选索引临时值 |
| index | 30,720 | 16,384 | 精确 tile 内索引 |
| mask | 960 | 512 | NaN 清理和最大值相等掩码 |
| reduce scratch | 30,720 | 16,384 | 向量归约临时区 |
| reduce result、output | 64 | 64 | 标量归约及输出 |
| gather offsets | 0 | 4,096 | 仅非连续路径分配 |
| 合计 | 185,344 | 102,976 | 连续约 181 KiB，非连续约 100.56 KiB |

**UB 上限须按实际 SDK 可分配容量判断。**CANN 9.1.0 的 arch2201 常量中，物理 `TOTAL_UB_SIZE` 为 192 KiB，但 `TOTAL_VEC_LOCAL_SIZE` 与 `TMP_UB_OFFSET` 均为 **184 KiB，即 188,416 字节**。不能把物理 192 KiB 全部作为 `TPipe::InitBuffer` 可用空间。

连续 tile 长度为 `T` 时，显式缓冲合计为 `24*T+T/8+64` 字节。V8 使用 `T=7680`，合计 **185,344 字节**，低于 188,416 字节；该版本已完成下文的完整精度、PF 输出和全部 200 项 event 性能检查。非连续路径保持 4,096 容量的分量、索引与归约缓冲及 1,024 行搬运，不随连续 `T` 扩大，合计为 **102,976 字节**。

局部有效连续索引范围为 `[0,7679]`，无效候选哨兵为 `7680`；这些值都能由 FP32 精确表示。调整 `T` 时须同步更新哨兵、缓冲容量及比较补齐容量，并检查 Gather 与归约限制。工作区复杂度为 `O(B)`，核内 UB 上界不随 `n` 增长；索引生成调优与任何后续变更都须绑定相应候选与验证结果。

##### 3. tilingkey规划策略：

沿用 kernel 直调函数参数，不另引入图执行器 tiling key 或 Host 数组式核间分配表。传入 `n`、`incx`、`B` 和 Device 指针，kernel 根据输入选择连续/步长路径；`n<=4` 使用有界极小向量路径，避免向量初始化成本。

正常路径及快返的选择只依赖公开参数、实际核心数和有效工作区，不依赖输入随机种子、CSV 名称、基线数值或验收状态。

#### 3.2.2 kernel侧设计：

1. **流水线生命周期。** 在每次 kernel 入口创建 `TPipe`，通过指针交给实现类，不将 `TPipe` 对象保存为类成员。两个入口各自拥有独立生命周期。

2. **首项与极小向量。** `n=1` 直接返回 1；其他正常输入先检查第一个复数的分量位模式。首项含 NaN 时，所有核生成一致的索引 0 partial，最终输出 1。`n<=4` 的有界路径采用严格大于更新，不扩展为大规模逐元素循环。

3. **连续输入 CopyIn 与相邻求和。** 使用 `DataCopyPad` 批量读入不超过 7,680 个交错复数。对 packed 的 `2*len` 个 FP32 分量取绝对值后，以 `PairReduceSum` 对相邻实部与虚部求和，直接得到每个复数的 L1 模，不再为连续路径分离两个分量。每个 repeat 读取 64 个 FP32、写出 32 个模值；目标 repeat stride 为 1，源 block stride 为 1、源 repeat stride 为 8，确保输出连续。尾块以 `2*tail` 个有效分量单独执行，搬运仍只覆盖实际 `len*8` 字节，后续比较和归约限定在有效 `len`。

4. **非连续输入 CopyIn。** 使用 `DataCopyPad` 的二维批量搬运，一行读取一个 8 字节复数，源行间隔为 `(incx-1)*8` 字节，目的端按 32 字节行对齐；再以 `i*32` 和 `i*32+4` 的 UB 字节偏移 Gather 两个分量。`len<=1024`，目的端占用不超过 32 KiB。Host 的合法跨度约束保证 `n>=5` 时源行字节间隔可由 UINT32 表示，极大步长的小 `n` 使用上述有界路径。

5. **模值与 NaN 清理。** 连续路径采用上述 `Abs+PairReduceSum`，非连续路径在 Gather 后分别对实部、虚部取绝对值，再以 FP32 `Add` 相加。以 `value>=0` 的比较掩码把后续 NaN 替换为 -1。所有合法 L1 模非负，因而该哨兵不会战胜正常元素。首项 NaN 已由独立规则处理。CANN 9.1.0 上 FP32 `Compares` 的计数按 64 个元素向上补齐；缓冲区容量覆盖补齐范围，但后续 `Select` 和 `Reduce` 仍只使用真实有效 `len`，补齐元素不进入归约。

6. **精确局部索引、显式并列选择与 record-prune。** 连续路径使用 `MakeLocalIndices`：先通过 `CreateVecIndex` 生成不超过 8 个索引，令已生成数量为 `filled`，随后每轮取 `count=min(filled,len-filled)`，以 `Adds(indices[filled], indices, float(filled), count)` 复制已生成前缀并加偏移，逐轮倍增直到覆盖有效长度。每轮的源区已初始化、目的区与源区不重叠，并以向量屏障保证前一轮完成；由归纳可得写出值恰为 `0..len-1`。最大有效索引 7679 以及偏移都可由 FP32 精确表示，不依赖近似舍入。非连续路径继续使用其原有 `CreateVecIndex` 和 Gather 偏移表。取得索引表后，先仅归约最大值。各核按全局索引递增顺序处理 tile；若当前 tile 最大值不大于该核此前最大值，则跳过本 tile 的索引定位。严格更大时才执行相等比较掩码，令相等位置保留精确局部索引、其他位置为 tile 容量哨兵，再归约最小索引。相等比较同样按 64 向上补齐，索引选择及归约仍限定有效 `len`。这样不依赖 `ReduceMax` 默认如何处理并列。

   **首索引保持证明：**小于此前最大值的 tile 不可能胜出；等于此前最大值时，该 tile 的所有全局索引都大于已处理 tile 中保留的首个最大索引，也不可能改善结果。只有严格更大的 tile 才需要找到本 tile 的最小最大值索引。核间 finalize 仍显式比较最大值和最小全局索引，因此不会因 record-prune 改变跨核并列语义。首项 NaN 独立规则、有效值非负和 -1 哨兵保持不变。

7. **流水线与 CopyOut。** 使用 MTE2→V、V→S、S→V 及 S→MTE3 等事件维持数据依赖；完成 tile 的向量结果读取后再复用输入缓冲。单核输出四字节 INT32；多核各写独占 32 字节 partial，并等待该次 MTE3 完成。

8. **第二级合并。** partial 与 finalize 在同一 stream 顺序下发，后者只在生产者完成后读取工作区。不采用跨核自旋、原子抢占索引或 Host 读回合并。finalize 仅按实际核数处理少量 partial。

总计算复杂度为 `O(n+B)`，输入有效数据搬运为 `O(n)`，多核 partial 写入与读回各为 `32B` 字节。非连续输入可能受低有效带宽影响，因此保留其独立功能回归；正式性能 200 档全部为连续输入。

## 算子约束限制

- 仅实现公共签名规定的单精度复数输入和 INT32 索引输出。
- 不支持负步长反向访问；所有 `incx<=0` 均成功输出 0。
- `result` 为独立 Device 标量；输入保持原字节不变。
- 正常路径要求有效 Device 输入、输出及足够的物理输入跨度；非法指针不能仅靠 Host 数值校验判定可访问性。
- 读取输出前，调用方必须同步 handle 绑定 stream。API 成功下发不等同于已经完成设备执行，异步设备错误由同步等运行时操作报告。
- 不更改 arch35 的已有实现、公共 API、数据布局或同族其他算子的行为。
- 本地前端、Host stub 和 CPU 参考检查只用于辅助定位；正式验证使用 CANN 9.1.0 真机构建及 NPU 输出，二者结果分开记录。

错误和快返用例只分配单元素占位输入，不按无效跨度分配大内存。正常用例调用真实 `cblas_icamax`，指定 Netlib 版本并保存实际加载库身份，不能静默改用特殊值语义不同的 BLAS。

1. 核验实际设备、CANN 9.1.0、编译器及 Netlib 参考库，构建独立目录；保存源码、构建产物和输入 CSV 哈希。

4. 保留每次 API 返回状态及同步结果，仅有效成功执行作为性能样本；同步后再次核对精确结果与输入不变。
5. 按任务书另行保留 `msprof op` 原始采集。多核一次 API 包含 partial 和 finalize，必须按调用配对合计两个任务，不只取 partial，也不把两个阶段的平均数当作完整调用耗时。
