# aclblasCsyrk3mEx 算子设计（Atlas 950PR）

## 需求背景

本任务在 `cann/ops-blas` 的 arch35 SYRK 模块提供复数对称秩 k 更新，用于已有列主序矩阵及外部指定的前导维度。调用方使用复数标量、三角选择和转置标志，能够从同一入口处理单精度复数及交错的复整数输入。对标接口为 cuBLAS 的 `cublasCsyrk3mEx`。[社区任务书及验收要求](https://www.hiascend.com/activities/task-center/details/3d67a5f992894ea8b43e472342c122e6)

## 需求分析

令 $X=\operatorname{op}(A)$，更新目标是 $C\leftarrow\alpha XX^{\mathsf T}+\beta C$。实现只读写 `uplo` 指定的三角，对角元素的实部和虚部均参与计算。对称性采用普通转置。`OP_N` 读取 n 行 k 列，`OP_T` 与 `OP_C` 都按 k 行 n 列输入的普通转置取数。调用方的另一半三角和各列 padding 保持原有字节。

| 参数 | 支持范围与布局 |
| --- | --- |
| A | `ACL_COMPLEX64` 为两个交错 FP32 分量，`ACL_INT8` 为两个交错的有符号 8 位分量 |
| C、alpha、beta | `ACL_COMPLEX64`。C 为列主序 n 行 n 列；标量支持 Host 或 Device 地址 |
| lda、ldc | `OP_N` 的 lda 至少为 max(1,n)，其余两种转置的 lda 至少为 max(1,k)。ldc 至少为 max(1,n) |
| 空维和零系数 | n 为 0 时校验参数后返回。k 或 alpha 为 0 时只需按 beta 处理指定三角。beta 为 1 时可直接返回，beta 为 0 时可直接写入结果 |

## 详细设计

### 计算分解

将操作数拆为 $X_r$、$X_i$ 和 $X_s=X_r+X_i$。同一次计算内核发射完成 $P_0=X_rX_r^{\mathsf T}$、$P_1=X_iX_i^{\mathsf T}$、$P_2=X_sX_s^{\mathsf T}$。结果实部为 $P_0-P_1$，虚部为 $P_2-P_0-P_1$。重组后完成复数 alpha、beta 缩放及三角写回。该分解也适用于转置、交错 INT8 输入和非零对角虚部。

### Host 侧

公开接口位于 `include/cann_ops_blas.h`，实现入口位于 `blas/syrk/arch35/csyrk3m_ex_host.cpp`。依次检查 handle、枚举、维度、前导维度、类型组合和指针。需要读取矩阵 A 的分支在提交乘积前校验 A。Host 从 handle 获取 stream 和可用计算核数，按输入布局选择 GM 地址映射，并对工作区乘法、加法和对齐进行越界检查。常规路径复用 handle 的工作区。下一步将两个 Device 标量的读回合并到同一条流上，在消费值前同步一次，并参照同目录 SSYRK 的运行时发射接口传回发射结果。

### 第三轮已验证的设备路径

1. **拆分。** AIV 将交错输入以 FP32 平面形式写为实部、虚部和两者之和。整数路径的 INT8 分量可精确提升。写入对齐尾部，Cube 读取的前导维度与工作区布局一致。
2. **矩阵乘。** 一次 AIC 发射计算三个实乘积。每个核根据所选三角取得有效的 64×64 输出块，沿 K 方向迭代，用三个 L0C 累加区保留结果，最后写入三个工作区平面。关闭 HF32，维持 FP32 操作数有效位数。
3. **重组和写回。** AIV 对选定三角重组复数并缩放。beta 为零的分支直接写出。第三轮另设长 K 复 INT8 路径，段内用整数计算三个实乘积，在宽整数中累加段结果，再转换至输出类型。该路径已通过本轮 INT8 精度验证，大矩阵的吞吐需要改善。

常规实现的工作区包含三个对齐的输入平面和三个对齐的输出乘积平面。n=k=4096 且无需尾部补齐时共需 384 MiB。接口与硬件路径分别验证，按形状、类型、数据布局和数值风险决定执行分支。

### 片上重组与数值修正

小阶数优先采用无工作区的单次发射，在寄存器或 UB 完成 3M 与三角写回。对大 n、小 k 的形状，采用 arch35 CGEMM 中已有的 `KERNEL_TYPE_MIX_AIC_1_2` 和 `Fixpipe` 行主序 UB 传输机制做对照试验，使两个配对 AIV 分别消费同一输出块的相应行。C 的最终地址仍按列主序和 ldc 计算。上下三角、奇数尾块、跨核 ready/free 的配对和 UB 峰值均需通过真机检验。[仓内 CGEMM 参考实现](https://gitcode.com/cann/ops-blas/blob/master/blas/gemm/arch35/cgemm_compute_kernel.cpp)

长 K 的候选路径每 128 项重组一次。复 INT8 的第三个点积在该段长的绝对值至多为 8,388,608，段内 FP32 能精确表示。跨段仍采用宽累加再收窄。对 COMPLEX64，比对分块、补偿累加和异常元素重算，分别检查相消、大系数、极值及 Inf/NaN。三角保护和一次发射内完成三个实乘积为各路径的共同约束。更大的输出分块、双缓冲和 Split-K 的选择依据为实际核数、片上容量、归约代价及逐例设备时间。

## 可维可测分析

| 项目 | 验证方法 |
| --- | --- |
| 精度 | 1000 条官方 CSV，通过仓内 ATK/GTest 调用公开接口。按任务书允许的双精度域使用 `cblas_zsyrk` 后收窄，分别比较实部与虚部。各分量匹配比例至少 0.99，相对和绝对容差均为 2 的负 13 次方，同时逐分量检查 0.01 或 32 ULP 上限与非有限值类别 |
| 接口与边界 | 校验返回码、输入矩阵保护区、另一半三角、列 padding、对角虚部、零维、零系数、Host 及 Device 标量 |
| 性能 | 200 条官方形状，每例预热 5 次后取 10 次有效设备采样。以 `msprof op` 的设备时长对应 GPU 基线的原始 ID，每例倍率至少 0.4，整体算术平均至少 0.5。复 INT8 补测沿用相同形状的 GPU 标杆 |
| 内存 | 任务书 §3.4 规定为 N/A。实现侧检查工作区大小、对齐和边界写入 |
| 硬件与兼容性 | Atlas 950PR、arch35、CANN 9.1.0。新增 C API，现有 SYRK 入口和调用签名保持兼容 |

第三轮在 950PR 上使用 OpenBLAS 0.3.20 得到精度 937/1000。相同源码、二进制、输入与判据换用 Netlib 3.10.0 后为 936/1000，另两条接口测试通过。差异集中于含 Inf 的 `TC_FL_324`，其 528 个有效三角元素的虚部分量均触发类别差异。后续精度验收固定 Netlib 3.10.0。

第三轮 COMPLEX64 系统级设备时间线有 197/200 条达到单例门槛，最低倍率 0.3550，平均倍率 0.8203。2433×85 的拆分、矩阵乘及写回分别耗时 7.12、86.90、127.60 微秒，优先验证片上写回。复 INT8 沿用同形状的 GPU 标杆补测，17/200 达到 0.4，平均倍率 0.0839。4096×4096 的整数直算耗时 1685.32 毫秒，重点验证用 Cube 计算精确段和再宽累加的路径。最终自验证报告采用正式单算子采样，并附逐例日志。
