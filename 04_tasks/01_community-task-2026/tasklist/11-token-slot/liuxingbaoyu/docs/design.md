# token slot 地址翻译算子设计文档

# 需求背景（required）

## 需求来源

本需求来自 xLLM 2026 年 11 月社区任务“token slot地址翻译算子”。使用 Triton Ascend 实现分页 KV Cache 的 token 地址翻译，提供 Python 调用接口和完整自验证工程。

## 背景介绍

### token slot 地址翻译算子开发

自回归模型在 prefill 和 decode 阶段产生 K/V 数据后，需要将逻辑 token slot 转换为各层 KV Cache 的物理 slot。本算子完成地址元数据计算，实际 K/V 写入由调用方执行。

### 现有方案分析

任务书基线采用 PyTorch NPU 操作，依次完成索引类型转换、整数除余、映射查表、地址合成和无效位置处理。本设计融合上述计算，减少设备调用次数和中间张量，降低完整调用耗时。

### 算子功能分析

| 参数 | 含义 | 数据类型 | 形状及约束 |
| --- | --- | --- | --- |
| slots | 逻辑 token slot，负值表示无效位置 | INT32 | 连续 `[N]`，N≥0 |
| M | 逻辑页到物理页的映射 | INT32 | 连续 `[B]` 或 `[L,B]`，B、L≥1，元素非负 |
| block_size | 页大小 S | Python int | 1≤S≤2147483647，不接受 bool |
| output | 翻译后的物理 slot | INT32 | `[N]` 或 `[L,N]`，独立连续存储 |

输入位于同一 NPU，支持合法的非零 storage_offset。M 的一维形式表示单层映射，二维形式表示各层分别映射，不进行隐式输入广播。

# 需求分析（required）

## 需求描述

实现具有 prepare/run 接口的独立组件，将逻辑 slot 转换为物理 slot。准备阶段完成一次性输入校验与执行元数据准备，运行阶段在当前 NPU stream 上读取最新输入，返回新分配的输出。

## 需求拆解

1. 实现逻辑页号、页内偏移、映射查表及物理地址合成。
2. 支持单层、多层、空输入、负值哨兵及非零存储偏移。
3. 保证页大小覆盖规定范围，整数除余及地址计算在 INT32 边界附近仍精确。
4. 支持 prepared 对象复用、合法输入值更新和同形状存储重绑定。
5. 完成功能、性能、内存及流与生命周期验证，形成可复现的交付材料。

# 详细设计（required）

## 算子分析

### 数学公式

对非负逻辑 slot x，设页大小为 S：

```text
logical_page = x // S
offset       = x % S
output[l,i]  = M[l,logical_page] × S + offset
```

当 `slots[i] < 0` 时，对应各层输出均为 −1，不使用负值作为查表地址。一维 M 使用相同计算规则，输出省去层维度。

例如 S=128、x=130、M[1]=5，则逻辑页号为 1、页内偏移为 2，输出为 642。

### 支持数据类型

输入和输出均为 `torch.int32`。索引、整数除余和地址合成保持整数精确性；值域校验使用足够宽的整数计算，避免校验过程自身溢出。

### 支持形状

slots 为 `[N]`，M 为 `[B]` 或 `[L,B]`，输出分别为 `[N]` 或 `[L,N]`。N=0 时返回相应形状的空输出。单个输入及输出的元素总数均不超过 2147483647。

## 算子实现

### 实现方案

整体采用 Python 准备与调度、Triton Ascend 设备计算的方式。按 token 数量、层数和页大小组织执行，融合地址计算与查表，保持调用接口和输出语义一致。

#### 3.2.1 host 侧设计

`prepare` 校验输入数量、张量类型、设备、连续性、维度和属性。通过一次性值域回读检查 M 非负、有效逻辑页号不越界，并检查每个映射值满足 `M×S+S−1≤2147483647`。

prepared 对象持有输入 Tensor，记录形状、设备、页大小及执行所需元数据。每次 `run()` 从当前 Tensor 获取存储信息，使用调用时的当前 stream，不缓存旧数据指针、输入计算结果或输出。

运行时按规定形状分配新的输出。根据输入规模与页大小选择计算组织方式，空输入直接返回空张量。准备阶段校验和首次编译与稳态执行分离。

#### 3.2.2 kernel 侧设计

设备侧按层和 token 区间划分工作，完成逻辑页号计算、页内偏移计算、映射读取和物理 slot 写回。不同输出位置独立计算，尾部通过有效范围掩码限定访问。

对二次幂页大小使用等价的整数运算优化；其他页大小保持精确整数除余语义，覆盖大页大小和接近 INT32 上限的输入。负 slot 在查表前进行安全处理，最终统一输出 −1。

计算结果直接写入本次分配的输出，减少完整中间张量。输入只读，不修改 slots 或 M。

#### 3.2.3 接口与工程接入

工程提供以下接口：

```python
prepare(inputs, attributes) -> Prepared
Prepared.run() -> torch.Tensor
run(inputs, attributes) -> torch.Tensor
```

调用形式为 `prepare([slots, M], {"block_size": S})`。直接 `run` 完成准备和执行，`Prepared.run()` 复用准备结果。提交工程以 `solution.py` 提供入口，包含所需依赖、测试驱动和复现命令，按 xLLM NPU 算子工程组织交付。

#### 3.2.4 流、生命周期与内存

每次调用使用当前 NPU stream 下发计算，不固定到 prepare 时的 stream。调用方保持输入及其存储在设备计算完成前有效，并保证跨 stream 数据依赖的执行顺序。

每次返回独立连续输出，输入、不同调用的输出之间不共享存储。prepared 对象只保留执行所需输入与元数据，不持有历史输出；当次临时张量随调用结束及设备使用完成释放。

| CANN | 9.1.0 |
| 软件依赖 | Python、PyTorch、torch_npu、triton-ascend 的配套版本 |
| 验证方式 | 构造地址元数据，不加载模型权重 |

## 算子约束限制

- attributes 仅包含 `block_size`；S 必须为规定范围内的整数。
- 非负 slot 满足 `slot//S<B`；M 的每个元素均满足完整物理页的 INT32 范围约束。
- 输入为同设备连续 INT32 张量，支持合法非零 storage_offset，不支持非连续布局。
- prepare 后形状、dtype、device 和 S 固定；改变这些条件时重新 prepare。
- 合法值更新和同形状 `set_` 存储重绑定后读取当前数据；越界更新须重新校验。
- 非法输入在 prepare 中抛出 TypeError 或 ValueError，设备端不使用 CPU 代算结果。

## 精度标准/性能标准

| 验收项目 | 标准 | 标准来源 |
| --- | --- | --- |
| 正确性 | 提交实现和基线均与独立 CPU 标杆逐元素零差异 | 任务书精度要求 |
| 小规模性能 | slots `[512]`、M `[8,4096]`、S=128，平均耗时≤85 μs | 任务书主性能目标 |
| 大规模性能 | slots `[65536]`、M `[32,4096]`、S=128，平均耗时≤155 μs | 任务书主性能目标 |
| 同机收益 | 基线减实现的均值差、中位数差均大于 0，配对均值差的 95% 置信区间下界大于 0 | 任务书计时协议 |
| 存储与流 | 当前 stream 正确，输入不变，每次输出独立，释放后活跃分配恢复 | 任务书工程及内存要求 |

功能测试覆盖全部 14 个正向输入、10 项非法输入及规定的补充检查，包含空输入、全负值、单层与多层、非二次幂页大小、大页大小、INT32 边界、动态值更新和存储重绑定。

性能按完整 `prepared.run()` 计时。实现与基线分别预热 50 次，交替测量 6 轮，每轮连续调用 200 次并在轮末完成设备同步，以该轮总墙钟耗时除以 200 得到单次耗时。计时包含 Python 提交、新输出和当次临时张量分配、设备执行及完成同步；输入生成与传输、prepare、一次性校验、CPU 标杆和首次编译在计时范围外。

主性能用例按六轮单次耗时的算术均值判定固定上限，配对收益使用 10000 次共同重采样、随机种子 20261031 和线性分位数计算 95% bootstrap 置信区间。S=64 与 S=96 的指定补充用例执行同样的配对计时并提交统计结果。

大小两组主性能输入均记录预热后的 PyTorch NPU 活跃分配峰值，计入新输出及当次临时张量，保留输入和 prepared 对象。两条 stream 各保留 3 份输出并逐份核对；重复调用 20 次，释放输出并同步后检查活跃分配恢复。大输入输出有效数据为 8388608 字节。

自验证保存逐项功能结果、泛化结果、性能原始数据、内存记录、软件环境和源码版本，形成步骤说明、精度/性能/内存报告及日志。失败、中断或缺失必测项均返回非零退出码。

## 兼容性分析

保持任务书规定的 Python 接口、INT32 类型、形状及负值语义。单层和多层输出按 M 的维数区分，prepared 对象复用遵循固定元数据与动态数据约束。不需要 ACLNN 自定义安装包。
