# 需求背景（required）

## 需求来源

本设计对应“10月社区任务-ops-math算子onnx适配”，参与账号为 [wsnidie1](https://gitcode.com/wsnidie1)。依据任务书 `ops-math_onnx_task_doc.md` 和配套 `test_cases/README.md`，在 [cann/ops-math](https://gitcode.com/cann/ops-math) 完成 ONNX 插件的 protobuf 解耦。迁移方式参考 [Issue #2892](https://gitcode.com/cann/ops-math/issues/2892) 中的既有实现。

## 背景介绍

### 现有解析方式

现有插件通过 `ParseParamsFn` 注册回调，回调接收 protobuf `Message`，转为 `NodeProto` 后遍历属性、读取节点名及输入输出列表。这使插件和 framework UT 同时依赖 protobuf 生成代码及运行库。

### 改造目标与范围

将参数解析改为 `ParseParamsByOperatorFn`：由 GE 提供 `ge::Operator`，插件读取其中的属性 JSON 和节点信息，生成与原实现相同的目标 Operator。原算子注册和设备计算路径保持。

任务范围为 **57 个插件文件、124 个“文件×算子”条目**。同一文件的不同算子、不同 opset 回调分别核对，不能只替换一个公共入口后认为整份文件完成。

任务登记范围以 `91c6c17` 为基础，改造涉及任务插件、对应 framework UT、公共工具和必要构建接线。Shape、Bernoulli 两份已迁移插件仅作头文件依赖收尾，不增加迁移条目或修改计算逻辑。当前自验使用冻结的迁移前后共同源码版本；其中 QKV 的共同属性解析补丁属于另行列明、待评审确认的专项范围，不能视作原版基线已获认可。

# 需求分析（required）

## 需求描述

完成参数解析接口和数据访问方式的等价迁移，使目标插件不再依赖 `ge_onnx.pb.h` 或 protobuf 对象，同时保持原有属性、返回值、节点名称及输入输出行为。迁移成果应能通过 framework UT，并通过迁移前后 OM 对比证明解析行为一致。

## 需求拆解

1. 回调签名改为 `domi::Status Fn(const ge::Operator&, ge::Operator&)`，注册改用 `.ParseParamsByOperatorFn(...)`。
2. 读取 `op_src.GetAttr("attribute", ...)` 返回的 JSON，使用仓内 nlohmann/json；不引入新的第三方版本。
3. 保留原算子名、opset 范围、`ImplyType`、属性映射、动态输入输出注册和拆图回调。
4. 以 Operator 构造 UT，覆盖正常、缺失、非法 JSON、边界四类场景及各自例外。
5. 在选定硬件上，用迁移前后插件分别转换、推理同一模型和输入，按任务书的精度或原负例规则判定。

# 详细设计（required）

## 算子分析

### 数学公式

本任务不增加计算公式。各算子的数学实现继续使用原拆图和 kernel；参数解析迁移应得到相同的目标属性、输入输出连接及计算路径。

### 支持数据类型

保持各插件原有 dtype 支持范围和 ONNX→GE 映射。属性载体包括 INT、FLOAT、STRING、INTS、FLOATS；本次迁移按任务约定读取 FLOAT 标量的字符串载体，整数和列表使用对应 JSON 数值或数组类型。

### 支持形状

保持原有 shape、axis/axes、格式和可选输入输出约束，不增加广播或动态形状能力。同一算子的不同 opset 若使用不同属性或张量输入，继续沿原注册分支处理。

## 算子实现

### 实现方案

解析流程为：GE 源 Operator → 原分支的属性读取与转换 → 目标 Operator 属性写入 → 原注册的算子或拆图路径。迁移只替换源信息的读取接口，保留原控制流和写入时机。

#### 3.2.1 host侧设计：

**接口与公共工具。** 各解析函数保留现有名称，参数替换为源、目标 Operator。通过 `math_onnx_plugin_util.h` 复用无 protobuf 依赖的节点名、dtype 映射、标量／列表 Tensor 和格式工具。注册中仅替换参数回调 API，其他注册项保持。

`GetOnnxInputSize`、`GetOnnxOutputSize` 优先读取源 Operator 的 `input`、`output` 槽列表，缺失时回退到 GE 描述数量。这样可保留 ONNX 的空可选槽，避免直接使用 GE 输入数量改变原 `NodeProto` 槽位语义。

**属性解析。** 原来读取属性的回调先保留默认值初始化，再遍历 JSON 的 `attribute` 数组。逐项沿用原属性名和 type 判断，不统一改变类型宽松程度；同名属性原来取首个、取最后一个或累加列表的处理顺序保持。属性和 Tensor 的写入顺序也保持，以免改变失败前已写出的内容。

| 场景 | 迁移后的处理 |
| --- | --- |
| 整个属性不存在 | 保持该分支的默认值或必需属性错误，不能统一返回成功 |
| 属性存在但 `i`／`f` 缺省 | 按 proto3 零值处理为 `0`／`0.0`，不能退回算子默认值 |
| FLOAT 标量 | 按任务约定读取字符串型 `f` 并转换，保留原浮点取值语义；非法转换返回原规定的失败状态 |
| JSON 或字段转换异常 | 原本解析 JSON 的路径记录日志并返回 `FAILED` |
| 原来不读取 JSON | 不新增 JSON 校验，保持原成功返回及固定属性行为 |
| 原来仅校验 JSON 合法性 | 保留校验；Max、Min、Xor 等不能改成无条件成功 |

**具体边界。** Cast 缺少 `to` 仍失败；不支持 dtype 时，按任务书要求使用映射工具真实返回的 `DT_UNDEFINED` 判断，修正原来永远不成立的 `-1` 判断。Squeeze／Unsqueeze 的旧 opset 继续解析 axes，V3 路径继续使用输入张量并忽略属性 JSON。除下文单列的 QKV 专项共同补丁外，Similar、Sequence 等无属性回调不添加原来没有的属性解析。

**构建接线。** 插件移除 protobuf 生成头文件及相关解析依赖；公共头只依赖 GE、注册和必要标准库。UT 放在对应算子的 `tests/ut/framework/`，使用仓内原生相对 include。必要 CMake 变更负责收集、链接这些 framework UT，不引入独立算子工程。

##### 1. 分核策略：

不涉及。Host 回调不调整设备核数或核间任务分配。

##### 2. 数据分块和内存优化策略：

不涉及。保留原 kernel 的 UB、搬运和缓存策略；本任务不设性能、内存优化指标。

##### 3. tilingkey规划策略：

不涉及。不新增 TilingData、tilingkey 或设备计算分支。

#### 3.2.2 kernel侧设计：

不涉及 kernel、tiling、算子原型修改。`ParseOpToGraphFn` 及原动态输入输出逻辑保持，不借本次迁移修复其历史计算问题。

例如，Multinomial 的原拆图对 seed、sample_size、dtype 的既有处理保持，依照官方用例的行为档验证；不在此处改拆图来获得新的随机语义。对原有模型、组件或注册问题，须区分等价迁移与兼容修订，单列修订内容、适用范围和两侧共同基线，不能用兼容实验自动扩展本次任务的修改许可。

## 支持硬件

参数解析代码为 Host 实现，不新增芯片分支。任务书允许 Atlas A2 或 Ascend 950 任一硬件验证，CANN 版本须大于 9.0.0；每组迁移前后比较使用同一硬件、环境、模型、全部输入及 ATC 参数。

本轮选定源码的完整自验证在 950PR、CANN 9.1.0 上执行，迁移前后使用相同硬件平台及验证条件。历史 A2、950 记录独立保留，不加到本轮计数中。

## 算子约束限制

原 dtype、shape、opset、可选输入输出和组件依赖均保持。迁移前能转换并推理的用例，迁移后必须满足精度规则；原环境缺失自定义后端或原用例本就非法的情况，须按声明规则保留两侧失败证据。

QKV 的共同属性解析补丁将 `head_num`、`head_dim`、`seq_length` 解析及校验同时施加于迁移前后两侧。该补丁的任务范围及共同基线是否可接受，仍须评审确认；原始无补丁失败证据保持，实验结果不等同于范围获批。

Score 的精确 meta 修订属于用例声明修订，保留原 meta、修订差异和两侧原始失败，交验收方复核。按负例规则匹配的记录只说明声明条件下两侧失败行为一致，不能称获得合法数值或正式精度验收通过。其余兼容修订同样逐项披露，不将不同源码或硬件的结果拼接为本轮通过。

# 可维可测分析

## 精度标准/性能标准

| 项目 | 验证方法 |
| --- | --- |
| framework UT | 开启 `OP_HOST_UT`，使用 Operator 构造输入；运行全部 `Onnx*PluginTest.*`，含 experimental 配置所覆盖的插件 |
| 确定性／固定 seed 随机用例 | 比较迁移前后 OM 的完整输出集合、dtype、shape 和字节，包括正负零、NaN 载荷 |
| 已声明不可复现用例 | 先有同一 OM 重复推理证据，再按官方 meta 的混合容差或行为档判定；Multinomial 还核对类别下标范围 |
| 原转换负例 | 两侧转换失败；若原 meta 声明关键字，两侧均须命中。未声明失败或单侧失败不能记为匹配 |
| 原推理负例 | 按声明检查两侧失败及归一后摘要；仅按官方允许的规则处理提前转换失败 |
| 性能、内存 | 不涉及，按任务书填写 N/A |

测试先固定模型、meta 和全部输入，再用迁移前后库分别执行 ATC、OM 推理与比较；ATC 日志同时保留实际插件加载路径及内置同名注册被跳过的记录，防止误测内置插件。FP32 精度模式按用例需要设置，但两侧必须相同。动态容量输出遵循官方工具的容量声明和执行前置零要求，比较完整设备输出，不用采样代替。

原用例全部覆盖，并补充未覆盖的 dtype、可选 IO、格式、属性值和 opset 分支。每算子非必要少于 50 例是控制验证成本的建议。用例包的模型生成器、UT、工具或 meta 如需修订，逐文件说明原因并提供代码；不放宽精度判据。

截至本次设计更新，当前选定共同源码的 **Host UT 覆盖 677 项并通过**；不同构建配置的覆盖按唯一测试项整理，不累加重复运行。950PR 双轮 OM 自验已执行 **157 项：151 项完整字节数值一致、1 项官方 Multinomial 行为例外、5 项负例规则匹配，0 项失败、0 项未执行**。三类结果分别报告，不能将 157 项均写成数值通过。实验配置下取得上述结果，也不代表 QKV 专项修改范围、Score meta 修订或正式验收已经获批。

Max 的 experimental 配置另有 **1 项额外完整字节一致验证**，与默认用例使用相同 fixture，单列为配置覆盖证据，不计入上述 157 项或扩充唯一用例数量。

## 兼容性分析

兼容重点是注册、默认值、异常返回、节点名、输入输出槽和拆图行为保持。仓内 JSON 版本不变；迁移前旧插件如因 protobuf 符号缺失需要兼容库，仅按官方 compat 工具用于旧库，迁移后库不携带该依赖。

修改公共工具或某解析分支时，回归受影响插件的四类 UT 和对应双轮 OM。源码、UT、用例修订代码、模型、ATC 命令、加载日志、输出比较及迁移自查表随验收材料交付；性能和内存模板写明 N/A。设计文档审核、生产代码评审与正式验收依各自流程办理，本设计 PR 仅提交设计说明。
