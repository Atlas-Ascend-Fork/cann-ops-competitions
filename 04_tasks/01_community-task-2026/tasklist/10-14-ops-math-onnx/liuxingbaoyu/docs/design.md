# ops-math ONNX 插件迁移设计

## 需求背景（required）

### 需求来源

本设计对应“10月社区任务—ops-math 算子 ONNX 适配”，依据任务书中的 protobuf 解耦要求，对 57 个插件文件、124 个“文件 × 算子”条目进行接口迁移。具体范围以任务书迁移清单为准，包含常规 Max 和实验目录中的 Max 两份实现。

### 背景介绍

原有插件通过 `ParseParamsFn` 注册参数解析函数，以 `google::protobuf::Message` 为入参，在插件内部转换为 `ge::onnx::NodeProto`，再读取节点属性、输入输出名称和节点名称。该方式使插件解析代码依赖 protobuf 生成头文件及对象类型。

本次改造使用 GE 提供的 `ParseParamsByOperatorFn` 接口，以 `ge::Operator` 承载节点信息。插件通过 `GetAttr` 读取属性 JSON 和输入输出名称列表，完成 ONNX 节点到目标算子的参数映射。

## 需求分析（required）

### 需求描述

迁移范围内的插件参数解析代码解除对 protobuf 对象及生成头文件的直接依赖，保持原有算子映射、属性默认值、输入输出处理和子图构建行为。

本任务属于 Host 侧框架适配，不涉及 kernel、tiling、aclnn 接口或算子原型开发。`ParseOpToGraphFn` 对应的子图构建逻辑保持原实现，不进行无关重构。

### 需求拆解

| 改造项 | 设计要求 |
| --- | --- |
| 解析接口 | 源参数由 `const Message*` 改为 `const ge::Operator&`，目标参数继续使用 `ge::Operator&`。 |
| 注册接口 | `.ParseParamsFn(...)` 替换为 `.ParseParamsByOperatorFn(...)`，保留算子名称、ONNX 版本范围和执行类型。 |
| 属性解析 | 从源算子的 `attribute` 属性读取 JSON 字符串，使用仓内 nlohmann/json 解析。 |
| 输入输出信息 | 从源算子的 `input`、`output` 列表属性读取名称及数量，保留空名称占位。 |
| 节点名称 | 使用公共函数 `GetOpName(op_src)`，保留原有写入目标属性的行为。 |
| 公共能力 | 将通用属性解析和输入输出读取能力下沉到公共工具层，供各插件复用。 |
| 异常处理 | JSON 解析及取值异常由调用方捕获，记录日志并返回 `FAILED`。 |
| Cast 失败判据 | 按任务要求，以 `ge::DT_UNDEFINED` 判断 dtype 映射失败。 |
| 单元测试 | 使用 `ge::Operator` 构造源输入，验证属性映射、默认值、异常及边界行为。 |

## 详细设计（required）

### 1. 处理流程与接口

GE 将 ONNX 节点信息转换为源 `ge::Operator`，调用插件参数解析函数。插件读取源信息、设置目标属性和端口，再由原有转换或子图构建流程继续处理。

解析接口保持各插件原有函数名称，仅替换源参数类型：

```cpp
domi::Status ParseParamsCast(const ge::Operator& op_src, ge::Operator& op_dest);
```

| 信息 | 迁移前 | 迁移后 |
| --- | --- | --- |
| 节点属性 | `node->attribute()` | 通过 `GetAttr` 获取属性 JSON，由公共工具解析后读取所需属性。 |
| 输入名称及数量 | `node->input()`、`node->input_size()` | 读取源算子的输入名称列表，以列表长度确定输入数量。 |
| 输出名称及数量 | `node->output()`、`node->output_size()` | 读取源算子的输出名称列表，以列表长度确定输出数量。 |
| 节点名称 | `node->name()` | `GetOpName(op_src)` |
| 参数回调注册 | `ParseParamsFn` | `ParseParamsByOperatorFn` |

### 2. JSON 属性解析

属性字符串通过 `op_src.GetAttr("attribute", attrs_string)` 读取，典型表示如下：

```json
{
  "attribute": [
    {"name": "axis", "type": 2, "i": 1}
  ]
}
```

公共工具负责读取和解析属性 JSON，各插件根据属性名称及原有类型条件提取所需字段，完成目标属性设置。具体默认值和必填属性判定保留在各插件中。

| 属性类型 | 类型值 | 取值字段 | 读取方式 |
| --- | --- | --- | --- |
| FLOAT | 1 | `f` | 按字符串读取并转换为 float；字段缺省时取 0。 |
| INT | 2 | `i` | 按整数读取；字段缺省时取 0。 |
| STRING | 3 | `s` | 按字符串读取；字段缺省时取空字符串。 |
| FLOATS | 6 | `floats` | 按浮点数组读取；字段缺省时取空列表。 |
| INTS | 7 | `ints` | 按整数数组读取；字段缺省时取空列表。 |

各插件保留原有的属性名和类型筛选条件。属性名或类型未匹配时，沿用原分支的缺失处理方式。取值转换仅在相应分支匹配后执行，未使用的属性保持忽略。

属性整体缺失与属性存在但取值字段缺省分别处理。例如，Flatten 缺少 `axis` 属性时取默认值 1；存在 INT 类型的 `axis` 属性但省略 `i` 字段时取 0。

重复属性的处理顺序及结果保持原有语义。

### 3. 浮点属性处理

GE 的标量浮点字段 `f` 以字符串承载，由公共工具统一完成浮点转换。字段缺省时保留原有零值语义，转换异常时返回失败，具体业务约束沿用各插件原有逻辑。

### 4. 默认值、异常及返回值

各解析函数保留原有的属性默认值、必填校验、目标属性类型及业务检查。

捕获属性解析及转换异常，记录日志并返回失败。

原本不读取节点属性的函数继续保持原行为。例如 Mean、Sum 仅使用输入名称列表，`similar_opp` 中无需参数处理的函数直接返回成功；不为此类分支额外引入 JSON 解析。

### 5. 输入输出与名称处理

通过公共工具读取源算子的输入输出名称列表，属性读取失败时返回空列表。列表长度及空名称位置均保留，用于动态端口注册和可选输入判定。

Clip V11 等具有可选输入的分支，根据输入列表长度及空字符串判断输入是否省略，不删除空项。Mean、Sum、Max 等变长输入算子由列表长度设置 `N` 并注册动态端口。

需要记录节点名称的插件使用 `GetOpName(op_src)` 写入目标 `name` 属性；`original_type`、动态端口名称和注册顺序沿用原实现。

DeformableOffsets、DepthToSpace、SpaceToDepth 等算子的目标端口格式更新逻辑保持不变。单元测试在目标算子上注册对应端口，模拟 GE 提供的目标对象。

### 6. Cast dtype 失败判据

按任务要求，使用 `ge::DT_UNDEFINED` 判断 dtype 映射失败。合法 dtype 的映射不变，不支持的 dtype 在参数解析阶段返回失败。

### 7. 文件组织与依赖

| 位置 | 职责 |
| --- | --- |
| 各算子 `framework/*_onnx_plugin.cpp` | 实现新接口、JSON 属性读取及注册方式替换。 |
| `common/inc/framework/` 公共工具层 | 提供属性解析、浮点转换、类型判断及输入输出读取能力，复用现有 dtype 映射和格式更新能力。 |
| 各算子及公共目录 `tests/ut/framework/` | 使用源 `ge::Operator` 验证对应插件解析行为。 |
| `experimental/math/asinh/framework/max_onnx_plugin.cpp` | 独立迁移实验版 Max，并单独构建和验证。 |

迁移文件使用 `graph/operator.h`、`register/register.h`、`nlohmann/json.hpp` 和公共工具头替代 `onnx_common.h`。JSON 库使用仓库现有依赖，不引入其他版本。解耦范围为任务清单中的插件解析代码，不扩展到仓库内其他未纳入本任务的插件和构建依赖。

### 8. 实验版 Max

常规 Max 与实验版 Max 注册相同的 ONNX 类型和版本范围。实验版使用独立插件库进行 OM 验证，每轮仅加载对应版本的实验插件，避免同名注册影响被测实现。

验证覆盖单输入和多输入分支，迁移前后使用相同模型、输入、数据类型及 ONNX 版本。

### 支持硬件与约束

验证平台按任务要求选择 Atlas A2 或 Ascend 950，CANN 版本大于 9.0.0，迁移前后使用同一环境。

本次迁移不扩展算子的 dtype、shape、广播能力或 ONNX 版本支持范围；各项约束沿用原插件及目标算子定义。Host 侧不新增分核、UB 分块或 tilingkey 设计。

## 可维可测分析

### 单元测试设计

单元测试直接构造 `ge::Operator`，通过 `SetAttr` 设置 JSON 字符串和输入输出名称列表，再调用迁移后的解析函数。主要场景包括：

| 场景 | 验证内容 |
| --- | --- |
| 正常解析 | 属性值、目标属性名称和类型、节点名称及动态端口数量。 |
| 属性缺失 | 默认值、必填属性失败分支、proto3 零值字段省略。 |
| 异常输入 | 非法 JSON、取值类型错误、浮点转换失败，以及原有业务校验。 |
| 边界情况 | 空列表、负值、重复属性、可选输入空名称及不同输入数量。 |
| 版本分支 | Clip、Squeeze 等算子不同 ONNX 版本对应的解析路径。 |
| Cast 特殊分支 | 不支持的 dtype 命中 `DT_UNDEFINED` 失败判据。 |

对于不解析属性的分支，单独验证其忽略属性的原有行为。涉及格式更新的测试需构造完整目标端口。常规与实验目录的同名 Max 实现分别编译、执行。

### OM 验证方法

使用任务包生成 ONNX 模型、输入及 golden，分别加载迁移前后插件完成 ATC 转换和设备推理。确定性用例比较两轮输出是否完全一致，并按用例规定独立进行 golden、dtype 和 shape 比对。

随机用例按任务规定单独记录行为；转换失败场景记录两轮错误信息，按任务允许的情形判定。变体模型与原模型分别记录，不合并为同一验证结果。

OM 覆盖范围按实际执行的算子、模型变体、输入数量和版本填写，模型生成脚本数量不等同于全部注册条目及属性分支覆盖。

### 精度、性能与内存标准

| 验收项目 | 设计标准 |
| --- | --- |
| 参数解析 | 保持原有默认值、属性映射及输入输出处理；Cast 失败判据按任务要求修正。 |
| 两轮输出 | 确定性用例的迁移前后输出完全一致；随机用例按任务规定判定。 |
| golden 精度 | 按任务包的混合容差、硬上限和匹配率要求比较，并检查 dtype、shape；整数和布尔结果精确比较。 |
| 性能 | 不涉及，依据任务文档第 3.3 节。 |
| 内存 | 不涉及，依据任务文档第 3.4 节。 |

### 兼容性与维护

保留原有 `OriginOpType`、算子映射、ONNX 版本分支及 `ParseOpToGraphFn`。公共 JSON 辅助函数不承担算子业务规则，各插件继续管理自己的默认值和校验条件，避免公共修改改变其他算子的语义。

迁移后的解析代码使用 GE 新接口及仓内 JSON 库，不再直接访问 protobuf 对象。
