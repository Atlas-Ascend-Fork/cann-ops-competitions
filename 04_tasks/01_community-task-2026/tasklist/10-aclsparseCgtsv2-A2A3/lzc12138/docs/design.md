# 需求背景（required）

## 需求来源

《10月社区任务-aclsparseCgtsv2算子开发（A2A3）》：在 Atlas A2/A3 的 ops-sparse 工程中新增 complex64 三对角线性方程组求解接口 `aclsparseCgtsv2`，功能与 C++ 接口语义对标 NVIDIA cuSPARSE `cusparseCgtsv2`。代码提交至 `cann/ops-sparse` 的 `master`，设计文档提交至 `cann/cann-ops-competitions` 本任务目录。

## 背景介绍

### 算子功能

求解 `A X = B`。`A` 为复三对角矩阵，由 `dl/d/du` 三个一维系数数组表示：`A[i,i]=d[i]`、`A[i,i-1]=dl[i]`（`i>=1`）、`A[i,i+1]=du[i]`（`i<m-1`），边界满足 `dl[0]=0`、`du[m-1]=0`。`B` 为列主序 `[ldb,n]`，求解结果原地覆盖 `B` 的前 `m` 行，`m<=i<ldb` 的 padding 保持不变。

### 现有实现现状

上游 `master` 已有 float 版本的 `aclsparseSgtsv2` 及其 `Sgtsv2Nopivot`、`Sgtsv2StridedBatch` 系列，可作为 Legacy C++ API 的调用流程与目录组织参考，但其 ABI 与算法能力不满足本任务：本任务要求 complex64、带部分主元选取、`aclsparseComplex_t*` 独立 ABI。仓内当前没有 Cgtsv2 的公开接口或实现。

### 平台与约束

目标平台为 Atlas A2/A3（DAV_2201，`arch22`），核心计算必须由 Ascend C 开发的 NPU Kernel 完成；性能仅在 910B3 上验收。禁止 CPU、cuSPARSE 或其它整算子回退。

# 需求分析（required）

## 需求描述

新增公开类型与两个接口，不修改既有 `aclsparseSgtsv2(float*)` 声明：

```cpp
typedef struct {
    float real;
    float imag;
} aclsparseComplex_t;

aclsparseStatus_t aclsparseCgtsv2_bufferSizeExt(
    aclsparseHandle_t handle, int m, int n,
    const aclsparseComplex_t *dl, const aclsparseComplex_t *d,
    const aclsparseComplex_t *du, const aclsparseComplex_t *B,
    int ldb, size_t *pBufferSizeInBytes);

aclsparseStatus_t aclsparseCgtsv2(
    aclsparseHandle_t handle, int m, int n,
    const aclsparseComplex_t *dl, const aclsparseComplex_t *d,
    const aclsparseComplex_t *du, aclsparseComplex_t *B,
    int ldb, void *pBuffer);
```

`aclsparseComplex_t` 由连续的两个 `float` 组成，通过编译期断言保证 `sizeof(aclsparseComplex_t) == 8` 且 `alignof(aclsparseComplex_t) == alignof(float)`。

参数约束：`m>=3`、`n>=0`、`ldb>=max(1,m)`；`n>0` 时 `dl/d/du/B` 非空、`pBuffer` 非空且 128 字节对齐、长度按查询值足量；`n=0` 时 `bufferSizeExt` 返回 0，执行阶段跳过求解且不要求系数、B 或 workspace。`dl/d/du` 只读，`B` 原地输入输出，没有独立 `X`、`batchCount`、转置视图或任意 stride。

## 需求拆解

1. 公共类型、接口声明与编译期布局断言；Host 侧参数校验、workspace 查询与 NPU 调度。
2. 带部分主元的复数三对角消元：按复数模长比较当前主元与相邻候选主元，必要时交换相邻方程行，同步更新全部 RHS，维护交换产生的第二上对角填充项，再对所得上三角系统回代。不得退化为无主元 Thomas 算法。
3. `bufferSizeExt -> 分配 128 字节对齐 workspace -> 执行` 的完整流程，正确处理 handle stream、workspace 生命周期与错误码。
4. 覆盖单/多 RHS、对角占优、需要 pivot、零主对角但非奇异、病态/奇异系统、边界输入、`n=0` 与 padding 保持；相同输入复跑满足确定性语义。
5. C++ UT/ST、官方 ATK 精度套件、Profiler 性能与内存统计，并按任务书交付设计与自测材料。

# 详细设计（required）

## 算子分析

### 数学公式

对每个 RHS 列 `j`（`0<=j<n`）求解：

```text
d[0]     * x[0,j]   + du[0]     * x[1,j]   = b[0,j]
dl[i]    * x[i-1,j] + d[i]      * x[i,j]   + du[i] * x[i+1,j] = b[i,j]    (1 <= i < m-1)
dl[m-1]  * x[m-2,j] + d[m-1]    * x[m-1,j] = b[m-1,j]
```

### 支持数据类型

仅 complex64，即以两个 `float` 分量（实部、虚部）表示的复数，公开接口统一使用 `aclsparseComplex_t*`；不提供 float ABI 重载，也不做隐式类型转换。

### 支持形状

运行时动态 `m/n/ldb`，单次执行内尺寸固定；不广播、不支持任意 stride。元素地址为 `B[i+j*ldb]`，有效求解区为 `[m,n]`，其余 padding 不读写。调用方保证输入连续、真实容量足够以及 `dl[0]=du[m-1]=0`；raw C ABI 无法推断 dtype、分配长度或 stride。

## 算子实现

### 实现方案

#### 总体数据流与模块划分

| 阶段 | 归属 | 输入与职责 | 输出 |
| --- | --- | --- | --- |
| 参数校验 | Host | 校验 handle、查询输出指针、`m/n/ldb`、空指针、workspace 对齐、字节与索引溢出 | 同步错误码 |
| workspace 查询 | Host | 按固定公式计算所需字节数，不读取设备数据 | `size_t` 字节数 |
| 分解 | Kernel 1 | 分块预取 `dl/d/du` 到 UB，按占优档位选择消元策略，写 workspace 因子；`n=1` 且 `m` 达并行门槛时改为全核分片占优探测，全部严格占优则跳过因子物化 | 工作对角、工作上对角、消元乘子、第二上对角填充项、主元交换标记、按需物化的缩放双浮点因子 |
| 求解 | Kernel 2 | 每个 AIV 核处理一组 RHS 列，列内完成前代、回代与按需的残差精化；严格占优输入可改走列×行块二维并行替换或并行循环归约 | 最终解（原地覆盖 `B` 的有效区） |

前代与回代合并在同一列的同一段 Kernel 内完成，省掉一次 RHS 整体往返全局内存；分解与求解之间只依赖 stream 顺序，不插入额外的全设备同步。任务书要求计时覆盖求解范围的全部 Kernel，因此 launch 数本身不是加分项，划分以访存次数与串行链长度为准。

Host 侧在 `include/cann_ops_sparse.h` 新增类型与两个声明；实现放在 `sparse/cgtsv2/`（公共校验与工具）与 `sparse/cgtsv2/arch22/`（Host 调度与 Kernel），测试放在 `test/cgtsv2/` 与 `test/cgtsv2/arch22/`，按仓内既有 CMake 模式接入，不新增重复构建目录。

#### 接口边界与错误语义

建议状态码映射（最终以仓库接口评审为准）：空 handle 返回 `ACL_SPARSE_STATUS_HANDLE_IS_NULLPTR`；查询输出指针为空、`m<3`、`n<0`、`ldb<max(1,m)`、`n>0` 时必需指针为空、workspace 未 128 字节对齐、字节或索引计算溢出时返回 `ACL_SPARSE_STATUS_INVALID_VALUE`；stream 获取或 Kernel 启动失败返回 `ACL_SPARSE_STATUS_EXECUTION_FAILED`。

校验顺序固定为：handle → 查询输出指针 → `m/n/ldb` → `n==0` 提前返回 → 数据指针与 workspace（执行接口）→ 溢出检查。这样 `n=0` 不会因未分配 workspace 被误判为错误。由于接口异步执行，Host 只能同步返回参数类错误；数值奇异等设备侧结果不承诺由同步返回值反映。

#### workspace 布局

工作区按 128 字节对齐的基址划分，全部由 `bufferSizeExt` 返回的长度覆盖，查询与执行使用同一公式：

| 段 | 内容 | 字节数 |
| --- | --- | --- |
| S0 | 快速因子：4 组 complex64 工作数组（工作对角、工作上对角、第二上对角填充项、消元乘子） | `32m` |
| S1 | 缩放因子：4 组带指数的双浮点复数（每元素 5 个 float，仅精化路径写入） | `80m` |
| S2 | 主元交换标记，每行 1 字节 | `m` |
| S3 | 缩放消元路径的行交换标记，每行 1 字节 | `m` |

总长度为 `align_up(114m, 128)`，`n=0` 时为 0。以 203 条用例最大的 `m=8192` 计约 912 KiB；workspace 随 `m` 按 114 字节/行线性增长，逐条用例把查询值、128 字节对齐后的实际分配、allocator 增量与设备 free/total 一起记录，再按任务书 §3.4 判定。所有加法、乘法与向上对齐都在 Host 侧先做溢出检查。

#### Kernel 侧设计

**分解 Kernel。** 由 1 个 AIV 主核沿 `m` 方向串行推进：第 `k` 步（`0<=k<m-1`）确定该步的消元因子，更新 `d_work[k+1]`、`du_work[k+1]` 与第二上对角填充项 `du2[k+1]`，并把这一步的工作对角、上对角与乘子写进 workspace。用户输入的 `dl/d/du` 全程只读，所有变形结果落在 workspace。

上述单行链会把每行 6 个系数变成标量全局读，是 `m` 较大且 `n` 较小时的第一个性能瓶颈。实现改为先把 `dl/d/du` 按 512 行分块用 `DataCopyPad` 预取进 UB，块内逐行推进、按块批量写回 workspace，串行链只剩寄存器级运算。

消元策略由一次全量占优扫描的结果决定，档位只在启动时按输入数据计算，不引入 case 编号、种子或公共 shape 的映射：

| 档位 | 判据（按行） | 分解动作 | 求解侧 |
| --- | --- | --- | --- |
| 强占优 | `\|d\| > 2(\|dl\|+\|du\|)` | 无主元快速消元 | 直接解算，不做精化 |
| 严格占优且裕度足够 | `\|d\| > \|dl\|+\|du\|`，且每行相对裕度 `(\|d\|-(\|dl\|+\|du\|))/\|d\| >= 10^-2` | 无主元快速消元 | `n>1` 且 `m>=1024` 时跳过精化，并可走列×行块二维并行替换；`n=1` 满足并行探测门槛时由循环归约接管，否则仍走精化 |
| 欧氏模复核准入 | L1 判据未过，且 `n>1`、`m>=1024`；改按复欧氏模 `sqrt(re^2+im^2)`（溢出安全）逐行复核 `\|d\|_2 > 0` 且 `\|dl\|_2 + \|du\|_2 <= (1-10^-2)\|d\|_2`，全部行通过 | 无主元快速消元 | 跳过精化，走与严格占优相同的免精化求解路径；任一行不通过或出现非有限值则退回下面的带主元路径 |
| 近边界严格占优 | `\|d\| > \|dl\|+\|du\|`，但存在相对裕度 `< 10^-2` 的行 | 无主元快速消元 | 残差精化，防止 float32 舍入把近边界行推出容差 |
| 其余 | L1 与欧氏模复核均不满足 | 带部分主元的复数带状消元（相邻行交换、第二上对角填充项、RHS 同步交换），并在 `m<=2048` 时物化缩放双浮点因子 | 残差精化，必要时整列切换缩放路径 |

带主元分支的第 `k` 步比较当前主元 `|d_work[k]|` 与候选 `|dl[k+1]|`，取模长较大者；若选择交换，则交换相邻两行的对角、上对角与填充项，并记录交换标记，使求解侧可以对每一列施加同一行交换。占优扫描对所有 `m` 逐行执行；L1 判据未过时，`n>1` 且 `m>=1024` 的输入再用复欧氏模逐行复核一次（判据见表中“欧氏模复核准入”行），两次都不过才进入带主元路径。缩放路径上限 2048 只限制缩放双浮点因子的物化与缩放重算，`m>2048` 时带主元消元与残差精化仍然生效，不会退回无保护的快速路径。

**占优探测的并行化。** `n=1` 且分片存在非空尾块时，分解阶段不做串行消元，而是把 `[0,m)` 按核均分成行段：每个核只在自己的行段内判定严格占优（对角分量绝对值之和大于上下对角分量绝对值之和），把结论写成 workspace 标志位，`SyncAll` 后由 0 号核汇总。全部行段严格占优即置位“无需物化因子”，分解到此结束；任一核判定失败则整体退回串行带主元路径。准入门槛为 `m>=1024` 且 `chunk=ceil(m/核数)` 满足 `(核数-1)*chunk < m`，保证每个核都分到非空行段（例如 48 核下 `m=1536` 通过、`m=1024` 因每核 22 行刚好铺满而不通过，40 核下 `m=1024` 通过）。判定与执行使用同一个准入条件，探测只减少工作量，不改变数值结果。

**求解 Kernel。** 以 RHS 列为并行单元，列内按 `k` 递增做前代（施加行交换与消元更新），再按 `k` 递减回代：`k=m-1` 与 `k=m-2` 用单上对角，更小的 `k` 同时用上对角与第二上对角，最后只写回 `B` 的有效区。`m<=8192` 时整列 RHS 常驻 UB，更大的 `m` 改用全局访存分块版本；前代按 4096 行、回代按 1536 行分块，块尾用 `DataCopyPad` 的 padding 模式处理。

上述按列路径在 `n` 小、`m` 大时受 `O(m)` 串行链限制，因此对严格占优输入再开两条并行路径。

**列×行块二维并行替换。** `n>1`、无主元、`m>=1024`、且每列能分到至少两个行块时，求解按“列 × 行块”二维切分：每个 owner 先对自己那段连续行做前代，并把它压缩成仿射传递 `x_hi = P·x_lo + Q`；0 号行块按行序把各段传递依次合成，得到每段的入口值；各段再并行回放本段解。回代用同样的分段传递，从列尾向前合成。跨核只交换每段一个复数入口值和一组 `(P,Q)`，各段在 `SyncAll` 发布后合成，不做跨核归约。owner 数由 `rowBlocks = floor(AIV 核数 / n)` 得出：`rowBlocks < 2` 或 `n>48` 时该路径不启用，否则 owner 数为 `n * rowBlocks`（例如 48 核、`n=8` 为 6 段/列共 48 个 owner，40 核、`n=16` 为 2 段/列共 32 个 owner）；核数不能被 `n` 整除时按整数行块数向下取整，剩余核不参与该路径。

**并行循环归约。** `n=1`、分解已置位“严格占优无主元”、且分片满足与占优探测相同的非空尾块判据时，求解把三对角系统按 `(dl,d,du,B)` 四个平面写进 workspace，做并行循环归约：每轮把步长加倍，用相邻两个等式消去次对角与超对角，`log2(m)` 轮后系统逐行解耦；两套平面乒乓复用，每轮之间 `SyncAll` 对齐，行段按核均分、系数按块从 workspace 读入 UB。行段是否非空与分解探测共用同一判据，避免部分核空跑却仍参与同步。

**按运行时量分发。** 只有 `m`、`n`、`ldb` 参与选择：

| 选择点 | 条件 | 分支 |
| --- | --- | --- |
| 求解驻留方式 | `m<=8192` | 整列 RHS 常驻 UB |
| | `m>8192` | 全局访存分块 |
| 求解算法 | `n=1`、严格占优、`m>=1024` 且分片有非空尾块 | 并行循环归约 |
| | `n>1`、无主元、`m>=1024`、每列至少 2 个行块 | 列×行块二维并行替换 |
| | 其它 | 按列前代/回代 |
| 列并行度 | `n>1` 且 `ldb*8` 为 64 的整数倍 | `min(n, AIV 核数)` 个核按列切分 |
| | 其它 | 单核串行，避免相邻列共享缓存行的写回竞争 |
| 免精化 | 强占优，或严格占优且每行相对裕度 `>=10^-2`、`n>1`、`m>=1024` | 分解不置精化位，跳过整轮精化 |
| 精化 | 分解标记为需要精化 | 残差回代修正后累加 |
| | `n=1`、无主元、无缩放因子 | 解析残差界通过则跳过整轮精化 |
| 缩放路径 | 精化后该列出现非有限分量且缩放因子已物化 | 该列改用缩放双浮点求解 |

#### 分核与数据分块

- 分解阶段默认是 `O(m)` 的标量串行链，只用 1 个主核执行；只有 `n=1` 的大 `m` 改走全核分片占优探测，探测本身不带跨核消元依赖，避免为并行引入额外同步。
- 求解阶段的 `O(m*n)` 主体按 RHS 列分核：列与列之间没有数据依赖；每核按 `blockIdx + k*blockNum` 步进取列，列数不能被核数整除时天然均衡。二维并行替换在同一列内再按行块切分，循环归约在同一列内按行段切分，两者都以段为单位交换少量标量，不改动列间的独立性。
- 全局访存按 32 字节对齐组织，单次 `DataCopyPad` 不超过 16 KiB，尾块使用 padding 模式避免越界。
- 系数、因子与 RHS 按分块驻留 UB；`m` 超过 UB 容量时退化为全局访存分块版本，语义不变。

#### 数值与主元策略

- 复数模长比较使用带缩放的 `hypot` 形式，避免 `re*re+im*im` 中间上溢或下溢；比较相等时固定选择“不交换”，保证确定性。
- 复数除法采用带缩放的 Smith 形式，避免分母中间量上溢；主元模长为 0 时按 IEEE 语义产生 Inf/NaN 并继续推进，不做特殊短路（见下一小节）。
- 主体按 float32 复数运算实现。为守住 `max(1e-2, 32×ULP(g_low))` 的有限值绝对误差上限，求解侧对需要精化的档位做一次残差回代精化（迭代改进）；精化后仍出现非有限分量且缩放因子已物化时，该列整列改用带指数的双浮点缩放运算重算。严格占优是否免精化由逐行相对裕度 `>=10^-2` 决定：裕度不足的行可能被 float32 舍入推到容差边界，仍走精化；该判据只看输入系数，不看用例特征。欧氏模复核沿用同一 1% 裕度：严格行对角占优使每个 Gershgorin 圆盘排除零点，乘子满足 `|l_i|·|u_i| < 1` 且 `(1-|l_i||u_i|)^{-1}` 的增长有界，1% 裕度约比 float32 量级的比较误差大四个数量级；复核只决定“是否物化主元标记与走精化”，不再改变接口、主元策略与验收口径，任一非有限或边界不满足即退回精化。
- 全程不依赖原子累加或跨核归约，同一输入与配置下复跑结果一致。

#### 奇异与非有限输入

奇异系统要求不崩溃、不越界。实现按 IEEE 语义传播：除零产生 Inf/NaN 并继续走完同一段 Kernel，不做特殊短路、不回退、不越界；接口是异步的，同步返回值不承诺反映设备侧数值奇异。NaN/Inf 的分类与符号由独立特殊值套件按实际输出检查，不作为常规数值精度通过依据。

## 支持硬件

| 平台 | 功能与精度 | 性能验收 |
| --- | --- | --- |
| Atlas A2 910B3 | 是 | 是 |
| Atlas A2 910B4 | 是 | 否 |
| Atlas A3 任务环境具体型号 | 是 | 否 |

各平台分别记录完整 SoC 型号、CANN、驱动、固件、代码提交与测试结果；单一平台的结论不外推到其他型号。

## 算子约束限制

- 仅 complex64；仅连续一维系数与列主序 `B`；不支持广播、转置视图、任意 stride 或 batch 维度。
- `m>=3`、`n>=0`、`ldb>=max(1,m)`；调用方保证 `dl[0]=du[m-1]=0` 与缓冲区真实容量。
- workspace 必须在异步执行结束前保持有效，且由调用方按查询值足量分配、128 字节对齐。
- 数值奇异不保证同步错误码；不得把非有限输出当作精度通过。

## 兼容性分析

新增类型与两个符号，与既有 `Sgtsv2(float*)` ABI 独立，不修改其声明；公共 Host 代码若与 A5 版本并行合入，按实际合入顺序处理冲突并做交叉回归。设计阶段不引入新的构建体系，沿用 `sparse/<算子>/archXX`、`test/<算子>/archXX` 组织。

## 风险与未决事项

1. 非严格占优输入的消元链仍是串行，只能靠分块预取降低单行代价；`n=1` 的大 `m` 通过“跳过分解 + 并行循环归约”绕开该链，`n>1` 通过二维并行替换把串行段限制在行块内，两条路径都以严格占优为前置条件（`n>1` 还要求每行相对裕度足够），因此非占优与近边界输入仍是主要耗时来源，需用 Profiler 逐档验证分块尺寸与核数配置。
2. float32 复数运算在病态矩阵上可能仍不满足 ULP 绝对上限，精化与缩放路径的触发率需以实测统计确认；该路径不改变接口与验收口径。
3. workspace 布局与错误码映射需与 ops-sparse 现有 Legacy API 评审对齐；本文为设计提案，未包含设备精度或性能结论。
