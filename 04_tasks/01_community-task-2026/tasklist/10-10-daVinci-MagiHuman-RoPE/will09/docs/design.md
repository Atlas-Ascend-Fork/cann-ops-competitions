# 详细设计（required）

## 数学语义及接口依据

令偶数 rotary dimension 为 R、head dimension 为 D，R≤D，h=R/2。基线仅对前 R 维执行 half 旋转，尾部保持不变。构造 D×D 矩阵 M：

```text
M[0:h, h:R] = I
M[h:R, 0:h] = -I
其余元素为 0
```

对行向量 x，有 `x @ M = [-x[h:R], x[0:h], 0]`。将 cos 前 R 维保持原值、尾部补 1，将 sin 前 R 维保持原值、尾部补 0，得到 `cos_full/sin_full`；计算 `x*cos_full + (x@M)*sin_full`，数学上等价于前缀旋转加原尾部。

使用 `torch_npu.npu_rotary_mul(x, cos_full, sin_full, rotary_mode='half', rotate=M)`。依据为 [op-plugin 官方文档](https://gitcode.com/Ascend/op-plugin/blob/master/docs/zh/custom_APIs/torch_npu/torch_npu-npu_rotary_mul.md)，并已核对安装 wheel 的真实 schema 及 `rotate` 的 `input @ rotate` 语义，A3 独立调用成功。数学等价和单次逐元素相同不替代完整模型数值与质量验收。

## 路线选择的依据

本模型 R=96、D=128，原前缀切片的最后一维长度与实际存储步长不同；后续还需将结果与 32 维尾部拼接。整头路径使用原连续 Q/K，在一次融合调用中保持尾部，不引入 Q/K 特征重排，也不依赖推理缓冲区的原地改写权限。真实输出连续，因此下游 Attention 的 `.contiguous()` 无需为本次结果新增复制。

当前已验证的优势是：改动可集中在模型内 RoPE 准备和调用边界，保留原非原地接口；完整原始轨迹的候选输出一致；准备成本及实际 FA 消费者加入后局部收益仍成立。相对准备复用和前缀回写，矩阵路线有更明确的局部收益依据。端到端收益、正式质量及峰值内存仍待证明。

只对四对真实输入做的独立设备采样中，原路径有 32 条 kernel 记录，矩阵路径 8 条，联合 `npu_mrope` 4 条；对应设备累计约 920.495/605.564/918.076 us。矩阵路径每个输入只对应一条设备 kernel 记录，未因公式写作 `x@M` 而出现额外独立 kernel；联合路径虽调用更少，实际设备耗时仍较高。该采样包含 profiler 开销，只解释本次局部路线选择，不外推端到端收益。

联合候选的 cache 按 `[cos_half, sin_half]` 排列，identity positions 只查找每个 token 已算好的系数行，没有用一维位置重新生成多模态坐标。这使比较保持了原 Fourier 语义；淘汰依据是实测耗时，而非误认为 partial 维度必然不适配。

## 1. 主候选：整头矩阵旋转

| 位置 | 拟定改动 |
| --- | --- |
| 模型初始化/首次准备 | 根据配置和实际 R、D 构造 M，作为非持久 buffer 随模型迁移 device/dtype，不进入权重文件；不在层循环中重复生成。不硬编码 96/128。 |
| `DiTModel.forward` | 保留原 Fourier 计算和检查；在原有层外 cos/sin 展开处补齐至 D，形成连续 `[1,S,1,D]` 系数，将系数和 M 沿既有 RoPE 参数传入各层。cond/uncond 各自使用当前序列的系数。 |
| `Attention.forward` | 接收显式携带 M 的模型内部 RoPE 参数；Q/K 在原有逆排列后调用整头融合路径，不改 QKV 拆分、Q/K norm、V 或 attention。保留原两项 tuple 和原张量调用方式。 |
| `apply_rotary_emb_npu` | 增加可选 `rotate` 参数；有受支持矩阵且形状匹配时整头调用，没有矩阵时保留原完整/partial 实现。返回新输出，不修改输入，不引入前缀回写。 |

第一阶段限定已运行的单设备 BF16 推理、非 interleaved、受支持 BSND 布局；R=D 沿用原完整融合路径，其他有效输入保持原路径。按实际调用检查系数和矩阵的维度、dtype、device 及广播关系，不增加热路径 `.item()`、张量 hash 或设备同步，不用捕获所有运行异常来静默回退。

M 在实测 D=128、BF16 时为 32 KiB。两分支补齐后的 cos/sin 按实测 S 合计 4,161,024 字节（约 3.97 MiB）；这是系数自身大小，非模型峰值内存。初版每次 forward 在层外准备系数即可，先隔离验证矩阵路径的端到端收益，避免同时改动 pipeline、adapter 和坐标传递。正式计时包含本次请求的矩阵与系数准备成本，不把准备移出测量范围。

## 2. 辅助候选：按分支复用静态准备

只有主候选完整生成结果支持继续优化且额外收益值得改动时，再实现请求局部的 cond/uncond 两个准备槽。固定上游的 `SingleData.coords_mapping` 依赖网格、有效音频/文本长度、参考网格、offset 和 `coords_style`，不读取 latent 数值或 timestep；两分支文本长度不同，不能共用系数。

槽位描述必须覆盖有序样本的完整 CPU 几何元数据、patch/坐标规则、模型、设备、坐标生成 dtype、bands dtype 和最终 dtype，任一依赖改变即失效。未传上下文、训练、learnable bands、自定义坐标或不能证明描述完整的路径沿用原计算。形状相同和 `data_ptr` 相同不构成命中依据。

未命中时保留坐标 dispatch、原 Fourier 变换及有效性检查，完整准备成功后才发布最终系数；命中时在 `MagiDataProxy.process_input` 跳过坐标准备，在 adapter/model 跳过系数准备。动态特征、token 打包、modality/attention 元数据、投影及 `saved_for_output` 仍逐次更新。上下文仅存本请求两份最终系数和 CPU 描述，结束或异常即释放，不缓存完整打包对象或 Q/K，不引入全局缓存。

固定几何和 dtype 时目标为准备次数 64→2，模型前向仍为 64 次。87 ms 回放差值提示该项量级较小，不以次数下降宣称整段生成提速；若实际增加传递复杂度却无可辨收益，可以不交付此辅助候选。

## 3. 回退与数值边界

保留原完整/partial rotary、interleaved 和非融合回退语义；奇数 R、R>D、cos/sin 不匹配等非法输入给出明确异常。对外 helper 保持非原地行为，输入 Q/K、源 QKV、V 及未旋转尾部不被修改。不扩展到 sequence parallel，不添加通用缓存或独立算子工程。

矩阵主候选若在真实 Q/K 或完整生成中出现精度退化、累计耗时不占优或内存异常，即撤回该候选并保留原路径；设计允许随实测修订。当前已因负收益撤下前缀回写，不再为该路线补尺寸扫描。
