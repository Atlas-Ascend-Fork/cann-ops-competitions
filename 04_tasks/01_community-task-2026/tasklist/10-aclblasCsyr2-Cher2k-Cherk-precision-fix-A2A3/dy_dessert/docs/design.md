## 背景介绍

### 现有实现及问题

三个接口均采用列主序，在原输出矩阵上更新`uplo`指定三角。修复前，Csyr2 LOWER的对齐写回会把对角之前的非操作前缀一起写回；即使数学上加零，也会改变负零符号或NaN载荷。最初专项探针400次调用中16次出现非操作区改变。

| 接口 | 实现目录 | 计算形式 |
|---|---|---|
| Csyr2 | `blas/syr2/arch22/` | Vector列组、逐段写回 |
| Cher2k | `blas/her2k/arch22/` | Cube乘法与Vector后处理；小矩阵另有回退 |
| Cherk | `blas/herk/arch22/` | Cube、Vector tiny及精确回退等多路径 |

任务要求另一三角与前导维padding保持输入比特位；不能用整块覆盖后恢复的方法满足检查。精确裁剪后还须消除逐列同步开销，并解决操作区相消、极值与非有限输入问题。

### 功能分析

| 接口 | 公式 | 标量与对角语义 |
|---|---|---|
| Csyr2 | `A += alpha*x*y^T + alpha*y*x^T` | alpha复数；不共轭；对角虚部参与正常计算 |
| Cher2k，OP_N | `C = alpha*A*B^H + conj(alpha)*B*A^H + beta*C` | alpha复数、beta实数；对角虚部置零 |
| Cher2k，OP_C | `C = alpha*A^H*B + conj(alpha)*B^H*A + beta*C` | 同上 |
| Cherk，OP_N/OP_C | `C = alpha*A*A^H + beta*C` / `alpha*A^H*A + beta*C` | alpha、beta实数；对角虚部置零 |

# 需求分析（required）

## 需求描述

保留公开接口、合法形状、返回码与quick return语义，修复三算子非操作区写入，并按任务书完成操作区混合容差与性能验证。A2和A3均须验证精度及bit一致，正式性能门禁使用910B3。

## 需求拆解

1. 复用`include/cann_ops_blas.h`现有接口，不增加平行API；Host校验覆盖非法枚举、尺寸、步长、前导维、handle与指针等约束。
2. 非操作三角与padding不作为计算输入，不写回，不在覆盖后拷回原值。选中三角、对角与合法no-op分别按接口约定处理。
3. 支持复数COMPLEX64，合法`lda/ldb/ldc` padding以及Csyr2正负步长；不要求前导维等于n。
4. 操作区按固定任务书判据验证；参考环境固定，不能为单个失败用例挑选更容易通过的参考或放宽阈值。
5. 改动集中于arch22与对应测试；不修改arch35实现。不依赖CPU执行生产计算。
6. 使用原始任务CSV与独立bit探针；性能按完整调用中计算kernel的耗时求和，不能只统计最快一段。
7. 不引入常驻、与问题规模无关的Device缓存；A3未实测前不得声明双机型验收完成。

# 详细设计（required）

## 算子分析

### 数学公式与内存区域

公式见功能分析。列主序地址为`M[i+j*ld]`，分配范围`ld*n`个复数。

| 区域 | UPPER | LOWER | 检查 |
|---|---|---|---|
| 操作区 | `0<=i<=j<n` | `0<=j<=i<n` | 实虚部分别混合容差 |
| 非操作三角 | `i>j` | `i<j` | 与调用前逐bit一致 |
| padding | `n<=i<ld` | 同左 | 与调用前逐bit一致 |

### 支持数据类型

输入输出为`aclblasComplex`，由两个float32分量构成。控制参数与标量的归属沿用现有接口，既有Host/Device标量处理路径不能混淆。

### 支持形状

`n,k>=0`；Csyr2要求`lda>=max(1,n)`，非零步长支持负值，`inc=0`按接口报错。Hermitian接口在OP_N时输入前导维至少为`max(1,n)`，在OP_C时至少为`max(1,k)`；`ldc>=max(1,n)`。零规模和标量no-op沿用既有提前返回约定。矩阵乘法输入形状随trans选择，不引入一般ND广播语义。

## 算子实现

### 实现方案

#### 3.2.1 Host侧设计

- 保留接口校验与返回码；在已校验的几何条件下选择原有或复用的arch22计算路径。
- Csyr2 LOWER列组选择同时考虑实际可用Vector核数与UB容量预算，核数不超过资源上限。新增列组按资源公式分派，不增加按CSV编号或离散n值的调优表；不适用的步长、规模继续走既有通用路径。
- Cherk n=32/64的适用小矩阵路由复用已有transpose实现，保留其他规模路径与极值回退。Host选择顺序同时检查tinyVector与tinyTranspose，防止前者抢先命中。n=64的缓冲压缩后才启用该实现。
- Cher2k对满足既有OP_C direct路径条件的输入放开不必要的n整除限制；K对齐契约不变。producer对真实n/k裁剪、尾块清零，consumer对真实n裁剪。OP_N后处理另行使用成熟的重排与向量处理方案，不把OP_C的路由结论套用到OP_N。
- 不增加Host侧同步来规避kernel内部事件问题。

#### 3.2.2 Kernel侧设计

**一、选中三角的精确写回**

Csyr2的`CopyOutFloats`、`CopyOutCols`等写回函数按列求有效起止位置。遇到不对齐头部时，使用整数位搬移准备短头，头和主体分开发DMA，只提交选中三角。另一三角、padding不参与读改写。LOWER选中区允许既有原子累加，但原子范围必须裁剪；不能对非操作前缀原子加零。

Cher2k partial/direct后处理以及Cherk direct、OuterK2等写回同样使用真实有效列段。Hermitian对角虚部在有效输出内置零。非对角块可沿用二维DMA；对角块只提交选中部分。

**二、Csyr2 LOWER列组、UB与流水**

新增实现位于`csyr2_lower_direct_eight.h`，由`csyr2_kernel.cpp`按资源条件选择。定义`F=ceil_align(2*n,128)`个float、`B=4*F`字节，各模式总预算包含输入、输出、索引与短头空间：

| 列组与槽数 | UB预算（字节） | 用途 |
|---|---|---|
| 4列、4输出槽 | `20*B+8512` | 中小规模增加可重叠的计算/写回 |
| 4列、2输出槽 | `12*B+6464` | 兼顾列组复用与UB容量 |
| 8列、1输出槽 | `12*B+5440` | 容量边界处保留列组复用 |
| 2列、2输出槽 | `8*B+6464` | 较大规模控制UB占用 |

910B3本次UB容量为196608字节。4列4槽在n=1074时占182592字节，n=1152时占192832字节；可选bank间距也独立计入容量检查。所有模式先满足容量条件再启动，超出范围不冒用该缓冲布局。

列组共用输入与系数，短头准备批量处理，减少逐列V/S/MTE3握手。小规模采用连续列组分配并按组边界取整；核数变化与工作量同时核验，不凭最大/平均负载比直接推导收益。

事件与所有权：MTE2完成后通过MTE2→V使用输入；初始化索引在V→S握手后才允许标量访问。输出槽`slot=issued%Slots`，V→MTE3使用同一槽号；复用前等待该槽MTE3→V，收尾等待所有已发槽并完成V→S后才恢复非原子状态。最多4槽，仅使用编号0..3，槽内短头空间互不覆盖，未完成DMA的输出不被下轮计算重用。

同时删除旧窗口LOWER路径中“UB先加旧A、随后再原子加到旧A”的重复累加。统一保留一次旧值贡献，避免数值错误及输入临时区被误覆盖。原子转读改写与系数前移等早期候选实测无收益，均未合入。

**三、Cherk tiny与对角store复用**

小矩阵复用已有逐列transpose内核，替代并行度不足的路径。n=32实测由4块切换为32块；n=64在本机使用40块。n=64将整矩阵输出缓冲改成单列复用，并让扫描平面与寿命不重叠的product缓冲别名，总UB从247808降为182784字节，低于192KiB容量。

LOWER对角tile的写回把逐列同步改成一次V→S、批量准备各列短头、一次S→MTE3后逐列提交。短头用64位复数原始位搬移，头长度与原32位分量表达字节等价；算术、UPPER及非对角二维DMA不随之改变。

**四、极值、非有限与相消**

Cherk有限极值使用已有28-limb整数累加回退，避免中间乘积溢出或严重相消。Inf/NaN分类在`cherk_nonfinite_class.h`按固定BLAS复数表达式求值图传播，区分有限值、零、正负Inf及NaN；不能只看最终数学实数公式，也不能把两侧同为非有限当作充分正确性证据。

tiny输入扫描用整数位变换识别绝对值达到`2^126`、Inf或任意NaN载荷；Compare掩码转标量读取前明确完成V→S握手。8/16/32/64相关路径保持统一检测与回退。特殊输入回退使用单写者，避免多个核通过标量GM写触及同一缓存行时破坏padding场景；正常输入的并行DMA路径不改为串行。

Cher2k的小n长k严重相消使用既有精确累加路径，其他输入保留Cube/Vector实现。所有回退在NPU上执行，不用Host计算冒充设备结果。no-op不得为重新舍入输出而写C。

**五、复用来源与范围**

成熟实现对照来源为`billion4562/ops-blas`分支`codex/triangular-bitwise-a2a3`，固定提交`6f4ba0f78b303366011ce376b23521dbab43cd5b`。按机制审查后局部复用，保留原版权与CANN许可证；不整文件覆盖，不以公开PR自述的通过率替代本项目复测。最终联合结果均来自本项目的同版本库。

## 算子约束限制

合法padding、负步长、无效参数与quick return须保持接口契约。UB别名只用于生命周期不重叠的数据；不引入与n/k无关的常驻Device缓存，不采用“覆盖另一三角再恢复”的方案。极值回退优先保证契约，不把异常输入路径的速度当作常规性能成绩。

# 可维可测分析

## 精度标准/性能标准

操作区实虚分量分别使用`atol=rtol=2^-13`，逐元素检查`abs(actual-golden)<=atol+rtol*abs(golden)`；整体匹配比例至少0.99，最大绝对误差满足任务书`max(1e-2,32*ULP)`上限。Inf/NaN按固定标准的分类规则处理。非操作三角、padding及no-op缓冲按原始位比对，通过率必须100%。

Csyr2实际金标为arch22测试中的`Csyr2Golden`，按Netlib ssyr2列循环扩展复数计算：先形成`alpha*y[j]`与`alpha*x[j]`，不跳过零列；不能把未使用的同名辅助参考当作运行中的金标。Cher2k/Cherk固定使用既有`TRIANGLE_GOLDEN_FP64=1`及Netlib BLAS3.10.0环境，本轮没有为167切换参考或免除非有限检查。

正式性能为910B3平均计算kernel耗时，门槛`GPU基准毫秒*1000/0.8`微秒。100次预热后采60次有效样本，连续更新C，每次同步；多kernel完整Task求和再除以60。性能测试独占NPU，不与精度进程或外层重复profiling并行。

## 兼容性分析

保持接口、列主序、标量模式与异步调用契约；通用路径承接不满足快速路径资源条件的输入。新增路径均以实际内核名、块数、构建源码和加载库定位，不能仅由源码分支推断运行路径。极值与非有限构造测试同时覆盖路由和输出位保护。

A2完整备份已在本地逐项校验，1940源码文件从备份恢复后重新编译通过，恢复库bit600×2与Cherk特殊值144通过。恢复验证补充可复现性证据，不替代原始全量性能测试。

### 双平台复测说明（A2 910B3 / A3 Ascend910_9362）

1. **同一份源码，两次独立构建**：A3 从已验证的 A2 源码恢复（1940 文件逐哈希一致）后，以 `SOC_VERSION=ascend910_9362` 重新配置与编译；未使用 A2 的二进制跨平台顶替。两侧构建返回码均为 0。
2. **参考与阈值完全一致**：两侧共用固定 Netlib BLAS 3.10.0 与 `TRIANGLE_GOLDEN_FP64=1`，输入配方、随机种子、精度阈值与判据未做任何平台差异化；也未在任一平台为个别用例切换参考或放宽阈值。
3. **证据形态一致**：两侧都保留三个算子的完整 gtest XML、夹具 XML、两套 bit 日志、特殊值日志、被测库 SHA256 与 `ldd` 实际加载路径；验收人可按 02 目录的脚本在同型号机器上复现。
4. **差异只体现在环境与性能**：CANN 均为 9.1.0，驱动 A2 为 25.5.0、A3 为 25.5.5；逻辑设备均为 0。A3 未采正式性能，故性能结论只来自 A2 两轮原始记录。
5. **库哈希不可跨平台比对**：这是编译目标与路径差异所致，不是功能差异；功能等价性由"同一提交 + 同一规范化源码指纹 + 两侧各自的实测结果"共同保证。
