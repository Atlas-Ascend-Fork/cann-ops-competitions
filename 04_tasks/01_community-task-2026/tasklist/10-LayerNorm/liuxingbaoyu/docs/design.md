# 双分支 LayerNorm 算子设计文档

# 需求背景（required）

## 需求来源

本需求来自 10 月社区任务“双分支 LayerNorm 算子开发”。算子名称为 `DualAffineLayerNorm`。

## 背景介绍

### 双分支 LayerNorm 算子开发

同一输入分别执行两次 LayerNorm 时，两条分支会重复计算行均值、方差和归一化结果。本算子使用 Ascend C 将两条分支融合，共享一次统计量及归一化计算，再分别应用两套独立的仿射参数，输出两路结果。

目标是减少重复归约、输入访问及算子调用开销，同时满足 FP16/BF16 精度、零显式全局工作区和框架工程化接入要求。

### 现有方案分析

任务提供两种对比基线：分别调用两次 LayerNorm，以及通过框架算子共享 FP32 统计量后分别执行两路仿射。前者存在重复计算，后者包含多个算子调用及中间张量。本设计采用单次融合内核调用，在片上完成中间计算。

### 算子功能分析

| 参数 | 含义 | 类型 | 形状及约束 |
| --- | --- | --- | --- |
| x | 两条分支共享的输入 | FP16 / BF16 | `[N,H]`，ND 连续 |
| gamma1、beta1 | 第一路缩放与偏置参数 | 与 x 一致 | 各为 `[H]` |
| gamma2、beta2 | 第二路缩放与偏置参数 | 与 x 一致 | 各为 `[H]` |
| epsilon | 数值稳定项 | float 属性 | 默认 `1e-5`，范围 `[1e-7,1e-2]` |
| y1、y2 | 两路归一化输出 | 与 x 一致 | 各为 `[N,H]`，独立连续存储 |

仿射参数沿 N 维复用，仅支持定义中的 `[H]` 参数形式，不扩展为通用广播。

# 需求分析（required）

## 需求描述

使用 Ascend C 实现双分支 LayerNorm 前向融合算子，支持 `1≤N≤4096`、`1≤H≤8192`，包括非对齐 H。统计量、归一化及仿射运算均使用 FP32，最终转换为输入类型。

提供完整 ACLNN 算子工程、两阶段 API、独立 C++ 调用样例及 PyTorch NPU 封装，同时提供 Kernel 直调入口进行交叉验证。计算和数据搬运在 NPU 上完成，使用调用方当前 stream，不修改输入。

## 需求拆解

1. **功能与精度**：两条分支共享统计量，支持 FP16/BF16、非对齐尺寸、大偏移小方差、常量行及 H=1。
2. **执行效率**：通过融合计算和按行并行减少重复计算，满足 10 个指定性能用例的耗时目标。
3. **内存控制**：显式全局工作区为 0，不创建全尺寸 FP32 中间张量；每次调用分配两份独立输出。
4. **工程接入**：提供 OpDef、shape/dtype 推导、tiling、ACLNN 和直调入口，以及安装至用户目录的安装包。
5. **输入与生命周期检查**：统一校验接口元数据和属性，满足多 stream、提前释放输入、重复调用及输出独立性要求。

# 详细设计（required）

## 算子分析

### 数学公式

对第 r 行，沿最后一维 H 计算：

```text
mu[r]       = sum(x[r,j]) / H
variance[r] = sum((x[r,j] - mu[r])²) / H
z[r,j]      = (x[r,j] - mu[r]) / sqrt(variance[r] + epsilon)
y1[r,j]     = cast(z[r,j] * gamma1[j] + beta1[j])
y2[r,j]     = cast(z[r,j] * gamma2[j] + beta2[j])
```

其中 `0≤j<H`，方差分母为 H，`cast` 表示转换为 x 的类型。两条分支共享同一个 z，不重复计算均值和方差。

### 支持数据类型

输入和输出支持 FP16、BF16，五个输入的数据类型必须一致。输入搬入片上后转换为 FP32，完成全部中间计算，再将两路结果分别转换为原类型。

### 支持形状

x 为二维 `[N,H]`，四个仿射参数均为一维 `[H]`，输出形状与 x 相同。支持 H=1，以及 H=7、65、127、1537、8191 等非对齐尺寸。连续但具有非零存储偏移的输入属于合法输入。

## 算子实现

### 实现方案

整体采用“按行分核、行内共享统计量、依次执行两路仿射”的方案。每行由同一 Vector Core 完成，均值、方差和归一化结果保留在片上，不进行跨核归约。

#### 3.2.1 host 侧设计

**接口注册与推导。** 注册五个必选输入、两个输出和 epsilon 属性。两个输出的 shape、dtype 均由 x 推导，格式为 ND。

**参数校验。** `prepare`、`run`、`run_direct` 复用相同的校验规则：输入数量为 5；所有输入位于同一 NPU 设备；维度、dtype、连续性、尺寸满足接口要求；属性容器为字典且只允许 epsilon。epsilon 必须为合法数值，拒绝字符串、布尔值、NaN、Inf 和越界值。输入值域是接口前提，不通过回传 CPU 扫描数据进行计算或校验。

**分核策略。** 根据平台可用 Vector Core 数量及 N 确定使用核数，将完整行尽量均匀分配给各核，不能整除时前若干核多处理一行。N 较小时减少启动核数，避免为了占满核心引入跨核同步和工作区。

**分块与缓冲。** 根据 H 和实际可用 UB 容量规划行内缓冲，优先保留一行归一化结果，仿射参数和输出可分块处理。tiling 传递 N、H、行分配、块大小及 epsilon 等必要信息；ACLNN 和直调入口复用同一份 tiling 逻辑。

**分支规划。** 按 FP16/BF16 选择内核类型；H=1 使用直接输出 beta 的路径，其余尺寸使用通用行归约路径。对齐差异由搬运长度和尾部掩码处理，不为每个测试 shape 单独设定计算逻辑。

#### 3.2.2 kernel 侧设计

内核按照 Init、CopyIn、Compute、CopyOut 的流程执行：

1. **CopyIn**：搬入当前行，转换为 FP32；按需搬入两路仿射参数。
2. **共享统计量**：完成均值及中心化平方和归约，方差按真实 H 求平均。避免采用 `E[x²]-E[x]²`，降低大偏移小方差输入的消减误差。
3. **归一化与仿射**：得到共享 z 后依次计算两路输出，复用临时缓冲，保留 z 直到两路均完成。
4. **CopyOut**：转换为原输入类型，仅将有效元素写入各自输出。

数值处理采用以行首元素为参考值的中心化方式：先计算 `d=x-x[r,0]`，再用 `d-mean(d)` 得到中心化结果，与原公式数学等价。常量行的 d 精确为零；对这类行直接输出对应 beta，H=1 同样直接输出 beta，以满足精确输出要求。

地址按照真实行宽计算：x 和输出的元素偏移为 `r*H+j`，仿射参数偏移为 j。输入地址使用张量实际数据起点，保留存储偏移；UB 中的补齐长度不作为 GM 行步长。非对齐搬运只访问有效元素，补齐位置不参与归约，也不写回 GM。

#### 3.2.3 接口与工程设计

| 接口或组件 | 设计职责 |
| --- | --- |
| `prepare(inputs, attributes)` | 校验输入并准备执行元数据，不执行算子计算，不缓存输出供后续调用复用 |
| `run(inputs, attributes)` | 正式验收入口；分配两份新输出并调用本题 ACLNN API，返回 `(y1,y2)` |
| `run_direct(inputs, attributes)` | 使用相同校验和 tiling 逻辑直调 Kernel，供结果交叉验证 |
| ACLNN 第一阶段 | 校验描述、准备执行计划并查询工作区大小；本设计显式全局工作区为 0 |
| ACLNN 第二阶段 | 在调用方传入的 stream 上提交执行 |
| 工程交付 | Ascend C 内核、OpDef、推导与 tiling、API、C++ 样例、PyTorch NPU 封装、构建及私有安装脚本 |

两种执行入口均使用当前 stream，并通过框架分配器的 stream 生命周期管理机制保护异步执行期间使用的存储。不得把 stream 或输入、输出设备指针固化在跨调用共享状态中。C++ 调用方负责提供有效设备指针、正确 ND 描述及不重叠的输出存储。

#### 3.2.4 内存设计

均值、方差、归一化行和仿射临时值均存放于片上。UB 预算包含行数据、FP32 中间值、仿射块、输出块及归约临时空间，由实际平台容量约束；采用缓冲复用和分块控制峰值，不将完整中间结果写入全局内存。

两路输出总字节数为 `2 × N × H × 2 = 4NH`。显式全局工作区预算为 **0 字节**，活跃张量分配峰值增量上限为 `4NH + 16 KiB`。UB 不计入该分配器指标。运行时已预热、输出释放并同步后，活跃张量分配须恢复至调用前水平。

## 算子约束限制

- 只包含前向计算，不提供反向接口。
- x 必须为有限值且 `abs(x)≤10000`，仿射参数绝对值不超过 8。
- 不支持空输入、超出规定范围的 N/H、非连续布局、FP32 输入或混合 dtype。
- 输出必须与输入处于同一设备，两路输出之间及输出与任一输入之间均不得共享底层存储；输入内容保持不变。
- 安装包安装到用户目录，不覆盖系统 CANN；其他软硬件版本需重新验证。

## 兼容性分析

本算子为新增算子，不涉及已有算子行为变更。ACLNN 和 Kernel 直调入口保持相同的输入约束、数学语义与输出要求；支持范围限定于上述目标环境，不增加其他类型、布局或平台的兼容分支。
