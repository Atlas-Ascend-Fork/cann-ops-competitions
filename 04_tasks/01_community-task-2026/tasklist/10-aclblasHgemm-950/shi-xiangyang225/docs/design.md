# 需求背景

## 需求来源

10月社区任务：在 Atlas 950PR 上开发 `aclblasHgemm`，补齐 ops-blas 的半精度矩阵乘接口。接口参数和运算语义参考 cuBLAS `cublasHgemm`，采用 Ascend C kernel 直调，代码纳入 ops-blas 的 GEMM 算子族。

## 背景介绍

GEMM 是矩阵运算的基础。950 目标实现需要处理列主序、转置、前导维填充和标量分支，并以任务提供的精度和 GPU 性能基线验收。复用仓内 arch35 GEMM 的分块、调度和构建框架，针对 FP16 输入输出扩展计算路径；实际可复用部分以目标仓版本和上板验证为准。

# 需求分析

## 需求描述

实现 `C = alpha * op(A) * op(B) + beta * C`，A、B、C 和 Host 侧 alpha、beta 均为 FLOAT16。`op` 支持 N、T、C；实数情况下 C 与 T 相同。矩阵按列主序存储，支持合法的 lda、ldb、ldc 填充，C 原地输出。

## 需求拆解

1. 在公共头文件增加 `aclblasHgemm` 声明，保持 handle、参数顺序与任务书一致，通过 handle 所绑定的 stream 启动 kernel。
2. 覆盖常规矩阵乘、零维、alpha/beta 特殊值、合法填充、错误参数与 Inf/NaN。
3. 适配 950PR；依据任务书使用 FP32 参考计算并转换为 FP16 检验，完成全部用例和性能验证。

# 详细设计

## 算子分析

对 `0 ≤ i < m, 0 ≤ j < n`，计算 `C[i,j] = alpha * sum_p(op(A)[i,p] * op(B)[p,j]) + beta * C[i,j]`。列主序元素地址为 `base + row + col * ld`；`op=N` 用原索引，`op=T/C` 交换行列索引。矩阵维度、各转置组合及最小前导维按任务书约束检查。

## 算子实现

### Host 侧

1. 校验 handle、转置枚举、维数、前导维及 alpha/beta 指针；alpha/beta 判空先于 m/n 零维短路。异常返回任务书规定的状态码。
2. m 或 n 为零时返回成功，不访问矩阵。k 为零或 alpha 为零时不读取 A/B，选择 C 的缩放或置零路径；根据实际访问需求检查矩阵指针。beta 为零时不读取旧 C，避免旧 C 中 NaN 影响结果。任务书对 `k=0,beta=0,C=null` 的表述存在冲突，具体返回语义待社区确认。
3. 读取 Host 的 FP16 标量并转换为计算所需类型；根据 m/n/k、转置、前导维和设备资源生成 tiling，选取计算路径和核数。索引及字节偏移使用足够宽的整数，并检查溢出。
4. 常规路径复用或扩展 `blas/gemm/arch35/` 的 GEMM 调度和直调机制，避免改变已有接口的行为。具体接口和缓冲布局以目标版本编译验证为准。

### Kernel 侧

1. 常规路径将输出矩阵按 M、N 切块分配到可用计算核；各核迭代 K 分块，按列主序及转置映射搬入 A/B。边界 tile 按有效长度处理，禁止越界访问或覆盖 padding。
2. 优先采用 950 Cube 的 FP16 乘法和 FP32 累加，在累加结束后以 FP32 处理 alpha 与 beta，再按 IEEE 754 就近舍入写回 FP16。需要验证目标 API、数据搬运和输出转换是否满足该精度语义，不能预先视为达标。
3. beta=0 时跳过旧 C 读取；其他情况读取并转换 C。alpha=0 或 k=0 使用轻量 C 缩放/置零 kernel；零维时不启动计算。按数据实际依赖设置同步。
4. 大矩阵优先提高 Cube 利用率和数据复用，结合资源预算尝试双缓冲；小矩阵减少核启动、同步和搬运开销。分块大小、核数及是否采用轻量路径由抽样性能决定，避免未经测量固定最优配置。

## 算子约束限制

仅支持 FP16 实数、列主序及前导维语义；不支持广播或额外 stride。C 为原地输出；运行时 shape 不要求编译期固定。alpha/beta 为 Host 标量指针，矩阵位于 Device 内存。

# 可维可测分析

## 精度标准和性能标准

| 项目 | 标准及方法 |
| --- | --- |
| 精度 | 以 Netlib `cblas_sgemm` FP32 结果舍入 FP16 为 golden，逐元素全矩阵比较。有限值 rtol=atol=2^-10，匹配比例至少 0.99，并满足任务书最大误差限制；非有限值按任务书单独判定。 |
| 功能 | 覆盖 N/T/C 全组合、非对齐和 padding、零维、标量、空指针、非法枚举和维度、Inf/NaN；同时检查输出 padding 和只读输入。 |
| 性能 | 按任务书 §3.3，msprof op 预热 5 次，采集 10 次有效样本；全部 case 分别达到 GPU 的 0.4 倍，倍率算术平均至少 0.5。任务书末尾另写“≥ GPU”和“>10 次”，存在口径冲突，须向任务方确认并记录。 |

测试包包含 1000 条精度和 200 条性能用例。按原参数、seed、分布及阈值执行；先抽样精度和性能，通过后再做全量。补充测试包目前只生成均匀分布，与任务书要求的均匀/正态各 50% 有差异，应补齐并核实输入生成；现有性能脚本执行 GTest 并解析耗时，不能直接视为 msprof kernel 耗时。完整记录原始结果、软件/源码版本和参考基线，未测或缺参考如实标注。

## 兼容性分析

接口进入公共头文件，950 实现由架构分发限定，不定义私有平行 API；现有 GEMM 接口和其他产品线应通过回归验证兼容。当前为设计方案，尚未完成编译、上板及性能验收。
