# Ascend 950PR 分组测量差值与统计设计

## 1. 需求背景

### 1.1 需求来源

本设计面向单卡 Ascend 950PR 与 24 核 Host，以合成仪器读数和标称值定义一条 CPU/NPU 数值处理流水线。输入是连续张量、有效位和分组边界，输出是各组测量偏差的样本数、均值和样本标准差。章节组织参考 [CANN 社区设计模板](https://gitcode.com/cann/cann-ops-competitions/blob/master/04_tasks/01_community-task-2026/resources/design_template.md)。

### 1.2 现状与热点假设

CPU 参考路径顺序读取输入、计算差值并累计各组统计量。每条记录的减法只需一次 FP32 运算，内存扫描、Host 与设备间搬运以及调度开销可能主导总耗时。对于长数组，连续批处理可以摊薄启动开销。对于短数组，CPU 路径预期更省时。设计以端到端计时决定设备路径的启用范围。

## 2. 需求分析

| 需求 | 设计约定 |
| --- | --- |
| 输入 | `measured` 和 `nominal` 是长度相等、连续的 FP32 一维数组。`valid` 是同长度的 U8 数组，`0` 表示忽略，`1` 表示统计。`group_offsets` 是从 `0` 开始、以元素总数结束的单调非减 U64 偏移数组，相邻等值偏移表示空组。 |
| 输出 | 按 `group_offsets` 的顺序输出每组的 `count`、`mean` 和 `sample_stddev`。空组的两项统计值为 `null`。有效数为 1 时仅标准差为 `null`。 |
| 异常 | 长度不一致、掩码越界、偏移非法、有效值非有限、有效差值溢出或设备故障均终止运行，报告失败批次及可用的元素下标。 |
| 资源 | 单卡 950PR。Host 及其子进程受同一 24 核 CPU 亲和性或 cpuset 约束。批次数量和缓冲区容量由 Host 控制。 |

## 3. 详细设计

### 3.1 算子分析

对有效记录 $i$，先以 FP32 最近偶数舍入计算 $d_i = \mathrm{round}_{32}(\mathrm{measured}_i-\mathrm{nominal}_i)$，再以 FP64 累计。记组 $g$ 的有效下标集合为 $I_g$，有效样本数为 $n_g$。均值为 $\mu_g = \sum_{i\in I_g} d_i / n_g$，样本标准差为 $s_g = \sqrt{\sum_{i\in I_g}(d_i-\mu_g)^2/(n_g-1)}$。标准差要求 $n_g\ge 2$。

设备算子是同形状的逐元素运算。Host 依照组边界对差值执行流式统计，同一组始终按原始下标顺序更新。设备侧的批尺寸和返回次序可以变化，统计输入顺序固定。

### 3.2 接口和算子原型

```cpp
// Host 包装层，设备指针与 stream 属于同一上下文。
int LaunchMaskedDifference(
    const float* measured_dev,
    const float* nominal_dev,
    const std::uint8_t* valid_dev,
    float* difference_dev,
    std::uint8_t* status_dev,
    std::uint64_t logical_count,
    aclrtStream stream);

struct GroupMoments {
    std::uint64_t count;
    double mean;
    double m2;
};

// 每次处理同一组内的一段连续下标，按输入顺序更新累加器。
void UpdateGroupMoments(
    std::span<const float> difference,
    std::span<const std::uint8_t> status,
    GroupMoments& moments);
```

| 参数 | 类型与逻辑形状 | 约定 |
| --- | --- | --- |
| `measured_dev`、`nominal_dev` | 输入 `FP32[N]` | 连续读数和标称值。仅对有效位置检查有限性。 |
| `valid_dev` | 输入 `U8[N]` | Host 打包时校验每个值属于 `{0, 1}`。 |
| `difference_dev` | 输出 `FP32[N]` | 仅成功位置的差值有效。其他位置写 `+0`。成功的零值统一写为 `+0`。 |
| `status_dev` | 输出 `U8[N]` | `0` 忽略，`1` 成功，`2` 有效输入非有限，`3` 需要 Host 复核。 |
| `logical_count` | 属性 `U64` | 该批逻辑长度 `N`。长度为零时 Host 跳过提交。 |
| `stream` | 属性 | `LaunchMaskedDifference` 返回 `0` 表示入队成功。同步点负责检查执行结果，输入和输出在同步完成前保持有效。 |

五块设备缓冲区互不重叠，首地址按 64 字节对齐，物理长度为 `P = round_up(N, 64)` 个元素。Host 将填充区的读数、标称值和有效位都置零。Host 在分配及提交前检查长度对齐、字节数乘法和指针偏移是否溢出。`UpdateGroupMoments` 接收等长的差值和状态切片，状态仅含已确认的 `0` 或 `1`。每组累加器以 `{0, 0.0, 0.0}` 开始，`m2` 保存离均差平方和。

### 3.3 Host 与设备流水线

```text
读取张量与分组边界
          |
校验形状和偏移，填充批缓冲区
          |
Host 到设备异步复制 --> Ascend C 逐元素差值 --> 设备到 Host 异步复制
                                                        |
                                         检查批次状态并复核异常差值
                                              |                    |
                                            成功                  失败
                                              |                    |
                                      按输入顺序累计统计        终止并报告
                                              |
                                       全部批次完成后写出
```

Host 使用两个批缓冲槽。每个槽持有一组页锁定 Host 缓冲区和一组设备缓冲区。上传流记录事件供计算流等待，计算流记录事件供下载流等待。Host 确认下载完成后才能读结果。槽位直到状态检查和统计消费结束才归还，确保复核仍可访问原始读数，事件也随槽位一同复用。两个槽都在使用时暂停预读，缓冲区占用随批大小增长。跨流重叠程度取决于设备和传输资源。 [异步复制](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/runtimeapi/aclcppdevg_03_0106.html) · [跨流事件](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/runtimeapi/aclcppdevg_03_0083.html)

Host 以批序号和全局起始下标定位数据。允许批次跨组，Host 在消费时用分组边界拆成连续区间。同一组的累计状态只有一个写入者，独立组可以分派给不同 CPU 工作线程。校验与累计使用固定预算的工作线程，避免同时为输入、计算和落盘各开一个满核线程池。任一阶段失败时停止接收新批次，等待已入队操作结束或销毁故障上下文，再释放关联资源。全量结果通过同目录临时文件写出，成功关闭后原子替换正式文件。

### 3.4 Tiling 与 Kernel

**分核。** 将 `P` 分成连续的 64 元素对齐块。设块数为 `J = P / 64`、可用向量核数为 `V`，实际使用 `K = min(V, max(1, floor(J / q)))` 个核，其中 `q` 是用于控制核间粒度的目标块数，初始取 8。每核取得 `floor(J / K)` 个完整块，前 `J % K` 个核各多一块。块区间互不重叠，逻辑尾部计算受有效位控制。Host 从平台获取向量核数和可用 UB 容量。

**UB 预算。** 设 `T` 为单个 tile 的物理元素数，取 64 的倍数。令 `A(x)` 将字节数向上对齐到 256 字节。输入队列的每个槽含两个 `A(4T)` 的数据区和一个 `A(T)` 的掩码区，输出队列的每个槽含一个 `A(4T)` 的差值区和一个 `A(T)` 的状态区。按队列槽数 `D`、向量谓词及临时存储 `S(T)` 和框架预留 `H`，选择预算 `D × (3A(4T) + 2A(T)) + S(T) + H` 不超过可用 UB 容量的最大 `T`，并约束 DMA 长度和向量单次处理上限。`S(T)` 取实际向量实现同时活跃的临时区峰值，输入分类结束后复用已释放的谓词空间。单缓冲可容纳任一核的整个区间时取 `D=1`。其余批次比较 `D=1` 和 `D=2`，双缓冲无可用 tile 时使用单缓冲。UB 利用率按上述预算除以可用 UB 容量记录。 [CANNBot Tiling 指南](https://gitcode.com/cann/cannbot-skills/tree/master/ops/ascendc-tiling-design) · [CANNBot Ascend C API 指南](https://gitcode.com/cann/cannbot-skills/tree/master/ops/ascendc-api-best-practices)

```text
领取本核连续块区间
          |
CopyIn  批量搬入读数、标称值、有效位
          |
Compute  按掩码分类输入，执行 FP32 减法，分类输出
          |
CopyOut  写回差值和逐元素状态
          |
本核还有块？ -- 是 --> 处理下一 tile
          |
          否
          |
        结束
```

对未启用及有效输入非有限的位置，使用零作为减法操作数，状态仍分别记录为 `0` 和 `2`。输入次正规数、差值为次正规数或非有限值、以及结果为零但两输入数值不同的位置标为 `3`。次正规数和非有限值基于 FP32 位模式分类，判断输入数值相同的时候将两个符号零视为相等。Host 对状态 `3` 使用保留次正规数的 FP32 最近偶数舍入重新计算，有限结果写回并改为状态 `1`，溢出时返回错误。

GM 搬运按本 tile 的物理长度进行。最后一个 tile 使用实际分配的完整对齐块，仅在 UB 内将向量内部的多余位置掩掉。对齐位置由单一布局计算给出，确保相邻核的回写范围无重叠。队列的入队和出队负责协调搬运、向量计算及回写。 [Ascend C 对齐与数据搬运](https://www.hiascend.com/developer/techArticles/20250627-1?envFlag=1)

### 3.5 数值一致性与性能决策

CPU 参考和 Host 复核使用相同的 FP32 舍入语义。设备的正常差值路径按同一语义验收，并在迁移芯片或编译配置时重新确认舍入、溢出和次正规数行为。Host 用 Welford 递推更新 `count`、`mean` 和 `m2`，长组跨批延续同一个累加器，最终以 `sqrt(m2 / (count - 1))` 计算样本标准差。独立参考用 FP64 两遍法计算统计量，便于定位设备差值与 Host 累加各自的误差。

对物理长度 `P` 的一批，设备读写搬运 `14P` 字节输入输出，两次方向相反的 Host 与设备间复制合计 `14P` 字节。设每槽最大物理长度为 `P_max`，两个槽的页锁定内存和设备数据区各占 `28P_max` 字节，另计 Host 的组累加器和运行时开销。设备侧向量算量较轻，优先检查传输带宽、核启动耗时、缓冲槽空转和状态 `3` 的比例。比较 CPU 直算、同步 NPU 和双缓冲异步 NPU 三条路径，计时覆盖输入读取、设备初始化、布局准备、搬运、计算、统计和结果落盘。只有端到端结果支持时，才按数据规模启用设备路径并确定批大小。

### 3.6 支持硬件及约束

目标设备为单卡 Ascend 950PR，Host 使用 24 核配额。算子接收连续、等长的一维 FP32 数据和 U8 有效位，布局转换由调用方完成。分组只在 Host 侧解释。设备调用出错时保留失败状态，CPU 直算由调用方在启动时选择，数值复核是正常设备流程的一部分。

## 4. 可维可测分析

| 验证项 | 计划采用的检查 |
| --- | --- |
| 正确性 | 构造整数差值、正负抵消和已知方差的合成读数。复核后的 FP32 差值和最终状态必须与 CPU 参考一致。样本数和空值约定严格匹配。对各组合成用例，以独立 FP64 两遍法为参考，均值和标准差的绝对误差上限取 `1e-12 × max(1, 组内最大绝对差值)`。 |
| 数值边界 | 覆盖正负零、次正规数、近抵消、有效输入的 NaN 和 Inf、减法溢出，以及掩码忽略非有限值的情形。 |
| 布局与分核 | 覆盖逻辑长度 `0`、`1`、`63`、`64`、`65`，以及跨 tile、跨核、跨批、空组和单样本组。改变批大小后检查组顺序和统计结果。 |
| 错误处理 | 覆盖掩码越界、偏移回退、尾偏移不匹配、分配与设备执行失败。检查错误退出及结果文件的发布行为。 |
| 性能 | 分别记录整段墙钟、各阶段耗时、每秒记录数、槽位等待时间和批峰值内存。在固定单卡、24 核约束下评估设备路径的收益区间。 |

示例中 `measured = [4, 6, 10, 13]`，`nominal = [3, 3, 10, 10]`，`valid = [1, 1, 0, 1]`，`group_offsets = [0, 2, 4, 4]`。第一组计数为 2、均值为 2、样本标准差为 $\sqrt{2}$。第二组计数为 1、均值为 3、标准差为 `null`。第三组计数为 0，两项统计量均为 `null`。
