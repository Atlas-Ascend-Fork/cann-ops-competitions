# aclblasScasum A2/A3 算子设计

## 需求背景

### 需求来源

[11 月 CANN 社区任务](https://www.hiascend.com/activities/task-center/details/a698b640487f434ca332f08fb23eb899)要求在 Atlas A2/A3 上提供复数向量绝对值分量之和。ops-blas 已声明公共 `aclblasScasum` 接口，本任务补充 arch22 实现。Ascend 950 对应的 arch35 实现继续使用公共接口。

### 背景介绍

复向量绝对值分量和用于 BLAS 一级操作。算子将向量归约为一个实数，跨步输入以复数元素为单位。

## 需求分析

### 需求描述

| 参数 | 约定 |
| --- | --- |
| handle | 有效 ops-blas 句柄，提供执行流与工作区 |
| n | 逻辑复数元素个数 |
| x | Device 侧交错存储的 `aclblasComplex` 向量 |
| incx | 两个相邻逻辑元素的复数元素步长 |
| result | Device 侧 FP32 标量 |

### 需求拆解

1. 使用现有 ABI，处理空句柄、空输出、有效计算时的空输入和越界跨度。
2. 实现连续与跨步搬运、分块归约和流内结果写回。
3. 为 A2/A3 的 arch22 GTest 加载官方 CSV，保留逐条精度、性能及运行时库身份。

## 详细设计

### 算子分析

对 `n > 0` 且 `incx > 0`，以零为起点，第 `i` 个逻辑元素位于 `x[i × incx]`。结果为这 `n` 个复数的实部绝对值与虚部绝对值之和。输入包含 `1 + (n - 1) × incx` 个复数，输出为一个 FP32 标量。

例如 `n=3, incx=2` 时访问 `x[0]`、`x[2]`、`x[4]`。输入物理长度为 5，向量归约只读取这三个元素。

### Host 设计

- 先检查句柄和输出。有效计算时校验输入地址，并以 int64 计算正跨度，拒绝超出 int32 范围的跨度。
- `n <= 0` 或 `incx <= 0` 时，在句柄绑定的流上使用运行时内存初始化写入正零，返回初始化状态。
- 小规模使用一个向量核。其余规模按输入长度、可用 AIV 核数和 workspace 大小决定核数。每核负责一段连续逻辑索引。大向量的前几段较短，降低初始累加值跨越指数边界时的开销。
- 多核每核预留两个 32 字节的 workspace 槽位，分别保存部分和与该段的最终贡献。64 核上限对应 4096 字节。工作区不足时走单核路径。各阶段在同一流按序提交，读取结果前由调用方同步。

### Kernel 设计

1. 连续输入按交错 float32 载入。跨步输入按复数对进行 DMA 搬运，32 字节槽位中未使用的 float 写零。字节步长超出 DMA 描述符范围时逐元素搬运。
2. 单核和多核分别使用最多 8192 和 16128 个 float 的 UB 数据块。搬运队列采用双缓冲，非整块尾部按实际长度搬运并填零。单核从零开始累加，对可能改变 FP32 指数或遇到中点的分块逐级细分，必要时按分量累加。
3. 多核先并行求各段部分和，再用前面各段的部分和估计当前段起点。落在同一 FP32 指数区间的分量按该区间的 ULP 并行舍入。跨越指数边界时，先累计仍在该区间的连续分组，再逐组定位边界并处理边界附近的分量。
4. 输出地址按 32 字节对齐时，第一阶段清零结果，第二阶段以原子加累积各段贡献。非对齐输出使用工作区保存各段贡献，由独立 kernel 归约后写回一个 float。偏移用例同时检查输出前后的哨兵。
5. 多核分段的起点和中点舍入会产生近似误差，按任务书的 Netlib 标杆和标量容差在真机逐条核验。

### 支持硬件和约束

arch22 目标为 Atlas A2/A3。正式性能按任务书在 Atlas 800T A2（910B3）与 CANN 9.1.0 上采集。本文当前对应 Git 树 `243b4e668d0f5c9c6c6a97891b450ac769965939`。

## 可维可测分析

### 精度

使用 Netlib BLAS 3.10.0 的 `cblas_scasum` 生成 FP32 标量参考，按任务书的混合容差及最大绝对误差上限判定。日志记录实际值、参考值、误差、状态码和判定。官方 1000 条精度用例原样保留，补充 763 条正态分布、4 条 CSV 边界以及空句柄和偏移的 2 条独立 GTest。

CPU 诊断和 910B3 实测表明，普通并行归约在部分大向量中会超出绝对误差上限。当前版本已通过 1769 条精度及边界用例、10 条冒烟，并通过全部 200 个性能输入的补充数值比对。

### 性能

使用官方 200 条性能用例及对应 GPU 基线。每个用例用 `msprof op` 预热 5 次，记录至少 10 个有效调用。多阶段实现按每次调用合计所有 kernel 的 Task Duration，报表列出 GPU 微秒、NPU 微秒和 GPU/NPU，门槛为 0.8。开发阶段的应用级 Profiler 数据用于定位各阶段耗时。

当前版本的 200 条应用级诊断均达到 0.8，最低 GPU/NPU 为 0.866。现有 A2 实例的 `msprof op` 报采集通道启动失败，正式性能仍待采集。

### 内存和兼容性

任务书没有内存性能门槛。交付模板中的内存报告及日志说明适用性并记录实现使用的 workspace。公共头文件的签名保持一致，测试用例和源码均按 arch22 放置。
