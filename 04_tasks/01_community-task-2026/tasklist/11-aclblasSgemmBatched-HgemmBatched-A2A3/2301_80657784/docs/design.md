# 需求背景

## 需求来源

昇腾社区 11 月社区任务要求在 Atlas A2/A3 上补齐 `aclblasSgemmBatched` 与 `aclblasHgemmBatched` 的 Ascend C 实现。任务书随社区任务发布，包含接口约束、测试用例和 cuBLAS GPU 基线。[任务详情](https://www.hiascend.com/activities/task-center/details/55123ab3caa64d089f525f646155094c) · [任务书](https://www.hiascend.com/p/resource/202611/50d7f6f055c948219f697c99ae5b0367.zip)

## 背景介绍

批量 GEMM 用同一组形状、转置、前导维和缩放参数执行多个相互独立的矩阵乘。各批矩阵的设备地址通过指针数组传入。ops-blas 中已有两个公共接口及 arch35 实现，同时已有 arch22 的批量复数 GEMM 工程。本任务在 `blas/gemm_batched/arch22/` 补充两个实数接口，并在 `test/gemm_batched/sgemm_batched/arch22/` 建立对应验证入口。[ops-blas](https://gitcode.com/cann/ops-blas)

# 需求分析

## 需求描述

每个批次 `i` 按列主序完成以下计算，结果原地写回 `Carray[i]`。

```text
C[i] = alpha × op(A[i]) × op(B[i]) + beta × C[i]
i = 0, …, batchCount − 1
```

| 接口 | A、B、C、alpha、beta | 累加与输出 |
| --- | --- | --- |
| `aclblasSgemmBatched` | FLOAT32 | 常规路径用 FP32 累加，输出 FLOAT32 |
| `aclblasHgemmBatched` | FLOAT16（`aclblasHalf`） | FP32 累加和缩放，输出按就近偶数舍入到 FP16 |

## 需求拆解

1. 复用 `include/cann_ops_blas.h` 的公共签名。接口参数按 `handle, transa, transb, m, n, k, alpha, Aarray, lda, Barray, ldb, beta, Carray, ldc, batchCount` 顺序传入。实数输入支持 `N`、`T`、`C`，其中 `C` 等价于 `T`。
2. 支持任意合法前导维、设备指针数组和不连续的批次地址。三组数组及其指向矩阵位于设备侧，`alpha`、`beta` 位于主机侧。每批 `C` 的有效写入区域相互独立，且与任一批输入矩阵隔离。
3. 保持异步语义，所有设备任务依次下发到句柄绑定的 stream。输出只更新逻辑 `m×n` 元素，保留列尾填充。
4. 达到任务书的精度及性能验收线。正式自验覆盖两接口各 500 条精度和接口用例、100 条性能用例。

# 详细设计

## 算子分析

正算调用可用行主序视图计算 `Cᵀ = op(B)ᵀ × op(A)ᵀ`。交换传给 Cube 的两个操作数以及逻辑 M/N，对应偏移仍由原始列主序前导维计算。批次基地址由设备侧读取，所有偏移及总 tile 数使用宽整数计算，防止大尺寸和高批数溢出。

| 参数 | 逻辑维度或取值 | 约束 |
| --- | --- | --- |
| `m,n,k,batchCount` | 非负整数 | `m=0`、`n=0` 或 `batchCount=0` 时合法调用空返回 |
| `Aarray,lda` | `op(A)` 为 `m×k` | `lda ≥ max(1,m)`（N）或 `max(1,k)`（T/C） |
| `Barray,ldb` | `op(B)` 为 `k×n` | `ldb ≥ max(1,k)`（N）或 `max(1,n)`（T/C） |
| `Carray,ldc` | `C` 为 `m×n` | `ldc ≥ max(1,m)`，每列只更新前 `m` 个元素 |
| `alpha,beta` | 主机标量，与接口数据类型一致 | `k=0` 或 `alpha=0` 时只计算 `beta × C`，`beta=0` 时跳过旧 C 读取 |

## 算子实现

### Host 侧设计

入口校验顺序为句柄、转置枚举、尺寸及前导维、主机标量、空输出判定、必要设备指针。空句柄返回 `ACLBLAS_STATUS_HANDLE_IS_NULLPTR`，非法转置返回 `ACLBLAS_STATUS_INVALID_ENUM`，其他非法参数返回 `ACLBLAS_STATUS_INVALID_VALUE`。主机校验设备指针数组本身，数组元素的有效性由调用方保证。无乘积且 `beta=1` 时，在必要指针校验后直接返回，对 C 保持逐字节原样。

按实际形状、标量、地址步幅与硬件能力选择路径：

| 路径 | 触发条件 | 执行方式 |
| --- | --- | --- |
| 缩放 | `k=0` 或 `alpha=0` | AIV 对 C 置零或缩放，跳过 A/B |
| 小点积 | `m=n=1` 且 K 很小 | AIV 执行单结果点积和缩放，降低 Cube 下发开销 |
| Cube 直接写回 | `alpha=1`、`beta=0` 且输出及路径约束满足对齐 | S 直接写 FP32，H 对满足已验证条件的分块直接从 Cube 收窄写 FP16 |
| 通用 | 存在缩放、非对齐输出或其他形状 | Cube 生成 FP32 临时 tile，AIV 执行缩放、累加旧 C、类型转换与精确长度写回 |

Host 以 `(batch, tileN, tileM)` 划分任务。首版输出 tile 为 `128×128`，各物理核以总核数为步长领取独立 tile，按实际剩余 M/N 处理尾块。H 对齐直出路径交错批次和空间 tile，K 微块采用已上板比较的配置。通用路径每个临时 tile 最多占 `128×128×4 B = 64 KiB`，按句柄可用空间划分窗口。默认窗口上限为 128 MiB，每个窗口内 Cube 生产完成后由 AIV 消费，依赖同 stream 顺序保证暂存区复用安全。工作区分配失败或下发失败沿用 ops-blas 的错误回传机制。

### Kernel 侧设计

1. **Cube** 从设备指针数组取本批 A/B/C 基址，按转置、前导维、tile 编号和 K 分块确定访问范围。保持 FP32 累加。直接路径仅在满足目标类型和写回约束时向 C 输出，通用路径写入当前工作区窗口的独立 FP32 tile。H 直出在 Cube 写回阶段完成最终 FP16 舍入。
2. **AIV** 从工作区读取一个多列面板，根据 `alpha`、`beta` 执行缩放和累加。批量使用二维 `DataCopyPad`，统一片上行距并以真实逻辑长度写 GM。FP16 面板按 16 个元素对齐，FP32 暂存读按 8 个元素对齐，需要的跨块填充在片上初始化。设备回归覆盖尾块、非对齐布局及 C 的填充哨兵。
3. **同步** 通过核内 pipeline 依赖保护搬入、向量计算、转换与搬出。Cube 和 AIV 在同一绑定 stream 按窗口顺序下发。每个 tile 对应独占的逻辑输出，批次间无归约或共享写入。

### 性能优化方案

| 优先级 | 目标 | 验证方式 |
| --- | --- | --- |
| 1 | H 大矩阵的 GM→L1 搬运和 Cube 执行。核对大尺寸的实际 dispatch、tile 分布及 MTE2 占比，比较 tile/K 配置和输入复用策略 | 对照 2048 方阵 batch 2、4096 方阵 batch 1，同时复测 512 方阵控制组 |
| 2 | 小 K 与非对齐形状的输出开销。保留多列搬运，测量 Cube、AIV 和 launch 间隔，针对尾块比例调整面板和写回路径 | 对照不规则尾块与带填充的转置用例，验算写入哨兵 |
| 3 | 高批数的小矩阵和 S 极值语义。降低指针读取及下发开销，单列复现 FP32 有限参考值对应设备溢出的用例，评估数值稳定性处理 | 对照 `1×1×1` 高批数、S 极值和常规 FP32 用例，检查精度和性能回归 |

每一项使用同设备、同输入、同测量口径进行前后对照。对于多 kernel 路径，额外记录完整序列与内核间隔，辅助判断耗时来源。开发阶段以目标用例和已达线控制组定位，候选稳定后执行全量回归。

# 可维可测分析

## 精度标准与性能标准

| 项目 | 判据与方法 |
| --- | --- |
| 精度 | CPU 参照 Netlib SGEMM 语义。FP64 累加后按任务书规定收窄，H 先收窄到 FP32，再按就近偶数舍入到 FP16。S 的 atol/rtol 为 `2^-13`，H 为 `2^-10`，匹配率至少 99%。每元素误差硬上限取固定绝对阈值（S 为 0.01，H 为 0.1）与该参考值 32 ULP 的较大值 |
| 接口 | 覆盖 N/T/C、合法及非法前导维、空矩阵、空指针、零 K、零标量、非默认标量、batch 边界和填充哨兵 |
| 性能 | 910B3 预热 5 次，随后采集 10 次有效调用。用 `msprof op` 的 Task Duration 得到设备 kernel 均值，与任务包同配置 GPU kernel-only 基线比较，上限为 GPU 耗时的 1.25 倍。ACL event 端到端耗时作为辅助数据独立归档 |
| 复现 | 保存运行环境、选定代码版本、逐条用例参数、原始样本、精度断言、性能结果和复现命令 |

## 当前验证状态

910B4 的开发阶段全量精度与接口试跑结果为 S `498/500`、H `500/500`。S 的 `TC_FL_013` 和 `TC_FL_014` 出现部分设备结果为无穷而 CPU 参考值有限，需继续定位。使用 `msprof application` 采集的设备 kernel 耗时合计与任务书数值线对比，S `41/100`、H `35/100`，用于确定优化优先级。910B3 正式性能数据待采集，最终验收以任务书口径及全量回归结果为准。

## 兼容性分析

复用现有公共接口、类型和状态码，新增实现通过架构目录接入。保持既有 arch35 实现和调用方式。参数校验、异步成功及设备执行错误仍按 ops-blas 约定处理。
